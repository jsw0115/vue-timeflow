# Example Workflow

## Goal

Define the outcome this skill must achieve.

## Required Inputs

Identify:
- User requirements
- Existing files and project context
- Technical constraints
- Expected deliverable

If some details are missing, inspect the available
context first. Ask only when an essential requirement
cannot be determined.

## Workflow

### Step 1: Analyze
1. Understand the user's request.
2. Inspect relevant existing files.
3. Identify dependencies and constraints.
4. Determine the scope of work.

### Step 2: Plan
1. Select an implementation strategy.
2. Identify the files or outputs to create.
3. Identify potential risks.
4. Preserve existing conventions.

### Step 3: Execute
1. Perform the required changes.
2. Use reusable resources when appropriate.
3. Follow all rules and constraints.
4. Avoid unrelated modifications.

### Step 4: Validate
1. Check completeness.
2. Check correctness.
3. Run applicable tests or validations.
4. Resolve detected errors when possible.

### Step 5: Report
1. Summarize completed work.
2. List modified or created files.
3. Describe validation results.
4. Report unresolved problems.

## Rules

- Never fabricate test results or file contents.
- Preserve existing functionality unless
  modification is requested.
- Never expose secrets.
- Avoid unnecessary dependencies.
- Use available tools for verification.
- Explain any steps that could not be verified.

## Output Format

Provide:
1. Task summary
2. Implementation details
3. Changed files
4. Validation results
5. Remaining limitations

## References

Read supporting files only when relevant
to the current task.
