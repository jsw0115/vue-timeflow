# 화면 목록서 및 기능 목록서 보충

> 기준 문서: `timeflow 앱웹.xlsx` (문서 버전 2.1, 2026-02-16) 시트 `화면 목록서 및 기능 목록서` — 화면 목록서(81행 실측, 헤더상 89개) + 기능 목록서(약 300개).
> 이 문서의 역할: 기존 표를 다시 옮겨 적지 않고 **빠졌거나 더 상세화가 필요한 항목만** 추가한다. ID 표기 규칙(대문자 도메인-일련번호[-F일련번호])은 원본과 동일하게 맞춰서, 아래 행을 그대로 xlsx에 복사해 넣을 수 있게 했다.

---

## 0. 정합성 점검 결과

화면 목록서의 `관련기능ID` ↔ 기능 목록서의 `기능ID`, 그리고 기능 목록서의 `주요화면ID` ↔ 화면 목록서의 `화면ID`를 서로 대조했다.

1. **`SET-009` 화면 누락**: 기능 목록서에 `SET-009-F01`(위젯 설정, "홈 위젯 ON/OFF, 순서/크기 조정")이 존재하고 이 기능을 참조하는 화면ID도 `SET-009`로 적혀 있는데, 정작 화면 목록서 표에는 `SET-009` 행이 없다. 아래 1-1에서 행을 채워 넣었다.
2. **화면 수 불일치**: 문서 상단 코멘트는 "89개 화면"이라고 적혀 있지만 실제 표에는 81개 행만 있다. 이전 개정에서 화면 8개가 통합되거나 삭제되면서 요약 카운트가 갱신되지 않은 것으로 보인다 — 의도된 축소인지 확인 후 헤더 코멘트를 실제 개수로 정정하는 것을 권장한다.
3. 반대 방향(화면 → 기능 참조, 기능 → 화면 참조)의 다른 dangling 참조는 없었다 — 즉 문서 골격 자체의 정합성은 대체로 양호하다.

이 두 가지를 제외하면 표 내부의 ID 참조 관계 자체는 깨진 곳이 없다. 아래부터는 "빠진 참조"가 아니라 **제품 완성도 관점에서 실제로 필요한데 아직 정의되지 않은 화면/기능**이다.

## 3. 반영 순서 제안

1. **즉시 반영(문서 정합성)**: `SET-009` 화면 행 추가, 헤더의 "89개 화면" 코멘트 실측치로 정정.
2. **Phase 1~2 (MVP~PvsA 심화) 병행**: `SET-004-F03`(알림 세분화), `GLB-009`(오프라인 피드백), `TASK-002-F03`, `EVT-005-F02` — 기존 정의된 기능의 완성도를 높이는 항목이라 이미 진행 중인 범위와 같이 가져가는 것이 자연스럽다.
3. **Phase 3 진입 전 필수**: `AUTH-007`(권한 요청), `LEGAL-001`(약관/정책) — 실제 사용자에게 앱을 배포하기 전에 법적/UX 리스크가 있는 항목.
4. **Phase 4 진입 전 필수**: `WS-005`(알림 배치) — 커뮤니티/채팅이 열리는 순간부터 알림 폭주 위험이 시작되므로 그 전에 설계.
5. **수익화 착수 시점**: `BILL-001`(구독/멤버십) — 유료 요소를 실제로 넣기로 결정하는 시점에 맞춰 진행.
6. **네이티브 앱 스토어 배포 직전 필수**: `SYS-001`(점검/강제 업데이트) — R4의 Capacitor 배포 착수와 동시에 설계해야 한다.
7. `SHARE-005`(차단 목록)는 우선순위상 R3~R4(공유/커뮤니티) 어느 쪽에 붙여도 무방하며, 차단 기능이 여러 도메인에 흩어져 생기기 전에 공통 컴포넌트로 먼저 설계해두면 재작업이 적다.
