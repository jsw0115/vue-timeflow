# 메뉴 구조 및 정보구조(IA) 제안

- 문서 버전: v2.1
- 기준일: 2026-11-20
- 원칙: 기존 MN-01~MN-127과 경로를 보존하고, 신규 커리어 메뉴를 기존 메뉴에 연결한다.

## 1. 정보구조 설계 원칙

1. 기존 기능 경로와 북마크를 갑자기 제거하지 않는다.
2. 신규 메뉴는 기존 `MN-51 경력·포트폴리오`, `MN-49 WBS`, `MN-68 커뮤니티`를 대체하지 않고 허브에서 연결한다.
3. 취업준비생과 이직 준비 직장인이 첫 화면에서 본인에게 필요한 정보부터 볼 수 있도록 대시보드 위젯을 개인화한다.
4. 사용자 메뉴와 관리자 메뉴를 분리한다.
5. 작은 화면에서는 넓은 사이드바를 하단 탭/드로어/컨텍스트 메뉴로 전환하되 기능 권한은 동일하게 유지한다.

## 3. 신규 메뉴 ID 후보

|---|---|---|---|---|
| MN-130 | 커리어 대시보드 | `/career` | 경력 요약, 최근 활동, 지원 현황, 목표, 미완료 문서 | career, application, activity |
| MN-131 | 활동 타임라인 | `/career/activities` | 업무·학습·프로젝트·커뮤니티 활동 통합 | 기존 actual/record + career activity |
| MN-132 | 경력·경험 | `/career/experiences` | 회사·인턴·알바·프리랜서·교육 경험 | 기존 `/work/career` 기능을 점진 확장 |
| MN-133 | 취업·이직 지원 | `/career/applications` | 공고·기업·지원 문서·면접·결과 | application / document version |
| MN-134 | 문서 센터 | `/career/documents` | 이력서·자기소개서·경력기술서·보고서 템플릿 | document/version/source link |
| MN-135 | 포트폴리오 편집 | `/career/portfolio` | 프로젝트와 결과물 구성, 공개 범위 | 기존 portfolio 기능 확장 |
| MN-136 | 프로젝트 허브 | `/projects` | 개인·팀 프로젝트, 진행 상태, 최근 산출물 | project / WBS |

## 4. 기존 메뉴의 배치·보존 정책

| 기존 메뉴 | 제안 | 보존 정책 |
|---|---|---|
| MN-01 홈 | 커리어 위젯 추가 | 오늘의 일정·할 일·루틴 요약 유지 |
| MN-10 플래너 | 일/주/월/연을 한곳에서 전환 | Plan/Actual와 하루 경계 규칙 유지. 미연결 보기 상태를 시연과 구분 |
| MN-49 WBS | 업무·프로젝트 메뉴 아래 | 현재 서버 연결과 100단계 제한 등 서버 규칙 유지 |
| MN-50 업무 위키 | 업무·프로젝트 메뉴 아래 | 버전 이력·하위 문서 규칙 유지 |
| MN-51 경력·포트폴리오 | 커리어 허브로 연결 | 기존 `/work/career` 경로를 alias/redirect로 장기간 보존 검토 |
| MN-60~MN-71 소셜 | 소셜 영역 유지 | 친구·공유·채팅·커뮤니티·챌린지 그대로 유지 |
| MN-72 동기화 | 연동 설정으로 통합 노출 가능 | 기존 경로와 provider 상태 표시는 유지 |
| MN-108 자동화·AI | AI 및 자동화 설정 허브 | 현재 미연결 상태를 실제 연결로 표시하지 않음 |
| MN-110 연동 설정 | GitHub·클라우드·캘린더 탭 구성 | 기존 외부 캘린더 상태와 새 connector 구분 |
| MN-111 데이터 관리 | 경력·문서 export 포함 | 기존 JSON 백업·병합 복원 범위 영향 분석 |
| MN-80~MN-90 관리자 | 관리자 콘솔 유지 | 신규 allowlist·AI 정책·자동화 감사 메뉴 추가 |

## 5. 사용자별 대시보드 기본 구성

| 사용자 모드 | 첫 화면 우선 위젯 | 후순위 위젯 |
|---|---|---|
| 취업준비생 | 지원 마감, 지원 진행 단계, 오늘 학습 루틴, 프로젝트 진행, 문서 미완성 | 머니로그, 일반 업무 일정 |
| 이직 준비 직장인 | 최근 업무 기록, 경력 타임라인, 프로젝트/WBS, 지원 현황, 문서 버전 | 커뮤니티 챌린지, 개인 소비 |
| 일반 재직자 | 오늘 업무·일정, 루틴, WBS, 업무 위키, 성과 기록 | 취업 지원 현황 |
| 프로젝트 참여자 | 담당 작업, 마감, 팀 메시지, 기여 기록, 결과물 | 일반 커리어 문서 |

사용자 유형은 온보딩에서 선택하는 초기 설정이며, 이후 환경설정에서 변경 가능해야 한다. 유형 선택이 권한이나 데이터 공개 범위를 자동 변경해서는 안 된다.

## 6. 공통 화면 기능 확장

- 통합 검색: 경력·활동·프로젝트·문서·지원 내역을 추가하되 검색 결과마다 공개 범위와 소유권을 적용한다.
- 새 기록 작성: 기존 10종 작성 흐름을 유지하고 `업무/경력 활동`, `프로젝트 회고`, `지원 기록`을 추가 후보로 둔다.
- 알림: 지원 마감·면접·프로젝트 마감·WBS 지연·외부 연결 만료를 추가한다.
- 빠른 기록: 사용자가 한두 문장으로 남긴 활동을 저장하고, AI 분석 연결 전에는 규칙 기반 태그·유형 제안만 제공한다.
- 저장 상태: 서버·로컬·오프라인 대기·충돌·시연을 명확히 표시한다.

## 7. 모바일 메뉴 원칙

- 홈, 커리어, 기록/플래너, 프로젝트, 더보기의 4~5개 하단 목적지를 우선 검토한다.
- 긴 글·문서 편집·WBS 계층·간트 차트는 모바일에서 단계형 편집 또는 가로 스크롤을 제공한다.
- 빠른 기록, 파일 첨부, 알림 확인, 일정·지원 마감 확인은 모바일의 핵심 사용 시나리오로 둔다.
- 웹과 모바일은 별도 데이터 저장소가 아니라 동일한 API와 계정 데이터를 사용한다.

## 8. 메뉴 변경 시 필수 작업

1. `navGroups`/`settingsSections.js` 수정과 이 문서의 메뉴 행을 같은 PR에서 갱신한다.
2. 화면 경로 생성기를 실행해 `screen-catalog.md`를 재생성한다.
3. 기존 경로 redirect/alias와 접근 권한 테스트를 추가한다.
4. 메뉴 상태가 서버·로컬·일부·시연·상태 표시 중 무엇인지 실제 API 호출로 확인한다.
5. 관리자 메뉴는 클라이언트 역할값이 아니라 서버 권한 검사 결과로 노출한다.
