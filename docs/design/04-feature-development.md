# 기능 개발 분해 및 기존 FD 연결표

- 문서 버전: v2.1
- 기준일: 2026-11-20
- 목적: 기존 FD-01~FD-84를 보존하고 커리어 확장 기능을 개발 단위로 나눈다.

## 1. 기존 기능 기준

기존 기능개발 목록서 v1.21의 FD ID·API·상태·검증 테스트는 원본을 유지한다. 아래 표는 신규 확장 작업이 기존 기능을 어떻게 재사용하는지 보여주는 연결표이며, 기존 구현 상태를 새로 검증한 결과가 아니다.

| 기존 기능 | 재사용 방향 | 확장 시 주의 |
|---|---|---|
| FD-01~02 인증·토큰 | GitHub 로그인 계정 연결의 기반 | GitHub 로그인과 Repository 접근 권한은 별도 승인 |
| FD-10 홈 요약 | 커리어 대시보드 위젯 연결 | 기존 오늘 일정·할 일·루틴 요약 유지 |
| FD-11~16 플래너·집중 | 프로젝트 작업 계획과 실제 시간 근거 | 프로젝트 활동을 기존 time recording에 억지로 중복 생성하지 않음 |
| FD-20~32 일정·기록 | 업무·학습 활동 기록의 시간 원천 | source link와 기존 record_link 재사용 가능성 검토 |
| FD-40~44 통계·검색·백업 | 활동·경력 검색, 원본 통계, export | 민감 본문이 분석 로그·검색 인덱스에 노출되지 않도록 함 |
| FD-50~52 업무 기록·WBS·위키 | 프로젝트 관리·업무 증거·문서 지식 | 현재 WBS/위키 데이터 모델을 확인한 뒤 중복 테이블 방지 |
| FD-53~54 경력·문서·공개 링크 | 커리어 허브의 핵심 기반 | 공개 링크 목록·회수 화면·접근 로그 보완 필요 |
| FD-60~66 공유·채팅 | 팀 협업·프로젝트 대화 | 커뮤니티 회원 권한과 프로젝트 회원 권한을 동일시하지 않음 |
| FD-63 커뮤니티·챌린지 | 직무별 그룹·프로젝트 모집 | 챌린지 인증을 직무 역량 인증으로 오인하지 않도록 구분 |
| FD-70~76 설정·운영 | 언어·연동·관리자 allowlist | 시연 화면은 서버 연결 완료로 표현하지 않음 |
| FD-80~84 연동·AI·결제·음성 | 신규 connector 및 독립 AI 기능의 출발점 | 제공자 미연결과 설계 상태 유지, 무리한 일괄 연결 금지 |

## 3. 기능별 완료 조건 제안

### FD-85~87: 커리어 활동 원장

- 회사 업무, 인턴, 아르바이트, 프리랜서, 개인 프로젝트, 학습, 커뮤니티 활동을 구분할 수 있다.
- 각 활동은 기간, 담당 역할, 설명, 기술, 성과, 관련 경험/프로젝트, 근거 파일 또는 URL을 연결할 수 있다.
- 사용자는 기록 유형별 공개 범위를 지정한다. 기본값은 비공개다.
- 활동 수정은 version 충돌을 처리하며, 삭제된 항목과 연결된 문서는 깨진 출처로 표시한다.
- 기존 `feature_record`, `/api/work/career/projects`, `/api/work/portfolio`와 중복되는 필드·API를 조사한 후 저장 모델을 결정한다.

### FD-88: 취업·이직 지원

- 기업, 공고 URL, 직무, 고용 유형, 지원 마감, 근무 형태, 급여 범위(선택), 지원 상태를 저장한다.
- 상태 예시: 관심, 준비 중, 지원 완료, 서류 통과, 면접 예정, 최종 합격, 불합격, 보류, 철회.
- 지원 시점의 이력서·자기소개서 버전을 고정 참조한다.
- 면접 일정·질문·답변·회고를 연결한다.
- 브라우저 자동 수집 또는 자동 지원은 초기 범위가 아니다.

### FD-89~90: 문서 및 포트폴리오

- 문서 템플릿은 유형·직무·언어별로 구분한다.
- 버전마다 변경 요약과 원천 기록 참조를 보존한다.
- 포트폴리오 공개는 선택한 항목만 노출하며, 링크 폐기·만료·암호 보호·검색 색인 제어를 제공한다.
- 공개 URL과 내부 파일 URL을 구분하고 비공개 파일 storage key를 직접 노출하지 않는다.

### FD-91~92: 팀 프로젝트·기여도

- 프로젝트 소유자, 팀 멤버, 역할, 권한, 참여·탈퇴·초대 이력을 관리한다.
- WBS 항목을 프로젝트와 연결하고 참여자별 담당 작업을 관리한다.
- GitHub 데이터는 기여 근거 중 하나이며 Commit 수가 기여도 점수로 자동 환산되지 않는다.
- 기획·설계·코드리뷰·테스트·문서·운영 기여를 수동 또는 승인 기반으로 기록한다.
- 팀 전체 산출물과 개인 포트폴리오의 복사/공개 권한을 분리한다.

### FD-93~94: 외부 연동

- 로그인용 OAuth와 자료 접근용 OAuth를 분리한다.
- scope를 최소화하고 사용자가 선택한 repository/folder/file만 수집한다.
- 토큰 만료, 연결 끊김, provider rate limit, 삭제된 외부 자료를 상태로 표시한다.
- 파일 복사와 외부 링크 참조를 사용자에게 구분해 보여준다.

### FD-95~98: AI 및 업무 자동화

- AI 작업은 비동기 job으로 수행하며 요청·진행·성공·실패·취소 상태를 제공한다.
- AI 서버는 메인 API의 사용자 동의·권한 확인을 통과한 자료만 받는다.
- AI 생성 문장은 근거 activity/document/project를 연결한다.
- 외부 게시·전송은 미리보기와 사용자 승인 이후에만 수행한다.
- 관리자 승인되지 않은 host·connector는 실행하지 않는다.

## 4. 권장 API 도메인 초안

아래는 경로 후보이며 실제 API 계약이 아니다. 기존 `/api` 규칙을 확인하고 현재 API와 충돌하지 않게 설계한다. 기존 문서의 `/api/v1`은 목표 초안이며 현재 Controller 매핑으로 간주하지 않는다.

| 도메인 | 경로 후보 | 주요 리소스 |
|---|---|---|
| Career activity | `/api/career/activities` | 활동 CRUD·timeline·source links |
| Experience | `/api/career/experiences` | 경력/경험 CRUD |
| Applications | `/api/career/applications` | 지원·면접·상태 |
| Documents | `/api/career/documents` | 문서·버전·템플릿 |
| Portfolio | `/api/career/portfolios` | 공개 설정·항목·링크 |
| Projects | `/api/projects` | 프로젝트·멤버·기여·WBS 연계 |
| Integrations | `/api/integrations/accounts` | GitHub·클라우드 연결 |
| AI jobs | `/api/ai/jobs` | 요청·상태·취소·결과 참조 |
| Automation | `/api/automation/jobs` | 승인·전송·결과 |

## 5. 구현 상태 작성 규칙

- 서버 코드가 있어도 화면이 호출하지 않으면 화면 상태는 `미연결` 또는 `일부`다.
- 화면이 동작하더라도 고정 시연 값이면 `시연`이다.
- 외부 연결 상태를 조회하는 것과 실제 OAuth/API 호출은 다르다.
- AI 제공 상태 `true`와 실제 특정 업무 기능의 모델 호출·검증은 분리한다.
- 신규 FD는 API·화면·검증·문서 항목을 모두 연결한 뒤 완료로 변경한다.
