# Timebar Diary UI 작업 프롬프트 템플릿

이 템플릿은 Claude Code/Codex에 신규 화면, 기존 화면 개선, 테마 설정 작업을 요청할 때 사용한다. 이미 대화나 이슈에 제공된 정보는 다시 묻지 말고 그대로 가져온다. 불명확한 정보는 임의로 만들지 않고 가정으로 표시한다.

## 작업 요청

```text
Timebar Diary의 [화면/컴포넌트 이름]을 [신규 구현/개선/버그 수정]한다.

[먼저 읽을 문서]
- 저장소 루트 DESIGN.md 전체
- AGENTS.md 및 Claude Code 사용 시 CLAUDE.md
- 관련 화면/라우터/공통 컴포넌트/스토어/API/CSS/테스트

[사용자와 목적]
- 주요 사용자: [누가]
- 사용자의 목적: [무엇을 완료하려는가]
- 성공 기준: [사용자가 어떤 상태가 되면 성공인가]

[화면 정보]
- 필수 정보: [반드시 표시]
- 보조 정보: [상황에 따라 표시]
- 주요 행동: [가장 중요한 행동 1개]
- 보조 행동: [있다면]
- 상태: 기본, 로딩, 빈 상태, 오류, 성공, 비활성, 선택 상태

[디자인]
- DESIGN.md의 레이아웃, 타이포그래피, 간격, 모서리, 색상 역할을 따른다.
- 기본 테마는 라이트 + 포레스트다. 테마 선택 기능이 영향을 받으면 다른 표면/색상 조합도 검증한다.
- 기존 로고·아이콘·디자인 시스템 컴포넌트를 먼저 재사용한다.
- 같은 크기의 카드 반복, 장식용 그라데이션, 불필요한 아이콘/뱃지/그림자를 추가하지 않는다.

[기술 제약]
- 기존 프레임워크, 폴더 구조, 라우팅, 상태 관리, API 규칙을 유지한다.
- 서버 저장과 로컬/모의 저장을 명확히 구분한다.
- 새 의존성을 추가하기 전 필요성과 번들 영향을 설명한다.
- 관련 없는 파일은 수정하지 않는다.

[반응형/접근성]
- 1440px, 1024px, 768px, 390px, 320px에서 점검한다.
- 200% 확대, 키보드 이동, focus-visible, accessible name, 색상 외 상태 표현을 점검한다.
- reduced-motion 설정을 존중한다.

[완료 기준]
- 관련 테스트 및 빌드/타입 검사를 실행한다.
- 바뀐 파일과 변경 이유를 요약한다.
- 실행한 검증 명령과 실제 결과를 기록한다.
- 수행하지 못한 검증과 남은 위험을 구분해 보고한다.
```

## 테마 설정 화면 전용 추가 요청

```text
환경설정의 화면 테마 설정 UI를 구현한다.

1. 표면 모드와 색상 분위기를 서로 독립적으로 선택할 수 있게 한다.
2. 표면 모드: 라이트, 다크, 세피아, 고대비.
3. 색상 분위기: 포레스트, 잉크, 플럼, 클레이, 모스.
4. 각 선택 카드는 실제 UI 일부(배경, 카드, 제목, 버튼)를 미리 보여준다.
5. 현재 선택은 체크 아이콘/테두리/접근 가능한 상태로도 표현한다.
6. 선택 변경은 미리보기에 먼저 반영하고 적용/취소/기본값 복원을 분리한다.
7. 적용은 실제 설정 저장 성공 후에만 완료 처리한다.
8. 모든 테마 조합의 텍스트 대비, control border, focus ring, data contrast를 검증한다.
9. 사용자 지정 accent를 제공한다면 원본 선택색과 보정 적용색, 대비 수치를 안내한다.
10. 모바일에서는 선택 영역과 미리보기를 1열로 배치한다.
```

## 리뷰어 체크

- [ ] 화면 목적과 주 행동이 명확하다.
- [ ] 기존 프로젝트 스타일과 컴포넌트를 재사용한다.
- [ ] 레이아웃이 콘텐츠에 맞고 과도한 카드/장식이 없다.
- [ ] 색상과 글자 대비가 적절하며 색상만으로 상태를 전달하지 않는다.
- [ ] 로고와 아이콘 사용이 일관되며 타사 브랜드 자산을 복제하지 않는다.
- [ ] 빈 상태/로딩/오류/성공/비활성/선택 상태가 확인된다.
- [ ] 데스크톱·태블릿·모바일 및 키보드 접근성이 확인된다.
- [ ] 테스트 결과와 미검증 항목이 보고되었다.
