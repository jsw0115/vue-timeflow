# 결정·근거·인수인계 메모

- 공유 범위는 그룹 멤버 행(`feature_member.share_level`)에 둔다. 일정마다 공유를 고르는 방식보다 단순하고, 그룹마다 다르게 보일 수 있다(UT-193). 처음 값은 none이라 그룹에 들어가기만 해서는 아무것도 보이지 않는다.
- 범위 밖 필드는 서버 응답에서 뺀다. 화면에서 가리면 개발자 도구로 볼 수 있기 때문이다(UF-112). 일정 ID도 담지 않아 다른 API로 원본을 부를 수 없다.
- 미리보기는 고른 멤버를 보는 사람으로 같은 `schedules`를 불러 내 일정만 남긴다. 미리보기와 실제 응답이 어긋날 수 없다(UF-111).
- 사람 찾기 횟수(1분 20번)는 서버 한 대의 메모리에 센다. 서버를 늘리면 공유 저장소로 옮겨야 한다(06 IM-10 위험).
- `UserRepository`는 테스트 설정에서 mock이라 테스트마다 `findByEmail`·`findById`를 정해 준다.
- 사용자 변경과 자체 변경 구분: 작업 시작 때 작업 트리는 깨끗했다(마지막 커밋 115c978). 이 단계의 변경은 모두 자체 변경이다.
- 2단계: 서버 응답에 이름이 없어 화면이 ID만 보일 수밖에 없었다. 이메일은 넣지 않고 닉네임만 더했다(이메일은 아는 사람만 정확히 입력해 찾는다는 Q-24 취지).
- 2단계: 초대받은 사람(INVITED)은 그룹 상세 API가 403이라, 수락·거절은 그룹 목록의 "받은 초대"에서만 한다. 거절은 자기 멤버 행 삭제로 했다(새 API를 만들지 않음).
- 2단계: 로그아웃 상태 공유 화면은 시연 데이터를 보이지 않고 로그인 안내만 보인다. 계정끼리 하는 기능을 로컬로 흉내 내면 서버 저장으로 오해할 수 있기 때문이다(CLAUDE.md 1절).
- 2단계: `.form-note`는 muted 글자에 surface 배경이라 DESIGN.md 대비 기준(4.36:1)에 못 미친다. 바꾼 공유 화면 5곳은 배경 없는 `.input-field-help`로 바꿨다. 다른 화면의 `.form-note`는 부록 B 항목이라 손대지 않았다.
- 2단계: 주소록(`store/contacts.js`)은 주소록·할 일·일정 화면이 계속 쓴다. 공유 화면만 떼어 냈고, 쓰지 않게 된 `addGroup`·`groupById`만 지웠다. 주소록과 공유를 잇는 일은 Q-21 결정 뒤다.
- 2단계 브라우저 점검 중 한글이 든 이메일은 브라우저 `type=email` 검사에 걸려 제출되지 않았다. 점검 스크립트의 계정 이메일을 ASCII로 바꿨다. 실제 가입 이메일 규칙과의 관계는 따로 보지 않았다.
- 3단계: 커뮤니티 화면이 넓어 목록·만들기·홈·가입·요청함·멤버·게시판만 연결하고, 챌린지·랭킹·채팅은 3b로 나눴다. 챌린지 화면은 챌린지 작성 창(`challengeError`, `joinedCommunities`)·검색 색인과 같은 로컬 store를 써서 함께 옮겨야 하기 때문이다. 커뮤니티 채팅은 서버 API가 없다.
- 3단계: 서버에 값이 없는 화면 요소(오늘 인증 수, 신규 배지, 커버 이모지, 역할 변경, 공지 고정, 인증 목표·규칙 동의, 방장 자동 대화, 처리 이력 필터)는 지어내지 않고 뺐다.
- 3단계: 비공개 커뮤니티는 초대받은 사람만 들어오므로, 방장이 초대할 수단이 없으면 쓸 수 없다. 서버 초대 API는 있어 멤버 화면에 이메일 초대를 두었다.
- 3단계: 전역 작성 창의 "커뮤니티 글"은 로컬 store에만 쓰여 서버 게시판에 보이지 않으므로 종류에서 뺐다.
- 3단계: 게시글 시각은 서버 UTC 값을 잘라 보이고 있어 한국 시간과 9시간 어긋났다. 기기 시간대로 바꿨다(`localTime`).
- 새 컨테이너에서는 Docker 데몬·MySQL·백엔드·Vite가 꺼져 있다. 다시 띄우는 명령은 `dockerd &`, `docker compose -f infra/chat/compose.yml up -d --wait`, `sh ./gradlew bootRun --args="--spring.profiles.active=chat-local --server.port=18080"`, `DEV_API_TARGET=http://127.0.0.1:18080 npx vite --port 15173 --strictPort`다.
- 다음 작업: 3b 또는 4단계(업무·WBS·위키). 첫 명령은 `grep -n "work" frontend/src/router/index.js`다.
- 3b 결정(2026-11-20 사용자 선택): Q-25 커뮤니티 채팅은 회원과 채팅방을 자동 동기화한다. Q-26 랭킹은 챌린지별 인증 랭킹으로 하고, 그 시간에 그 일을 했는지 확인하는 연계와 개인 기록 공개에 동의하는 별도 챌린지를 둔다. 전체 달성률 랭킹 서버는 만들지 않는다.
- 3b-1: 인증 근거는 실제 기록(ACTUAL_SESSION) 중 `finishKey`가 있는 완료 기록만 쓴다. 시작 시각을 서버가 찍었고 종료는 현재 시각을 넘을 수 없어 나중에 지어낼 수 없다. 백업 복원 기록은 `finishKey`가 없어 근거가 될 수 없다.
- 3b-1: 인증 날짜는 기록 시작 시각을 사용자 하루 기준(`DayPolicy`, 시간대·하루 시작 시각)으로 바꾼 날짜다. 시간대 조건(예: 06:00~08:00)이 있으면 그 구간과 겹친 시간만 센다.
- 3b-1: 인증은 feature_member의 CHECKIN 행 대신 새 테이블 `challenge_checkin`(V12)에 둔다. 근거(기록 ID·서버 시각·분)를 열로 남겨야 해서다. 기존 CHECKIN 행은 V12에서 옮기고 지운다.
- 3b-2: 챌린지·랭킹은 커뮤니티마다 따로라 `?id=` 없이 들어오면(사이드바) 내 커뮤니티 목록(`CommunityPicker`)을 보인다. 커뮤니티 탭에 챌린지를 더했다.
- 3b-2: 화면당 주 액션은 "챌린지 만들기" 하나로 두고, 카드마다 반복되는 참여·인증·랭킹·참여 취소는 보조 버튼으로 했다(DESIGN.md 4장 button-primary).
- 3b-2: 예전 랭킹 화면의 "업무 기록 제외"·"랭킹·비교에서 제외" 안내는 로컬 설정이고 서버 랭킹에 영향이 없어 뺐다. 서버 랭킹 참여 끄기는 UF-136(PR-19)이다.
- 3b-2: 검색 색인(`post-index`, 로컬)에서 커뮤니티·챌린지·게시글을 빼고, 예전에 들어간 `/community/` 항목은 앱을 열 때 지운다. 쓰이지 않게 된 `communityPosts.js`·시연 목록·`toggleMembership`·`challengeError`와 그 테스트를 지웠다. `workPrivacy.sanitizeForShare`는 정책 함수로 문서화돼 있어 남겼다(지금 쓰는 곳 없음).
- 3b-2: chat-local MySQL은 `connectionTimeZone=UTC`라 DATETIME을 `LocalDateTime`으로 읽어 JVM 시간대로 해석하면 9시간 어긋난다. 브라우저 점검을 준비하며 설정을 보다 찾았고 `getTimestamp`·`LocalDate`로 고쳤다(별도 커밋 64fe57a). H2 테스트로는 잡히지 않는다.
- 3b-2: 전역 `.event span { display: grid }`가 목록 행 안의 숫자 span을 따로 줄에 세운다. 새 화면(랭킹 행, 커뮤니티 고르기 행)에서만 안쪽 span을 인라인으로 덮었다. 전역 규칙은 다른 화면이 기대고 있어 손대지 않았다.
- 이 PC의 로컬 격리 DB는 3b-2 점검 때 V9에서 V12로 올라갔다(bootRun chat-local). 백엔드 18080·Vite 15173이 떠 있다.
