# 결정·근거·인수인계 메모

- 수정 재전송: 서버는 같은 키의 재전송에 그 기록의 현재 값을 돌려준다(처음 응답 본문은 저장하지 않음). 그 사이 다른 기기가 고쳤으면 응답 version이 "보낸 version + 1"이 아니다. 대기열은 이 경우 충돌로 보고 그 기록의 다음 변경을 멈춘다. 자동 덮어쓰기 금지(UF-103) 때문이다.
- 키 해시에 기록 ID를 넣었다. 같은 키로 다른 기록을 고치면 409다.
- `IdempotencyKeys.create`는 그대로 두고 `apply(…, statusCode, …)`를 더했다. `create`는 `apply(…, 201, …)`를 부른다.
- 메모 수정 화면이 없어 UT-185(메모 충돌)의 브라우저 점검은 할 일로 대신할 수 있다. 메모 쪽은 Node·HTTP로 확인한다. 3단계에서 정한다.
- 로그아웃 안내(UF-105)는 실제 로그아웃이 있는 채팅 화면 `signOut`에 붙인다. 앱 기본 레이아웃에는 로그아웃 버튼이 없다.
- 2단계: 보낼 때마다 저장소를 다시 읽는다. 생성이 끝나면 뒤 항목(같은 대상)의 대상을 서버 ID로 바꾸고 첫 뒤 항목에만 기준 version을 넣은 다음, 보낸 항목을 지운다. 그 사이 멈춰도 다시 보내면 멱등 키가 같은 결과를 준다.
- 연결 실패(`network`)와 5xx·401(`server`)은 멈춘다. 409·400·404는 확인 필요로 두고 그 대상만 막는다.
- 반응형 객체를 IndexedDB·`structuredClone`이 복제하지 못해 저장 전에 JSON으로 복사한다.
- 3단계: 대기열 사용은 요청마다 `{ offline: true }`로 고른다. 메모 생성, 체크리스트 없는 할 일 생성, 체크리스트가 그대로인 할 일 수정만 고른다(체크리스트는 범위 밖).
- 목록은 서버 목록 위에 대기 항목의 `preview`(화면 모양 값)를 겹쳐 그린다. 대기열이 진짜 원본이고 보낸 뒤 서버 목록을 다시 불러온다.
- 대기 중인 기록에 완료 표시·삭제·체크리스트·일정 배치를 하면 순서가 어긋나므로 `kind: 'offline'` 오류로 막는다.
- 로그아웃: 채팅 화면의 로그아웃 버튼은 실제로 열리지 않는 화면에 있다. 보안·계정에 "이 기기에서 로그아웃"을 두었다. 사용자에게 알릴 결정이다.
- UT-185는 메모 수정 화면이 없어 브라우저에서는 할 일로, 메모는 Node(TS-35)로 확인했다.
- PR-12 완료(2026-11-20). 범위 밖: 삭제·첨부·체크리스트·다른 기록 종류의 오프라인 처리. 7일이 지난 멱등 키는 지워진다.
