# 작업 계획

- 요청: 2026-11-19 "표 수정해야 할 부분들은 수정해 주고 다음 우선순위 진행해줘." 10 통합표의 PR-07 상태 불일치를 고친 뒤(커밋 `3f4879e`), 최종 처리 순서의 다음 사용자 기능인 PR-08을 진행한다.
- 기준 기획: 09 4절(UF-90~UF-96, UT-140~UT-150), 09 권장 결정 Q-06·Q-12, 06 IM-08.
- 현재 확인한 사실(2026-11-19 소스 대조)
  - 할 일은 JPA `task` 표(소프트 삭제 `d_at`), 일정·실제 기록은 `feature_record`(SCHEDULE·ACTUAL_SESSION)다. 저장소가 달라 연결 표에 FK를 둘 수 없다.
  - 실제 기록 시작(`ActualRecordingService.start`)은 `requestId`·`title`·`timeZone`만 받는다. 원본 정보를 받을 곳이 없다.
  - 일정 삭제는 공통 `RecordService.delete`, 할 일 삭제는 `TaskService.delete`(소프트 삭제)다.
  - 기존 `task.event_id`는 구형 `events`용 문자열 열이다.
  - 통계(`InsightService`)는 오늘을 `Asia/Seoul`로 고정하고, 실제 기록은 기록마다 저장한 시간대로 자정에 나눈다. 프로필(`SettingsService.profile`)은 `users.tz`를 이미 검증·저장한다. 하루 경계 값은 없다.
  - 프런트는 통계·프로필 API를 아직 부르지 않는다. 일간 플래너 타임라인은 08~23시만 그린다.
