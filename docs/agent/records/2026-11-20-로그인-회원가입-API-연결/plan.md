# 작업 계획

- 요청: 2026-11-20 "현재 백엔드 설정과 프론트엔드 API를 연결해서 로그인/회원가입까지 되게 해줘."
- 현재 확인한 사실
  - 백엔드 기본 프로파일: `application.yml` 포트 기본값 8081(사용자 미커밋 변경), DB `localhost:3307/timeflow`(backend/.env), 채팅 Redis 16389. 로컬 DB Flyway는 본 스키마 V12·채팅 V5로 저장소 최신과 같다(기동해도 스키마 변경 없음).
  - Vite 프록시 기본 대상은 8080인데 이 개발 PC에서는 8080을 다른 프로그램이 쓰고 있다. 그래서 `/api`가 엉뚱한 서버로 갔다.
  - 기본 프로파일 CORS 허용 출처가 `http://localhost:5173`뿐이다. 로컬 실행 가이드는 `http://127.0.0.1:5173/`을 열라고 하므로 브라우저 POST(가입·로그인)가 403으로 막혔다. chat-local 프로파일에는 127.0.0.1:5173이 있다.
  - 라우터의 가입 화면은 `features/auth/views/SignupView.vue`(서버 연결됨)다. `views/auth/SignupView.vue`는 쓰이지 않는 예전 시연 파일(가짜 휴대폰 인증)이다.
  - 가입 화면: 체크 하나로 두 동의를 함께 보냄, 비밀번호 종류(2종) 검사 없음, 입력 전부터 첫 오류 노출, 가입 뒤 /chat. 로그인 뒤 기본 도착도 /chat. 온보딩은 이름 '지수님' 고정·고른 모드 미저장.
- 범위: 연결 설정, 기본 CORS 허용 출처, 가입·로그인·온보딩 화면, 인증 오류 문구. API URL·요청/응답·인증 방식·DB 구조는 바꾸지 않는다.
- 제외: 소셜 로그인(미연결 안내 유지), 비밀번호 재설정 실제 발송, 쓰이지 않는 `views/auth/SignupView.vue` 삭제(별도 정리).
