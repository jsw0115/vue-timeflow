# 작업 계획

- 요청: 화면 본문을 표시 언어(한국어·English)로 옮긴다(01 PR-32, 09 Q-38). 2026-11-25 커리어부터 홈·통계까지 단계별로 진행했고, 이 폴더는 2026-11-26에 그동안의 진행을 정리하며 만들었다(CLAUDE.md 7절 작업 기록. 그 전에는 dev-docs 07 실행 결과로 대신했다).
- 현재 확인한 사실: 번역 함수 `tr()`(`frontend/src/store/locale.js`)는 한국어 원문을 키로 쓰고, 영어는 `frontend/src/features/i18n/dictionary.mjs`의 `EN`에 있다. 영어로 옮긴 경로는 `translatedRoutes.mjs`의 `TRANSLATED_PATHS`·`TRANSLATED_PREFIXES`이고, 그 밖의 화면은 본문과 `<html lang>`이 한국어다. 표시 언어는 로그인 상태면 `/api/settings/general`의 `locale`(ko·en), 로그아웃이면 이 브라우저에 남는다.
- 범위/제외: 범위는 화면 문구·날짜 형식·숫자 단위·문서 버전 언어 표시. 제외는 사용자가 쓴 기록, 저장값(분류·상태 등 한국어 값), 내보내는 문서(PDF·Word) 본문, 생성 초안, 시연 예시 제목. 일본어·중국어는 필요할 때 추가한다(Q-38 (5)).
- 성공 기준: 영어로 옮긴 화면의 사전 값에 한글이 없고 자리표시가 원문과 같다(사전 시험). 한국어 표시는 예전과 같다. 프런트 전체 테스트·빌드 통과, 브라우저에서 영어·한국어 확인.
- 보안 관련 ID/검증: 입력값 검증(서버가 locale·language를 ko·en만 받음), HTML 출력(`v-html`은 홈 첫 문장의 고정 사전 문구에만 씀). 정식 SW 49·웹 28·OWASP 점검은 하지 않았다(verification.md).
- 접근성 대상/검증: KWCAG 언어 표시(화면별 `<html lang>`), 버튼·입력의 접근 가능한 이름 번역. 정식 KWCAG 점검은 하지 않았다.
- 사용자 요청으로 이미 허용된 작업과 추가 확인이 필요한 작업: 단계별 커밋과 작업 브랜치 푸시는 허용됨. 남은 화면(환경설정·공유·커뮤니티·관리자) 진행은 사용자 확인 뒤 한다.
