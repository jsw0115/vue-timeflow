# 맥락 메모

## 측정 방법

- 헤드리스 Chrome(`--headless=new`)은 창 최소 폭이 있어 `--window-size=320`이어도 `innerWidth`가 526이다. 앞 작업의 360px 캡처는 526px 레이아웃을 잘라 본 것이었고, "앱 셸 전체가 넘친다"는 판정은 틀렸다.
- 정확한 폭은 같은 출처 페이지 안의 iframe 폭으로 준다. 페이지 전체(`html`, `body`, `main`, `.app`)의 `scrollWidth - clientWidth`와, 뷰포트 오른쪽을 넘는 요소 중 부모는 넘지 않는 요소(넘침이 시작되는 곳)를 기록한다. 표처럼 자기 안에서 가로 스크롤하는 영역 안의 요소는 의도한 것이라 뺀다.

## 원인과 결정

- 지표 행: 18개 화면이 `.metrics`에 인라인 `grid-template-columns: repeat(N, 1fr)`를 줬다. 인라인 스타일이 1150px 이하 2열 규칙을 이겨 320px에서도 4~5열이 되고, `1fr`의 최소값이 내용 폭이라 열이 줄지 못했다. 열 수를 `--metric-cols` 변수로 옮겨 넓은 화면에서만 쓰이게 하고, 열은 `minmax(0, 1fr)`로 바꿨다. 이 변경으로 761~1150px에서도 이 화면들의 지표가 2열이 된다(DESIGN.md 8장 규칙과 같다). `auto-fit`을 쓰는 감사 로그는 이미 반응형이라 두었다.
- 주간 타임테이블: 760px 이하에서 `.timetable`이 `overflow-x: auto`와 `min-width: 640px`를 함께 가져, 스크롤 영역 자신이 640px보다 좁아질 수 없었다. 그래서 표 안에서 스크롤되지 않고 카드와 화면을 682px로 밀어냈다. 최소 폭을 요일 칸(80px × 7)으로 옮기고, 그리드 열을 `minmax(0, 1fr)`로 바꿔 카드가 화면 폭에 맞고 표만 스크롤되게 했다.
- 헤더 액션(768px): 긴 제목과 액션 묶음이 함께 줄어들면서, 앞 작업에서 `flex: none`이 된 40px 아이콘 버튼이 묶음 밖으로 밀리고 "새 글 작성"이 49px로 접혔다. 액션 묶음은 줄어들지 않게 하고, 헤더를 줄바꿈 가능하게 해 자리가 없으면 액션이 제목 아래 줄 오른쪽으로 가게 했다. 760px 이하의 기존 규칙(액션 줄 전체 폭)은 그대로 이긴다.
- 다이어리 입력(375px): 라벨 글자와 같은 줄의 날짜 입력이 라벨 폭을 넘었다. `.form-row` 라벨 안 입력에 `max-width: 100%`를 줬다.

## 남은 일·발견

- 760px 이하에서 지표 행 마지막 카드를 숨기는 기존 규칙(`.metrics article:last-child{display:none}`) 때문에 지표가 3개인 화면은 2개만 보인다. 의도인지 확인이 필요하다.
- 주간 타임테이블의 시간 눈금 글자(9시·12시…)가 34px 칸 안에서 붙어 보인다. 넘침과 별개의 기존 표시 문제다.
- 다이어리 "오늘의 플래너 항목" 제목 줄바꿈 문제는 그대로다.
