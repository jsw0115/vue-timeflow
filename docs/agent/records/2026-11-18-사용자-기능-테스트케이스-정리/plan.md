# 작업 계획

- 요청: 시니어 기획자 관점으로 docs 문서를 분석해 사용자 중심 기능 목록과 개발자가 참조할 테스트 케이스 문서를 작성한다.
- 현재 확인한 사실: 요청이 지목한 `docs/reference`(`docs/referenece`) 폴더는 없다. 사용자가 기존 docs로 진행하고 결과를 dev-docs 08 새 파일로 두기로 선택했다.
- 범위/제외: 문서 작성만 한다. 코드·테스트 구현은 하지 않는다. P2·P3 의견(PR-19·PR-20)은 기능 범위가 정해지지 않아 제외한다.
- 성공 기준: 08 문서에 사용자 유형·하루 흐름·공통 요구·UF·UT·확인 필요 사항이 있고, 입력 규칙이 소스와 일치하며, README·03·07의 연결과 버전이 갱신되어 있고, 문서 검사를 통과한다.
- 보안 관련 ID/검증: 문서만 변경. 비밀값·계정·사용자 기록 원문을 넣지 않았다.
- 접근성 대상/검증: UI 변경 없음. 접근성 테스트 케이스(UT-C7)를 정의만 했다.
- 사용자 요청으로 이미 허용된 작업과 추가 확인이 필요한 작업: 문서 작성·문서 커밋은 기존 dev-docs 작업 방식에 따른다. Q-01~Q-09 결정은 사용자·개발자 확인이 필요하다.
