# 맥락 메모

## 결정

- 범위를 3단계로 나눴다. 1단계는 쉬는 날 구조와 루틴(UF-134 본체·Q-05 서버 계산), 2단계는 일정 회차 override·분할(Q-03 나머지), 3단계는 루틴 첫 수치 변경(Q-05 화면)이다. 3단계는 로컬 루틴 자료에 날짜별 완료 기록이 없어 PR-07에서 `/history`를 쓸 때 한다. 로컬 시연 자료에 날짜별 모델을 새로 만들면 PR-07에서 버릴 코드가 된다.
- action은 `skip`만 허용했다. `override`는 바꿀 필드가 정해지지 않았으므로 지금 받으면 검증 없는 자료가 쌓인다. 2단계에서 필드와 함께 추가한다.
- 쉬는 기간(휴가)은 별도 구조(`from`·`to`) 없이 기간 안의 예정 회차마다 `skip`을 넣는다. Q-03의 "예외 구조 하나"를 지키고 서버·프런트 계산이 날짜 집합 하나로 끝난다. 예정되지 않은 날은 넣지 않아 366개 한도를 아낀다.
- 쉬는 날은 count 종료의 회차 수에 포함한다(쉬어도 반복이 뒤로 늘어나지 않음). 회차를 계산한 뒤 쉬는 날을 빼는 방식이라 서버·프런트 모두 단순하다.
- 서버 `RecurrenceRule`에 `plannedDates`(규칙만)와 `dates`(쉬는 날 제외)를 나눴다. history는 "반복에 없는 날"과 "쉬는 날"을 구분해야 하므로 규칙만의 회차가 필요하다.
- history 항목에 `status`(done·missed·skipped·pending)와 응답에 `skipped` 수를 더했다. 기존 필드는 그대로라 추가 변경이다. `total`의 뜻은 "예정 회차 수"에서 "done+missed 수"로 바뀌었다. 오늘 미완료·미래 회차를 분모에서 빼려면 바꿀 수밖에 없고, 화면은 아직 이 API를 호출하지 않는다(PR-07).
- 오늘 기준을 테스트에서 고정하려고 `history(..., LocalDate today)` 패키지 전용 오버로드를 뒀다. 앱 전체에 Clock 빈을 새로 넣는 것보다 변경이 작다.
- 쉬는 날에 완료 로그가 이미 있으면 상태는 `skipped`로 계산하고 `completed`는 로그 값을 그대로 보인다. 쉬는 날 완료 기록 요청은 400이라 정상 흐름에서는 생기지 않는다. 화면은 완료한 오늘을 쉬는 날로 정하지 못하게 막는다.
- 루틴 목록의 기존 "쉬기"(무기한 `paused`) 버튼을 "중지"로 바꿨다. 새 "쉬는 날" 버튼과 이름이 거의 같아 혼동된다. "쉬는 중" 필터는 중지한 루틴과 오늘 쉬는 루틴을 함께 보여 준다.
- 화면 안내 문구는 로컬 카운터에서도 참인 내용만 적었다("쉬는 날은 계산에서 빠지고 연속 기록이 이어진다"). "놓친 날은 끊긴다"는 서버 규칙이지만 로컬 카운터는 놓친 날을 모르므로 화면에 적지 않았다(UF-C5).
- 알림 발송 기능이 서버·브라우저 모두 없어 "알림을 보내지 않는다"는 회차 판정으로만 보장한다. PR-09에서 발송을 만들 때 같은 판정을 쓰도록 IM-14에 적었다.

## 발견

- 중지(`paused`)한 루틴은 서버 history에서 지난 회차까지 모두 빠진다. 중지 전 기록이 사라져 보이고 달성률이 바뀐다. 이번 범위가 아니어서 09 Q-20으로 등록했다.
- 지난 날짜를 쉬는 날로 추가하는 것을 서버가 막지 않는다. 화면은 오늘 이후만 받는다. 09 Q-19로 등록했다.

## 보안 점검(변경 범위)

- 입력 검증(SW 입력 데이터 검증, OWASP A03·A04): 예외 목록은 배열 여부, 최대 366개, 항목 키 `date`·`action`만, action 허용 목록(`skip`), 날짜 형식(`YYYY-MM-DD`, 실제 존재 날짜), 날짜 중복을 서버에서 검사한다. 기존 `FeatureInput.bounded`의 깊이 8·배열 500·문자열 20,000 제한도 그대로 적용된다. 경계 테스트(366 허용, 367 거부, 중복·잘못된 날짜·추가 키·문자열 거부)를 `RecurrenceExceptionTest`에 두었다.
- 자원 사용(SW 자원 고갈, OWASP A04): 예외 수를 묶어 반복 규칙 JSON 크기와 회차 계산 비용을 제한한다. history는 쉬는 날 집합을 한 번만 만든다.
- 소유권(OWASP A01): 회차·history·완료 기록은 기존과 같이 `store.get/lock(user, ...)`으로 본인 자료만 읽는다. 예외 목록은 루틴 수정(`RecordService.update`, version 필수)으로만 바뀐다. 다른 계정 자원 접근 경로를 새로 만들지 않았다.
- 화면 출력(웹 XSS): 새 화면 값은 날짜 문자열과 루틴 제목이며 Vue 텍스트 보간으로만 출력한다. `v-html`을 쓰지 않았다.
- 해당 없음: 인증·세션, 비밀값, 파일, SQL 쿼리, 스키마 변경 없음.

## 접근성 점검(변경 범위, KWCAG 2.2)

- 새 버튼은 텍스트 라벨이 있고, 행마다 같은 "쉬는 날"·"해제"가 반복되므로 `aria-label`에 루틴 이름·날짜를 넣었다.
- 날짜 입력은 `<label>` 안에 있어 이름이 연결된다. 오류·안내 문구는 `role="status"`로 읽힌다.
- 대화상자는 기존 `Modal`(네이티브 `dialog`, 닫을 때 이전 포커스 복귀)을 그대로 쓴다.
- 좁은 폭: 날짜 입력 줄과 목록 항목, 행의 관리 버튼에 `flex-wrap`을 줬다. 루틴 목록은 기존대로 760px 미만에서 가로 스크롤이다.
- 색만으로 상태를 전하지 않는다("오늘 쉬는 날" 텍스트 표시). 새 색·radius를 쓰지 않고 토큰만 썼다.
- 실제 브라우저의 키보드·320px·200% 확대·화면낭독기 점검은 하지 않았다(NOT_RUN).
