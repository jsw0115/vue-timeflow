# 작업 계획

- 요청: UF-134 회차 예외 구현 시작(2026-11-18). 09 권장 결정 Q-03·Q-05·Q-14에 따라 PR-03 바로 다음 작업이다.
- 현재 확인한 사실
  - 반복 계산은 서버 `RecurrenceRule.dates()`와 프런트 `recurrence.mjs`의 `occurrenceDates()` 두 곳이다. 둘 다 예외 개념이 없다.
  - 서버 `RecurrenceRule.validate()`는 frequency가 none이 아니면 허용 키를 `frequency interval weekdays endMode until count`로 제한한다. none이면 키 검사 없이 바로 돌려준다.
  - 서버 루틴 회차 판정(`ScheduleService.occurs`)은 recurrence가 none이 아니면 반복 규칙, none이면 `days`를 쓴다. `paused`면 모든 날짜가 회차에서 빠진다.
  - 서버 `history()`는 회차가 아닌 날을 건너뛰고, 완료하지 않은 회차는 오늘·미래여도 연속 기록을 0으로 만든다. 그래서 오늘 아직 안 한 루틴이 있으면 연속 기록이 항상 0이다.
  - 서버에는 루틴 알림 발송 코드가 없다. 프런트 알림도 설정값 저장뿐이다.
  - 프런트 루틴 화면은 로컬 시연 저장이다. `done`·`streak`·`history`(7칸)는 날짜와 무관한 카운터라서 날짜별 달성률을 계산할 자료가 없다.
- 범위
  - 반복 규칙 안 예외 목록 `recurrence.exceptions: [{date, action:'skip'}]`. 일정·루틴 공용, 반복당 최대 366개, 날짜 중복 금지.
  - 서버: 검증, 일정 회차·루틴 회차에서 skip 날짜 제외, 루틴 history의 Q-05 계산(쉬는 날·반복 없는 날은 끊지 않음, 지난 미완료 회차만 끊음, 오늘 미완료·미래는 계산 보류), 항목별 상태 추가.
  - 프런트: `recurrence.mjs` 예외 검증·적용, 루틴 화면의 "오늘 쉬기"·"쉬는 기간" 입력과 해제, 계산 방식 안내.
  - 문서: 06 IM-14 신설, 01·09·07·08, API 규약·계약 검사.
- 제외(다음 단계로 기록)
  - 일정 회차의 override("이 회차만 변경")와 "이후 회차 수정" 분할, 일정 화면의 회차 건너뛰기 UI(Q-03 나머지).
  - 화면 첫 수치를 "최근 4주 달성률"로 바꾸는 일(Q-05 화면 부분). 로컬 자료에 날짜별 완료 기록이 없어 서버 history를 쓰는 PR-07 루틴 연결 때 한다.
  - 알림 발송(서버·브라우저 모두 없음). 발송 기능은 PR-09에서 회차 판정 함수를 쓰도록 한다.
- 성공 기준: UT-236~UT-238 통과, 예외 검증 경계(366·367개, 중복, 잘못된 action) 통과, 일정 회차에서 skip 날짜 제외, 프런트 Node 테스트·계약 검사·빌드 통과.
- 보안 관련: 입력 검증(예외 목록 크기·형식·키 제한), 소유자 범위 유지(기존 `store.get/lock(user, ...)`), JSON 크기 상한.
- 접근성: 새 버튼·날짜 입력의 라벨, 키보드 조작, 포커스 표시, 상태 안내 문구. 320px 폭에서 줄바꿈.
- 허용된 작업: 코드·테스트·문서 수정과 로컬 커밋. 푸시·배포·운영 DB 변경은 하지 않는다.
