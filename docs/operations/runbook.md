## 사용자 기본 안내

가입·로그인 후 홈에서 날짜와 요약을 확인합니다. 플래너의 일/주/월/년 보기를 선택하고 일정·할 일·루틴·개인 기록을 유형별로 작성합니다. 업무·WBS·위키·경력은 개인 자료로 관리하고 포트폴리오는 선택한 항목만 공유합니다. 기능별 필수값과 화면은 [기능 명세](../handbook/source/05-기능-명세서.md)·[화면 명세](../product/screen-design.md)를 따릅니다.

현재 일부 화면은 브라우저 로컬 시연 자료입니다. 다른 브라우저·기기에서 보이지 않는 경우 서버 장애로 단정하지 말고 실제 API 연결 상태를 확인합니다. 로컬 데이터 삭제·브라우저 초기화 전에 필요한 자료를 보관합니다. 서버 내보내기는 프로필·feature_record 중심이며 전체 파일·구형 기록·채팅을 포함한 전체 백업이 아닙니다.

AI·음성·외부 캘린더·실결제 등은 제공자 미연결 경계입니다. 해당 기능의 화면·설정값을 실제 분석·승인·발송 성공으로 해석하지 않습니다. 오류 시 날짜·화면·행동·응답 상태·재현 단계를 기록하고 비밀번호·토큰·개인 원문을 문의에 첨부하지 않습니다.

## 운영자 점검

| 주기 | 점검 | 기록·조치 |
| --- | --- | --- |
| 배포 직후 | SHA·웹·내부 API health·로그인·DB·SSE·파일·라우팅 | 실제 환경·시간·성공/실패·담당·증거 |
| 매일 제안 | 가용성·오류·DB 연결/디스크·Redis 메모리·outbox 지연·백업 | 임계값은 부하 측정 후 확정, 이상은 작업 원장 |
| 매주 제안 | 복원 표본·용량 증가·느린 조회·로그 접근·공유/만료 | 운영 정책·보관 기간과 일치하는지 확인 |
| 매월·변경 시 | 의존성·인증서·키·계정·비용·권한·삭제 정책 | 별도 검증 후 변경, 무조건 최신 교체 금지 |

위 주기는 제안이며 자동 스케줄러가 이미 등록된 것은 아닙니다. 알림 채널·담당자·당직·에스컬레이션·실제 임계값을 서비스 출시 전에 확정합니다. 현재 healthz는 웹 응답이며 내부 API·DB·Redis 상태를 모두 보장하지 않습니다.

```bash
# 프로젝트 루트, 운영 .env가 준비된 승인 계정에서 조회합니다.
docker compose --env-file infra/deploy/.env -f infra/deploy/compose.yml ps
docker compose --env-file infra/deploy/.env -f infra/deploy/compose.yml logs --tail=100 api
docker compose --env-file infra/deploy/.env -f infra/deploy/compose.yml exec -T api \
  wget -q -O - http://127.0.0.1:8080/actuator/health
curl --fail http://127.0.0.1:8088/healthz
```

HTTPS 환경은 실제 배포 때 사용한 overlay·도메인과 일치시킵니다. 로그를 공유하기 전 사용자 정보·키·요청 내용을 확인합니다. 운영자 API는 프록시 외부 차단과 ADMIN 검사를 모두 고려해 승인된 내부 접근 경로를 사용합니다.

## 장애 대응

1. 발생 시각·영향 사용자·영향 기능·배포 SHA·증상을 기록합니다.
2. 데이터 노출·손상·결제 오처리면 해당 기능의 새 쓰기·호출을 먼저 제한합니다. 증거와 원본을 보존합니다.
3. 웹·프록시·API·DB·Redis·외부 제공자를 순서대로 구분해 실제 로그·상태를 확인합니다.
4. 재현 가능한 경우 격리 환경에서 검증하고, 호환 가능한 이전 SHA 복귀나 전진 수정을 선택합니다.
5. 복구 뒤 핵심 시나리오·누락/중복 데이터·공유 권한·원장을 대사합니다.
6. 원인·조치·검증·영향·재발 방지·날짜·버전을 기록합니다. 원인 미확정 상태를 추정과 구분합니다.

| 현상 | 먼저 확인할 항목 |
| --- | --- |
| 웹 502 | API health·서비스 이름·DB 의존·프록시 DNS 재조회 |
| 로그인 401 | 토큰 만료·refresh·계정 상태·키/issuer 변경·전체 세션 무효화 |
| 데이터 404 | 존재 여부·소유권·차단·공유/파일 만료. 무조건 데이터 삭제로 해석 금지 |
| 409 | 오래된 version·중복·동시 잠금. 사용자 변경 보존 후 재조회 |
| 채팅 누락 | DB 메시지·읽음·outbox·Redis·SSE 재연결·REST 보정 |
| 파일 413 | Nginx 본문 10m·Spring 파일 10MB/요청 11MB와 multipart 오버헤드 |
| 연동 503 | capability·제공자 준비 여부. 현재는 예상된 미연결일 수 있음 |
| DB 오류 | 대상 schema·계정·이력·자원. clean·history 삭제·볼륨 삭제 금지 |

## 백업·보안·데이터 요청

백업·코드 롤백·DB 복원은 [Linux 절차](../deployment/gitlab-cicd.md)와 [DB 운영](../database/environment.md)에 단일 관리합니다. 백업 보관·복원 가능성·복원 시점·허용 데이터 손실량과 복구 시간을 실제로 측정하기 전 RPO/RTO를 보장하지 않습니다.

키 회전은 JWT·DB·Redis·Registry 각각 영향과 재인증·실제 계정 변경을 함께 검토합니다. 초기화한 DB의 비밀번호는 .env만 바꿔도 변하지 않습니다. 운영 사용자 계정·역할·접근 기록을 최소 범위로 관리합니다.

계정 내보내기·삭제·공유 철회는 요청자 확인, 범위·법정 보존 의무, 실제 데이터·파일·캐시·링크와 향후 AI 파생자료를 구분합니다. 삭제 처리 완료를 실제 전파 확인 없이 알리지 않습니다. AI 보관 기간 제안은 확정된 운영 정책과 구분합니다.

## 운영 인수인계

환경·도메인·전체 SHA·이미지·DB 이력·백업과 복구 증거·비밀값 위치·권한·알림·담당·최근 장애·남은 과제를 전달합니다. 실제 비밀값은 문서에 쓰지 않습니다. 설치는 [환경 준비](../development/environments.md), 검수는 [배포 계획](../deployment/release-plan.md), 변경은 [릴리스 원장](../releases/README.md)으로 연결합니다.
