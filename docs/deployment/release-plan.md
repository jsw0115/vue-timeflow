## 배포 대상과 선행 조건

| 대상 | 산출물 | 검수 경계 |
| --- | --- | --- |
| Pages | dist → public, 해시 라우팅·상대 자산 | 별도 HTTPS API·CORS·실제 Runner·공개 URL |
| Linux | 동일 전체 SHA의 web·api 이미지와 Compose | DB/Redis·migration·비밀값·백업·TLS·프록시 |
| 설치형 앱 | 플랫폼별 패키지·서명 | 네이티브 빌드·권한·인증·실기기·스토어 정책 별도 |

개발·검증 서버에서 후보 SHA와 migration을 먼저 검수합니다. 운영 도메인·계정·예산·지원 창구·복구 책임을 확정하고 요구사항·알려진 문제·기능 제공 가능 상태를 확인합니다. 배포 대상이 아닌 기존 사용자 변경은 포함하지 않습니다.

## 배포 전후 체크리스트

### 배포 전

- [ ] 목표 버전·전체 SHA·변경 요구·릴리스 노트를 연결했습니다.
- [ ] 관련 테스트·API/DB/화면 문서 검사와 빌드가 통과했습니다.
- [ ] 신규 스키마·기존 데이터·구버전 호환과 migration 순서를 검토했습니다.
- [ ] 검증 환경의 실제 로그인·저장·타인 접근·충돌·SSE를 확인했습니다.
- [ ] 백업이 성공했고 별도 환경의 복원 증거와 보관 위치를 확인했습니다.
- [ ] 운영 .env·키·계정·도메인·인증서·방화벽·포트·디스크를 확인했습니다.
- [ ] 이미지 경로·Registry 읽기 권한·서명/공급망 정책을 확인했습니다.
- [ ] 중단 조건·복구 담당·허용 영향·사용자 안내를 정했습니다.

### 실행과 배포 후

- [ ] 승인된 절차로 같은 SHA의 web·api를 배포했습니다.
- [ ] Compose healthy·내부 API UP·웹 health와 실제 업무 요청을 확인했습니다.
- [ ] 웹 직접 경로·새로고침·HTTPS·API 주소·CORS를 확인했습니다.
- [ ] 계정·자료·파일·공유·채팅·SSE·새 migration을 검수했습니다.
- [ ] 오류·자원·DB·Redis·outbox·업로드 한도를 관찰했습니다.
- [ ] 배포일·환경·실제 SHA·검수·백업·이전 SHA·잔여 문제를 기록했습니다.

모든 체크박스는 실행 전 기본 미완료입니다. 이 문서 작성이나 로컬 빌드로 자동 체크하지 않습니다. 기본 CI는 Pages이고 Linux 검증·이미지는 ENABLE_CONTAINER_BUILD=true에서만 동작합니다. 실제 서버로의 SSH 자동 배포가 이미 구현되어 있다고 가정하지 않습니다.

## 중단·롤백·복구

계정 간 노출·데이터 손상·예상하지 못한 인증 장애·이중 차감·백업 실패·migration 실패·핵심 기능 회귀면 배포를 중단합니다. 일반 오류율·응답 시간·자원 임계값은 기준 부하를 측정해 환경별로 정합니다.

코드 호환성이 확인된 경우 이전 성공 SHA로 복귀합니다. DB는 자동으로 과거 상태가 되지 않으므로 schema 호환이 없으면 전진 수정·제한 운영·승인된 백업 복구를 선택합니다. DB 복원에는 변경분 손실·사용자 영향·파일·Redis·외부 결제 대사를 포함합니다.

release.sh는 backup·pull·health 이후 성공 상태를 기록하지만 DB 역마이그레이션이나 서비스 전환 전체의 무중단·고가용성을 보장하는 도구는 아닙니다. `down -v`나 데이터 디렉터리 삭제를 롤백 명령으로 사용하지 않습니다.

## 배포 기록 양식

```text
릴리스 버전 / 후보 SHA / 이전 성공 SHA
계획일 / 실제 배포 시작·종료 / 환경 / 담당 역할
변경 요구·작업 ID / migration과 호환성
테스트·빌드·실환경 검수와 결과
백업 식별자·격리 복원 결과·비밀값 보관 위치
모니터링 결과 / 잔여 문제 / 중단·복귀 여부
실제 배포 승인 / 사용자 안내 / 후속 작업 날짜
```

실제 배포 기록과 릴리스 노트는 [버전 관리](../releases/README.md)에 추가합니다. 현재 문서 작업에서 운영 서버·Pages·Registry 게시를 실행하지 않았습니다.
