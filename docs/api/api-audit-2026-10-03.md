# 전체 API 목록·구현 상태 대조

2026-10-03. 현재 Java 컨트롤러, 전체 목록·상세 계약·JSON, 채팅/Redis 목록, 기존 목표114개와 확장 목표169개를 HTTP 메서드+전체 경로로 대조했다. 최신 수치는 [기계 검증 결과](api-audit-2026-10-03.json)를 따른다. [2026-09-27 보고서](api-audit-2026-09-27.md)는 당시 검증 기록으로 보존한다.

| 구분 | 대조 결과 |
|---|---|
| 현행 /api | 117개. 이전104개 + 채팅 검색·활성 상태3개 + 이번 신규10개 |
| 이번 구현 완료 | 체크리스트5개, 담당자 후보3개, 플래너 기본 보기2개 |
| 기존 서비스 연결 | 50개. Service 경로 존재 확인이며 전체 기존 동작 재검증을 뜻하지 않음 |
| 미구현 stub | 52개. 실제 조회·저장 로직 없음 |
| 메모리 시연 | 5개. 사용자 격리·영속화 없는 공용 메모리 데이터 |
| 채팅 | HTTP18개가 현행 목록·상세 계약·JSON·채팅 목록에 동일하게 존재 |
| Redis | 연동 HTTP10개, 내부 명령 계약6개. 별도 공개 Redis HTTP 서비스가 아님 |
| 목표 /api/v1 | 169개 전부 설계·미구현. 기존114개 ID 보존, 모든 목표 OpenAPI operation은 PLANNED |
| 생성기 | 현행 상태 분류를 공유하고, 검증한10개 메서드+경로의 명시적 목록만 완료로 표시. 같은 패키지에 향후 추가한 API는 완료 상태를 자동 상속하지 않음. 기존 Service/stub/메모리 구분도 보존 |
| 검증 기록 | 보고서 날짜를 옵션으로 지정하여 과거 결과를 덮어쓰지 않음 |

각 API 상태는 [현행 전체 목록](current-api-inventory.md)에, 요청·응답 필드는 [현행 소스 계약](../api-info/current-contract.md)에 표시한다. 이번 신규 API의 수동 상세 계약·권한·동시성·제한 값은 [체크리스트·플래너 계약](task-planner-contract.md), 사전 설계와 Java 네이밍 규칙은 [구현 계획](implementation-plan-2026-10-03.md), 단위·HTTP·컨벤션 검증 결과는 [실행 기록](implementation-verification-2026-10-03.md)을 따른다.

`구현 완료 · 단위/HTTP 계약 검증`은 이번 신규 Java 소스·단위 테스트·MockMvc 계약 테스트 범위다. 실 MariaDB/Redis에 연결한 통합 검증, 기존 DB migration 실행, 프런트엔드 서버 연동은 이 표시의 범위에 포함하지 않는다. 담당자 후보 등록이 공유 권한을 만들지는 않으며 현재 공유 API는 stub이다. 목표 /api/v1과 이름이 유사하더라도 경로·DTO·버전 정책이 다르므로 목표 계약을 구현 완료로 바꾸지 않는다.

## 재검사

프로젝트 루트에서 실행한다. 아래 명령은 API 문서와 정적 대조만 수행하며 DB 스냅샷이나 운영 DB를 변경하지 않는다.

```powershell
node frontend/scripts/api-inventory.mjs
node frontend/scripts/design-docs/build.mjs . --api-only
node frontend/scripts/api-inventory.mjs --check
node frontend/scripts/design-docs/build.mjs . --api-only --check
node frontend/scripts/design-docs/check.mjs .
node frontend/scripts/audit-api-docs.mjs --date=2026-10-03
node frontend/scripts/audit-api-docs.mjs --check --date=2026-10-03
```

`--check`는 보고서를 덮어쓰지 않는다. 후속 DB 복구에서는 `--live --base-url=http://127.0.0.1:8080 --date=2026-10-03`으로 실제 로컬 서버의117개 매핑도 대조했다. `--base-url` 생략 시 기존 chat-local 18080 포트를 사용한다. 실제 MySQL·Redis 저장·권한·동시성 검사와 원본 DB 반영은 [복구 기록](../development/database-recovery-2026-10-03.md)에 분리했다. 런타임 매핑 일치를 모든 API 행동 검증 완료로 해석하지 않는다.
