# API 목록 누락 재점검

2026-09-27. 현재 서버 코드, 현재 목록·상세 계약·JSON, 채팅/Redis 전용 목록, 기존 목표 목록과 목표 OpenAPI를 메서드+경로 조합으로 대조한다. 결과 수치는 [기계 검증 결과](api-audit-2026-09-27.json)를 따른다.

## 반영 내용

| 구분 | 변경·대조 결과 |
|---|---|
| 현재 `/api` | 기존 89개에 채팅 15개를 반영하여 **104개** |
| 구현 상태 | 서비스 연결 **47**, 계약 stub **52**, 공용 메모리 시연 **5** |
| 채팅 | 대화방 조회·생성·상세, 참여자 검색, 메시지 조회·전송, 읽음, 방장 이전, 나가기, 입력 중, SSE, 멘션 조회·읽음, 태그 목록·메시지 총 **15개** |
| Redis | 연동 HTTP **8개**, 내부 명령 계약 **5개**. 별도 공개 Redis HTTP 서비스가 아님 |
| 목표 `/api/v1` | 확장 목표 **169개**, 기존 목표 **114개** 전부 보존. 현재 구현 104개와 합산하지 않음 |
| 링크 | 삭제된 `docs/9-API` 대신 실제 `docs/api-info`로 수정. DDL 관계도 링크도 현재 `.md` 파일로 수정 |
| 생성기 | 중첩 record 추출, RequestHeader 위치, ResponseEntity.noContent의 204, SSE 응답, RATE_LIMITED 429를 반영 |

현재 목록에서 빠졌던 15개 채팅 경로는 [자동 생성 전체 목록](current-api-inventory.md), [현재 상세 계약](../api-info/current-contract.md), [JSON 추출 결과](../api-info/current-operations.json)에 모두 반영했다. 채팅 요청/응답의 정확한 예시는 [전용 설계서](../chat/api/design.md)를 따른다. `CHAT_ENABLED=true`일 때 등록되는 조건도 명시했다.

목표 API는 구현 여부를 섞어 표시하지 않는다. 예를 들어 기존 목표의 `recordRef` 메시지, 친구 초대 수락, 차단 API는 현재 채팅에서 구현하지 않았으며 여전히 목표 계약이다. 브라우저의 로그인 전 샘플 화면은 HTTP API 추가나 서버 인증 면제를 의미하지 않는다.

## 다시 검사하기

```powershell
node frontend/scripts/api-inventory.mjs
node frontend/scripts/design-docs/build.mjs . --current-only
node frontend/scripts/api-inventory.mjs --check
node frontend/scripts/design-docs/build.mjs . --current-only --check
node frontend/scripts/design-docs/check.mjs .
node frontend/scripts/audit-api-docs.mjs --check
# chat-local 서버가 18080에서 실행 중일 때 실제 등록 경로까지 대조
node frontend/scripts/audit-api-docs.mjs --live
```

정적 대조는 동작 검증을 대신하지 않는다. 실제 채팅 권한·내구성·UI 검사는 [채팅 검증 기록](../chat/verification/README.md)에 분리했다. 과거 날짜의 검증 기록은 당시 89개 수치를 유지하며 이 문서가 최신 추가분이다.
