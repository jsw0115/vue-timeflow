## 공통 원칙

실제 파일·호출부·테스트·작업 트리를 읽고 요구 ID와 범위를 정합니다. 사용자 변경과 무관한 포맷을 수정하지 않습니다. 복잡한 작업은 계획·체크리스트·의사결정 기록을 남깁니다.

새 소스 첫 줄에는 역할을 설명하는 한국어 한 줄 주석을 둡니다. 필수 지시문·shebang이 있으면 바로 아래에 둡니다. 설정·잠금·생성 파일은 예외입니다. 사용자 안내·문서는 한국어를 기본으로 하며 코드 식별자·고유명은 유지합니다.

현재 JavaConventionTest는 일부 패키지의 첫 줄 package를 강제해 헤더 지침과 충돌합니다. 이번 작업에서는 Java 소스·테스트를 바꾸지 않았습니다. 신규 Java 작업 때 헤더 허용과 테스트를 함께 정리하도록 [IMP-003](../releases/backlog.md#imp-003)에 등록합니다.

| Java | 공백 4칸·명시 import·타입/파일/패키지 일치·후행 공백 제거 | 체크리스트·플래너 설정의 JavaConventionTest. 전역 Checkstyle 아님 |

| Python | UTF-8·명시적 경로·입력 검증·생성/검사 분리 | 도구의 --check와 구문·보호 장치 검증 |
| SQL | 증분 migration·키 타입·소유권·인덱스·기존 값 확인 | Flyway·기동·메타데이터 검사, V1 수정 금지 |
| 셸·배포 | 입력·종료 코드·백업 실패 처리·비밀값 출력 금지 | sh -n·Compose config와 별도 실제 배포 검수 |
| Markdown | 주제별 기준 원문·날짜·상태·목차·근거 | 링크·생성 결과·소스 계약 검사 |

Controller는 HTTP·DTO·현재 사용자, Service는 권한·규칙·트랜잭션, Repository/Store는 저장을 담당합니다. 새 API는 엔티티 임의 노출 대신 계약을 사용합니다. 한 번 쓰는 추상화나 요구하지 않은 설정 확장을 추가하지 않습니다.

## 보안·DB·API

- userId·ADMIN 여부·가격·유료 여부를 클라이언트 주장만으로 신뢰하지 않습니다.
- 비밀번호·토큰·결제 비밀·개인 원문을 로그·예외·문서·커밋에 넣지 않습니다.
- 일반 설정 JSON에 비밀값을 저장하지 않습니다.
- 새 필드는 DTO·FeatureType·검증·OpenAPI·테스트를 함께 갱신합니다.
- version 충돌의 409를 보존하고 저장 실패 때 사용자 입력을 유지합니다.
- 관계 변경은 짧은 트랜잭션·소유권·필요한 잠금·멱등키로 처리합니다.
- 외부 호출 중 트랜잭션을 붙잡지 않고 재시도·timeout·중복 효과·비용을 구분합니다.
- 파일·링크·다운로드는 소유권·공유·만료를 검사합니다.
- Flyway 이력 삭제·clean·볼륨 삭제·ddl-auto=update로 오류를 우회하지 않습니다.

필드·단위는 [용어 사전](glossary.md), 정확한 입력·오류는 [API 기준](../api/README.md)을 따릅니다.

## 검증과 리뷰

변경 위험을 검증하는 최소 관련 테스트부터 실행합니다. 실패하면 실제 로그·재현 조건을 확인하고 다시 실행합니다. API·DB·권한·동시성 변경은 통합·회귀 검증을 넓힙니다. 단순 문서 변경에 무관한 전체 테스트를 반복하지 않습니다.

리뷰에는 요구·이유·동작 차이·정확한 테스트 명령과 결과·DB/호환/운영 영향을 적습니다. 실제 실행과 미검증 범위를 [테스트 계획](../quality/test-plan.md)에 맞춰 기록합니다. 생성 문서의 변경은 생성기·원본에 반영합니다. Word는 Markdown 원문의 배포본입니다.

## 브랜치와 커밋

브랜치는 `feat/<topic>`, `fix/<topic>`, `docs/<topic>`, `chore/<topic>`처럼 목적을 드러냅니다. 현재 로컬 기본 브랜치는 master이며 원격 기본 브랜치는 실제 설정을 확인합니다. 강제 push·사용자 변경 덮어쓰기·무관한 파일 일괄 stage를 하지 않습니다.

권장 형식은 `<type>(<scope>): <한국어 변경 요약>`입니다. type은 feat·fix·docs·refactor·test·build·ci·chore를 사용합니다. 한 문장으로 설명되는 논리 변경 단위로 커밋하고 기존 이력을 강제 재작성하지 않습니다.

```text
feat(growth): 목표별 분석 동의 저장
fix(chat): 재전송 메시지 중복 저장 방지
docs(database): 현재 테이블 정의와 스키마 근거 갱신
```

대상 파일을 명시해 stage하고 `git diff --cached --check`와 목록을 확인합니다. 릴리스에는 버전·전체 SHA·검증·migration·실제 배포일을 연결합니다. 모든 과거 커밋이 이미 이 표준을 따랐다고 소개하지 않습니다.
