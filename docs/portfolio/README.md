## 프로젝트 소개

Timebar Diary는 계획과 실제 기록을 같은 시간축에서 비교하고, 일정·할 일·루틴·개인 기록·업무·경력을 연결하는 Vue·Spring 프로젝트입니다. 개인 기록을 단순히 쌓는 데서 더 나아가 실제 결과물을 문서와 다음 행동으로 연결하는 방향을 탐색합니다.

현재는 화면의 로컬 시연 저장과 구현된 서버 저장이 함께 있습니다. 인증·채팅의 실제 연동, 기능별 서버 계약·소유권·버전 처리를 구현했고, 다수 화면의 API 연결과 외부 AI·결제는 후속 범위입니다. UI 존재·백엔드 구현·통합 검증·운영 출시를 구분해 설명합니다.

## 코드 품질과 검증

소유권·계정 상태·역할 검사를 서버에 두고, 수정 version과 잠금으로 동시 변경을 다룹니다. 민감값 저장·로그 노출을 제한하고 안전한 migration·데이터 보존 경로를 마련했습니다. 채팅은 영속 메시지·멱등키·순번·outbox와 SSE 재연결을 구분합니다.

검증 근거는 [테스트 계획과 증거](../quality/test-plan.md), [2026-10-31 실제 실행 기록](../development/documentation-2026-10-31/verification.md), [이번 문서 검증](../development/documentation-system-2026-10-31/verification.md)에 있습니다. 기존 178개 Java·47개 웹 테스트, 실제 HTTP·브라우저·빈 DB 검증은 각 기록의 런타임·범위 안에서만 인용합니다. 모든 277개 API의 운영 E2E를 통과했다고 주장하지 않습니다.

현재 자동 품질 검사는 Node 테스트·Vite 빌드·Java/JUnit·일부 Java 명명/공백·API 계약·문서 생성 대조입니다. 전역 lint·TypeScript 엄격 검사·Testcontainers·부하·실제 네이티브 테스트를 이미 적용했다고 쓰지 않습니다. [코딩 표준·커밋 규칙](../standards/coding-standards.md)을 개발·리뷰 기준으로 사용합니다.

## 문제 해결과 설계 판단

- 과거 위험한 DDL 재실행 대신 기존 스키마 검사·baseline·증분 migration으로 데이터를 보존했습니다.
- 기존 UUID와 신규 ULID 계정·채팅 참조의 폭 차이를 다뤘습니다.
- JDT/Lombok 생성자 진단과 실제 소스·빌드 기준의 차이를 정리했습니다.
- 과거 목표 API 검사와 최신 구현 계약의 불일치를 CI 기준에서 수정했습니다.
- 실시간 전파와 영속 저장, 시연 UI와 실제 서버 기능, 공개 출처와 개인 자료 권한을 분리했습니다.

각 항목의 실제 날짜·수정 SHA·검증·한계는 [트러블슈팅 기록](../development/troubleshooting.md)에 연결합니다. 이 기록에서 확인하지 않은 성능 향상률·데이터 무손실 수치·가동률을 만들어내지 않습니다.
