# 글자 크기 및 위계 정리

## 변경 내용

- LNB 일반 메뉴/하단 메뉴14px, 그룹 제목12px. 아이콘용 `nav span`의16px가 메뉴 이름에 적용되던 상속 문제를 분리했습니다.
- 설명·메타12~13px, 본문/버튼14px, 읽기 본문15px, 카드 제목18px, 페이지 제목 PC40px/모바일28px. 수치는 기본 글자 크기 설정 기준입니다.
- 기존8~13px 선언을 용도별 범위12/13/14px로 정규화하고 CSS·Vue 인라인의 고정 px 글자 크기를 rem으로 이관했습니다. 숫자·아이콘의 기존 큰 크기는 유지했습니다.
- 행간1.5~1.7, LNB 최소 행 높이40px 및 긴 메뉴명 줄바꿈, 좁은 화면 상단 액션 줄바꿈을 적용했습니다.
- 설정의 작게/기본/크게는 이제 전체 화면 `zoom` 대신 rem 기준을 변경합니다. LNB 폭/뷰포트 높이를 확대하지 않으며 body로 Teleport된 작성 모달에도 적용됩니다. 기존 저장된 선택값은 유지합니다.
- 모바일 입력창에16px 이상 크기를 적용하고 낮은 가로 화면에서 LNB를 스크롤할 수 있도록 했습니다.

## 범위 및 디자인 계약

`frontend/src`의 공통 앱 화면·컴포넌트·관리자에 적용합니다. 독립 `mock-demo`, 개발 기기 프리뷰 도구, 인쇄용 내보내기 양식의 폰트는 이번 변경에 포함하지 않습니다. 색상/브랜드/기능/DB는 변경하지 않습니다.

DESIGN.md의 기존 폰트/모노톤/위계는 유지했습니다. 사용자 요청에 따라 일반 컨트롤13px→14px 및 행간1→1.5, 모바일 입력16px를 가독성 보정으로 적용했습니다. DESIGN.md와 hash-bound graph는 직접 변경하지 않았으며, 이 차이는 추후 정식 디자인 시스템 반영 시 검토할 항목입니다.

## 검증

프론트엔드 폴더에서:

```powershell
node --test tests/typography.test.mjs tests/device-preview.test.mjs tests/writing-flows.test.mjs
npm run build
```

타이포그래피 검사는 CSS 구문·크기 하한·스타일 순서·LNB 상속·rem 설정·반응형 규칙의 정적 회귀 검사입니다. 실제 브라우저 레이아웃 테스트와 다릅니다. 이번 세션에는 연결된 브라우저가 없어 실제 화면 캡처 및320px/PC/200% 확대 시각 검증은 수행하지 못했습니다.

실행 결과: 기존 작성·프리뷰와 신규 타이포그래피 검사18개 통과 후, 동적 태그/인라인 입력 추가 검사1개를 보완했습니다. 최종 타이포그래피 검사6개 및 프로덕션 빌드를 재실행합니다. 빌드에500kB 초과 청크 경고가 있으며 코드 분할은 이번 타이포그래피 작업 범위에 포함하지 않습니다.

수동 확인: `npm run dev:devices`로 PC/모바일 프리뷰를 열고 홈, LNB, 새 글 모달, 루틴, 일정, 설정을 확인하세요. 320/390/1440px와 글자 크기 크게, 브라우저200% 확대에서 메뉴·버튼 잘림/가로 넘침을 추가 확인합니다.
