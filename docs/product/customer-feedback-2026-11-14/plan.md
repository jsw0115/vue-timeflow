# 구매자 관점 의견 작성 계획

- 목적. Timebar Diary 구매자가 게시할 법한 한국어 익명 의견을 작성한다.
- 범위. 현재 화면과 구현 근거를 확인하고 불편, 변경 희망, 추가 기능, 외부 서비스, 스마트폰, IoT 연동 의견을 제시한다.
- 진행. 로컬 홈·플래너·설정 화면을 살펴보고 관련 소스와 README의 구현 범위를 대조한다.
- 검증. 실제 관찰과 희망 기능을 구분하고 기존 기능을 미구현으로 단정하지 않는다. 제품 코드 변경과 외부 게시를 수행하지 않는다.

## 의견 관리 문서 확장 계획

1. 이전 답변의 36개 의견을 원래 번호를 유지하는 CF-001~CF-036으로 등록한다.
2. 이 폴더를 단일 진입점으로 사용하고 bug·improvement·integration·feature-addition 하위 폴더에서 항목별 Markdown을 관리한다.
3. README.md에 전체 목록·우선순위·상태·분류 규칙을, implementation.md에 항목별 최소 구현 범위·구조·예외·검증 기준·의존성을 작성한다.
4. 현재 소스와 공식 제공자 문서를 확인하고 기존 구현·제안·검증 미실시를 구분한다.
5. 36개 의견의 누락·중복·문서 링크·앵커·공백을 검사한 뒤 이번 문서 변경만 커밋한다.

## 단일 Excel 관리대장 전환 계획. 2026-11-15

1. CF-001~CF-036의 원문·근거·구현 제안·선행 조건·검증 기준을 하나의 xlsx로 옮긴다.
2. 표지·버전관리 순서를 고정하고 현황·요구사항·상세요건·개발관리·작업기록·QC·변경이력·운영안내를 구성한다.
3. 관리 버전은 1.0으로 시작한다. 동일 경로의 파일을 향후 요청 때 수정하며 기존 Markdown은 초기 검토 스냅샷으로 둔다.
4. 미정인 공수·일정·완료 시각을 만들지 않고, 실제 공수는 작업기록에서 집계한다. 수행하지 않은 QC는 NOT_RUN으로 기록한다.
5. 수식 재계산·입력 변경·다음 요청 추가·파일 재열기·시트별 렌더링을 확인한 뒤 관리대장과 원본 위치 안내를 커밋한다.

## P0 구현 계획. 2026-11-15

1. CF-005. 기존 저장 구조를 사용해 서버 기준 기록 세션과 멱등 시작·종료, 화면 복구·상세 조회를 연결한다. 재시도·동시 요청·계정 격리와 실제 시간 집계를 검증한다.
2. CF-007. capabilities·sync/status를 조회해 확인되지 않은 연결·성공 표시를 없애고 오류·미지원·조회 중을 구분한다. OS 방해 금지와 시연 자료를 명시한다.
3. CF-008. 명시적 범위의 버전 있는 수동 백업과 첨부, 무결성 확인·병합 미리보기·멱등 복원을 제공한다. 타 계정 복원 시 소유권과 관계를 재매핑하고 기존 자료 덮어쓰기를 금지한다.
4. 관련 서버 통합·HTTP·클라이언트 회귀 테스트와 웹 빌드를 실행한다. 실행 범위와 남은 제한을 검증 기록에 남긴다.
5. 기존 Excel의 세 항목만 실제 증거에 맞춰 갱신하고 논리 단위로 커밋한다. 자동 백업·새 외부 제공자 연결·CF-006의 집중 모드 재설계는 이번 최소 범위에 포함하지 않는다.
