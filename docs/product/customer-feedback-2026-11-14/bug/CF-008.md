## 익명 구매자 의견 원문

> 백업은 복원까지 믿을 수 있어야 해요. 백업 메뉴에서 실제 파일을 받고, 복원할 기록을 미리 확인하고 싶어요. 마지막 성공 시각과 실패 이유도 알려주세요.

## 현재 근거와 분류 이유

SettingsDataView.vue의 백업·내보내기·가져오기는 실행 핸들러가 없는 span이다. 기존 서버 /api/user/data/export는 profile과 FeatureType 자료를 반환하지만 플래너·작업·첨부 등 전체 계정 백업을 보장하지 않는다.

- [backend/src/main/java/kr/timebar/diary/contract/UserProfileController.java](../../../../backend/src/main/java/kr/timebar/diary/contract/UserProfileController.java)

## 원하는 결과와 최소 범위

범위가 명시된 수동 내보내기와 미리보기 기반 병합 복원을 먼저 제공한다. 자동 백업은 실제 예약 실행과 복원 검증 후 제공한다.

## 완료 판단 기준

- [ ] 서로 다른 기록과 첨부를 내보내 새 테스트 계정에 복원한 뒤 수·관계·내용을 대조한다.
- [ ] 손상 파일·미지원 버전·중복 ID·중단 후 재시도가 기존 자료를 조용히 덮어쓰지 않는다.
- [ ] 실제 변경·검증 명령·결과·남은 제한을 아래 이력에 남기고 상태를 변경한다.

## 관리 이력

- 2026-11-14. 원문 8번을 등록하고 현재 근거·최소 범위·검증 기준을 제안했다. 제품 구현과 기능 승인은 아직 수행하지 않았다.
- 2026-11-15. 최소 범위 구현·로컬 검증을 수행했다. [구현·검증 기록](../p0-implementation-2026-11-15.md)을 추가했다. 이 문서의 초기 상태·체크리스트는 스냅샷이며 최신 상태·QC·시간은 기존 Excel에서 관리한다.
