# Timebar Diary 구매자 의견과 기능 관리

최초 작성일 2026-11-14. 관리 방식 갱신일 2026-11-15. 원문 출처는 이 프로젝트 대화에서 작성한 가상의 익명 구매자 의견 36개다. 실제 고객 인터뷰나 브라우저 사용 실험 결과로 해석하지 않는다.

**현재 관리 원본은 [단일 Excel 통합관리대장](../../../outputs/timebar-diary-management-20261115/Timebar_Diary_Management.xlsx)이다.** 관리 버전 1.0으로 시작하며, 이후 요청도 이 파일을 가져와 수정한다. 파일명을 바꾸거나 요청마다 별도 Excel을 만들지 않는다.

Excel에는 표지·버전관리·현황·요구사항·상세요건·개발관리·작업기록·QC관리·변경이력·기술기준·운영안내의 11개 시트가 있다. 기존 36개 의견과 구현 제안, 72개 완료 기준을 이관했다. 예상·실제 공수, 예정·실제 시작과 종료, 최종 완료 시각, 담당자, 버전, QC 증거와 변경 이력도 같은 파일에서 관리한다.

이 폴더의 항목별 Markdown·분류 목록·아래 원문 모음은 **2026-11-14 초기 검토 보존본**이다. 아래 상태와 완료 체크박스도 당시 상태이며 이후 실시간 상태는 Excel을 따른다. 초기 이관 시 모두 검토 대기이고 QC는 NOT_RUN이다. Excel 생성은 제품 기능 개발 완료를 의미하지 않는다.

4. [참고 자료와 조사 한계](sources.md) 및 [작업 맥락](context-notes.md)을 확인한다.
5. CF-005·007·008의 변경 내용은 [2026-11-15 구현·검증 기록](p0-implementation-2026-11-15.md)에서 확인한다. 최신 관리 상태는 같은 Excel을 따른다.

## 우선순위와 상태 관리

다음 원칙은 Excel의 요구사항·상세요건·변경이력·QC관리 시트에 적용한다. 기존 Markdown은 원문과 근거를 보존하며 진행 상태를 병행 갱신하지 않는다.

- P0. 기록 유실과 잘못된 성공 표시처럼 기본 신뢰에 직접 영향을 주는 선행 작업. 실제 운영 장애 등급을 의미하지 않는다.
- P1. 매일 사용하는 기록·연결·접근권·데이터 이동의 핵심 조건.
- P2. 사용성 확대와 서비스·스마트폰 확장.
- P3. 핵심 기록 흐름 이후 검증할 IoT 확장.

우선순위는 제안이며 납기·예산·출시 약속이 아니다. 원문의 구매 우선순위는 **기록 보존과 기기 동기화 → 빠른 입력 → 실제 캘린더 연동 → 믿을 수 있는 분석 → IoT 확장**이다.

상태는 `검토 대기 → 조사 중 → 구현 준비 → 개발 중 → 검증 중 → 완료`로 관리한다. `보류`·`미채택`으로 바꿀 때는 이유와 재검토 조건을 남긴다. 담당자·채택 여부·일정은 아직 정하지 않았다. Excel의 목표 제품 버전 1.0은 후보 범위이며 출시 약속이 아니다.

- Excel의 요구사항 표가 현재 상태·담당자·분류의 기준이며 상세요건·QC관리 표에서 상세 근거와 완료 기준을 관리한다.
- 분류 변경 시 ID를 유지하고 Excel의 변경이력에 이유를 남긴다.
- 댓글 추가는 Excel의 상세요건·변경이력에 날짜·출처·요청 변화·결정 이유를 덧붙인다. 원문은 변경하지 않고 수정 요청을 새 이력으로 남긴다.
- 새 의견은 CF-037부터 부여한다. 기존 항목과 같으면 새 번호를 발급하지 않고 관련 의견으로 기록한다.
- 완료로 바꿀 때 변경 커밋/PR, 실행한 검증 명령과 결과, 실제 기기·제공자 환경, 남은 제한을 기록한다. 문서 작성 완료와 기능 개발 완료를 구분한다.
- checklist.md는 문서·관리대장 작성 작업용이다. 제품 기능의 실제 완료 상태와 검증 결과는 Excel에서 관리한다.
- 향후 갱신은 기존 Excel의 사용자 입력과 이력을 먼저 읽은 뒤 필요한 행·셀만 수정한다. 초기 Markdown에서 다시 생성하지 않는다. 새 행의 수식 복사·입력 선택지·버전 갱신 절차는 Excel의 운영안내를 따른다.
- 공식 API 계약은 [프로젝트 API 문서](../../api/README.md)를 기준으로 갱신한다. 이 폴더의 제안 필드를 이미 지원하는 API처럼 사용하지 않는다.

## 구매자 의견 원문 모음

**[익명] Timebar Diary, 이런 부분이 좋아지면 계속 돈 내고 쓰고 싶어요.**

계획과 실제로 보낸 시간을 나란히 볼 수 있다는 방향이 마음에 듭니다. 일정, 할 일, 일기, 업무 기록까지 연결하면 하루를 여러 앱에 나눠 적는 수고가 줄어들 것 같아요. 구매자 입장에서 바라는 점을 적어봅니다.

### 1. 목적별 시작 구성과 즐겨찾기

> 메뉴가 많아서 시작이 부담스러워요. 메뉴 접기와 홈 위젯 편집은 좋지만, 처음부터 ‘학생용’, ‘직장인용’, ‘개인 기록용’을 골라 필요한 메뉴만 보고 싶어요. 자주 쓰는 메뉴를 고정하는 기능도요.

[CF-001 관리하기](improvement/CF-001.md) · [구현 제안](implementation.md#cf-001)

### 2. 이해하기 쉬운 모드 이름과 요일별 전환

> J형·P형보다 사용 방식이 먼저 보이면 좋겠어요. ‘계획 중심’, ‘자유 기록’, ‘균형’처럼 설명하면 이해하기 쉬울 것 같아요. 평일에는 계획형, 주말에는 자유형으로 자동 전환하고 싶습니다.

[CF-002 관리하기](improvement/CF-002.md) · [구현 제안](implementation.md#cf-002)

### 3. 한국어 용어와 업무 기능 설명

> 용어가 더 쉬웠으면 해요. Actual·Plan은 ‘실제·계획’으로 보여주고, WBS나 공수 계산 같은 기능에는 짧은 설명이 있으면 좋겠어요.

[CF-003 관리하기](improvement/CF-003.md) · [구현 제안](implementation.md#cf-003)

### 4. 24시간 타임라인과 하루 경계 설정

> 새벽에도 하루는 계속돼요. 아침부터 밤까지의 시간표뿐 아니라 24시간을 보고 싶어요. 야간 근무자는 새벽 4시를 하루의 끝으로 정할 수도 있으면 좋겠습니다.

[CF-004 관리하기](improvement/CF-004.md) · [구현 제안](implementation.md#cf-004)

### 5. 실제 기록 저장과 화면 이동 후 복구

> 기록 버튼을 누른 시간이 확실하게 남았으면 해요. 종료하면 어떤 활동으로 저장됐는지 바로 보여주세요. 화면 이동이나 새로고침 때문에 기록이 끊길까 걱정하고 싶지 않아요.

[CF-005 관리하기](bug/CF-005.md) · [구현 제안](implementation.md#cf-005)

> ‘자유 타이머’는 정말 자유로웠으면 해요. 현재 구성의 50분 고정 대신 시간을 직접 정하거나 스톱워치처럼 쓰고 싶어요. 중간에 끝낸 13분도 기록할 수 있고요.

### 9. 할 일·일정·실제 기록의 연결

> 같은 일을 여러 곳에서 다시 입력하고 싶지 않아요. 할 일을 일정에 배치하고, 집중 시간을 연결하고, 일기에서 돌아볼 때 하나의 기록으로 이어졌으면 합니다. 어디에서 수정해도 일관되게 반영되고요.

[CF-009 관리하기](improvement/CF-009.md) · [구현 제안](implementation.md#cf-009)

### 10. 자연어 빠른 입력과 사후 분류

> 떠오른 생각부터 빨리 적고 싶어요. “내일 오후 3시 치과”라고 입력하면 날짜와 시간을 잡아주고, 종류는 나중에 바꿀 수 있으면 좋겠어요. 처음부터 모든 항목을 채우기는 귀찮아요.

### 11. 계획 지연 시 재배치 제안

> 계획이 밀렸을 때 다시 짜는 일을 도와주세요. 회의가 30분 길어지면 뒤의 할 일을 옮기는 안을 제안해주세요. 고정 약속은 유지하고, 바뀌는 내용을 확인한 뒤 적용하고 싶어요.

> 루틴에도 예외가 필요해요. 휴가, 아픈 날, 교대근무, 공휴일을 반영하고 싶어요. 하루 쉬었다고 연속 기록이 무너지는 방식은 부담스럽습니다.

[CF-012 관리하기](improvement/CF-012.md) · [구현 제안](implementation.md#cf-012)

### 13. 비계획 활동 인정과 점수 숨김

[CF-013 관리하기](improvement/CF-013.md) · [구현 제안](implementation.md#cf-013)

### 14. 근거를 확인할 수 있는 통계와 AI

> 통계와 AI가 제 기록을 근거로 설명했으면 해요. “오전에 집중이 잘돼요”라고 하면 어떤 기록을 보고 판단했는지 눌러서 확인하고 싶어요. 기록이 부족하면 부족하다고 알려주고, 일정 변경은 제가 승인했을 때만 해주세요.
