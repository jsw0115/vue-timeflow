# 검토 맥락

- 요청은 구현 작업이 아닌 구매자 역할의 의견 작성이다. 영어 요청에도 한국어로 답한다.
- README는 다수 화면이 로컬 시연 저장을 사용하며 AI·음성·실결제·외부 캘린더 제공자 실행이 미연결이라고 명시한다. 메뉴 존재와 서비스 연결 완료를 구분한다.
- 사용자 변경이 있는 PlannerItemQueryRepositoryImpl.java, Modal.vue와 .claude/settings.local.json은 수정하거나 커밋하지 않는다.
- 브라우저 전용 연결은 사용할 수 없어 기존 Chrome 창을 통한 로컬 화면 탐색을 시도한다.
- 외부 연동은 구매자의 희망 시나리오로 작성하며 실제 지원·호환성·제공 시기를 보증하지 않는다.

## 확인 근거

- `frontend/src/router/index.js`와 `App.vue`에 플래너, 기록, 인사이트, 업무, 소셜의 많은 메뉴가 있다. 메뉴 그룹 접기는 이미 있으므로 즐겨찾기와 목적별 시작 구성을 개선안으로 제시한다.
- `HomeView.vue`와 `SettingsWidgetsView.vue`에 위젯 숨김·크기·배치 편집이 있다. 위젯 자체를 신규 기능으로 제안하지 않고 역할별 구성과 스마트폰 홈 위젯을 구분한다.
- `PlannerDailyView.vue`의 표시 시간 눈금은 08시~22시다. 기록 시작·종료 함수는 경과 시간을 변경하지만 실제 기록 저장을 호출하지 않는다. 날짜 변경·야간 기록·기기 전환을 견디는 기록 흐름을 구매 요구로 제시한다.
- `FocusView.vue`의 자유 타이머는 50분 고정이며 세션 목록은 컴포넌트 내부 상태다. 시간 직접 설정·스톱워치·세션 보존을 희망한다.
- `SettingsIntegrationsView.vue`의 연동 상태는 정적 표시이며 `SyncStatusView.vue`의 동기화는 로컬 상태와 타이머를 바꾼다. 외부 캘린더 연결 검증을 수행한 것으로 표현하지 않는다.
- `SettingsDataView.vue`에 백업·내보내기·가져오기 문구가 있으나 해당 실행 핸들러는 없다. 기존 메뉴의 실제 백업·복원 완료를 요청한다.
- `AiInsightView.vue`의 리포트는 모드별 미리 정의한 문구를 사용한다. 개인 기록 근거와 사용자 승인 후 일정 반영을 희망한다.
- 템플릿, 메모 변환, 통합 검색, 공유 범위, 내보내기 관련 기능은 이미 존재한다. 기능이 전혀 없다고 단정하지 않고 편의·연결·실효성 향상으로 작성한다.

## 검증 범위와 한계

- `npm.cmd run dev` 실행 결과 Vite 준비 완료를 확인했다.
- `Invoke-WebRequest -UseBasicParsing -Uri 'http://127.0.0.1:5173/' -TimeoutSec 10` 결과 HTTP 200과 앱 루트 요소를 확인했다. 이는 브라우저 렌더링이나 사용자 흐름 성공을 뜻하지 않는다.
- Chrome 제어 호출은 `Computer Use was not approved to use Google Chrome`로 거부됐다. 화면 직접 조작·휴대전화 실기기·외부 서비스·IoT 연결은 검증하지 않았다.
- 제품 코드는 변경하지 않았으며 테스트·빌드 검증은 실행하지 않았다. 전체 `git diff --check`는 기존 사용자 변경인 `Modal.vue` 51·53행의 줄 끝 공백을 보고했다. 해당 파일은 수정하지 않는다. 검토 문서만 스테이징한 뒤 별도로 공백 검사를 수행한다.
- 검토용 Vite 서버를 종료했다. 종료 시 기존 `AdminModerationView.vue`의 table 바로 아래 tr 사용에 관한 Vue 경고가 출력됐다. 이번 의견 작성 범위에서 수정하지 않았다.
- 최종 의견은 메뉴 단순화, 입력·시간 기록, 계획 조정, 통계·AI, 데이터 신뢰, 외부 서비스, 스마트폰·워치, IoT, 구매 조건을 포함한다.
- `git diff --cached --check -- docs/product/customer-feedback-2026-11-14` 검사는 통과했고 스테이징 대상은 이번 검토 문서 세 개뿐임을 확인했다.

## 의견 관리 문서 확장 결정

- 사용자 후속 요청에 따라 이 폴더에 전체 의견 목록, 분류별 상세 항목, 별도 구현 제안서를 추가한다. 제품 구현은 이번 요청 범위가 아니다.
- 원문 번호를 CF-001~CF-036으로 고정하고 항목당 하나의 주 분류만 둔다. 스마트폰·IoT 등은 태그로 구분해 동일 의견을 중복 등록하지 않는다.
- 코드를 읽어 확인한 동작 결손만 버그로 분류한다. 실행 재현을 했다고 주장하지 않으며 기존 기능의 확장과 새로운 기능을 구분한다.
- 우선순위와 구현 순서는 제안이다. 문서가 생성됐다고 기능이 개발 완료된 것으로 처리하지 않는다.

### 작성 결과와 설계 근거

- CF-001~CF-036의 구매자 의견을 README 원문 모음과 항목별 파일에 보존했다. bug 4개·improvement 12개·integration 12개·feature-addition 8개로 분류했다.
- 각 항목에는 담당자·상태·태그·우선순위 제안·선행 항목·현재 소스·최소 범위·미완료 상태의 검증 체크박스를 넣었다. 상태는 모두 검토 대기다.
- implementation.md에 기존 Vue·Spring 저장 경계, 제안 데이터, 단계별 순서, 36개 구현안, 실패·충돌·플랫폼 제약, 실제 구현 시 검증·마이그레이션 조건을 작성했다.
- 기존 집중 세션 API와 엄격한 FeatureType/FeatureInput 허용 필드를 확인했다. 신규 세션 상태·일시정지·멱등 필드가 현재 지원된다고 표현하지 않았다.
- 기존 export가 전체 계정 백업을 보장하지 않는 점을 SettingsService에서 확인했고, 수신자 권한 미리보기와 기존 SNS 이미지 프리뷰를 구분했다.
- 공식 Google·Microsoft·Apple·Android·Capacitor·SmartThings·Home Assistant 문서를 조회해 sources.md에 적용 범위와 미확인 제공자·기기 조건을 남겼다. 실제 외부 계정·기기 연결은 수행하지 않았다.
- DESIGN.md 전체와 preferences를 읽었다. 두 프로젝트의 시각 규칙이 혼재하며 manifest 대비 graph·coverage·provenance 해시는 일치하지만 DESIGN.md는 불일치한다. preferences의 확인된 로그는 ambient/inferred다. 이번 문서에서는 시각값을 채택하거나 파일을 수정하지 않고 실제 UI 구현 전 정합성 확인 대상으로 기록했다.
- 기존 사용자 변경 세 파일은 이번 변경과 분리한다. 앞선 HTTP 확인·브라우저 접근 제한은 이전 검토 기록으로 유지하고 이번 기능 검증으로 재사용하지 않는다.
