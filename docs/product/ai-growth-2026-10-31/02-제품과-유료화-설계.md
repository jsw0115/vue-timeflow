## 제품이 제공할 약속

사용자가 선택한 분야의 변화를 근거와 함께 설명하고, 기존 경험이나 연구 자료에서 활용할 내용을 찾아주며, 이번 주에 할 수 있는 행동과 문서 수정으로 연결합니다. 사용자가 목표를 달성했는지 평가할 때도 AI의 인상평보다 실제 결과물과 사용자의 확인을 우선합니다.

핵심 단위는 대화방이 아니라 **목표 한 개와 그 목표에 연결된 근거·문서·행동**입니다. 대화는 자료를 확인하거나 제안을 다듬는 보조 수단으로 둡니다. 채팅 기록 속에 중요한 결정을 묻어두지 않습니다.

하나의 계정은 여러 목표를 가질 수 있습니다. 예를 들어 취업 준비와 석사 연구를 병행하더라도 사용 자료, 분석 방식, 일정과 공유 상대를 목표별로 관리합니다. 회원 가입 때 사용자를 평생 하나의 직업 유형에 묶지 않습니다.

### 사용자가 얻게 되는 결과

| 결과 | 반드시 함께 보여줄 내용 |
| --- | --- |
| 분야 변화 요약 | 출처, 발행·수집 날짜, 국가·지역, 분석 기간과 표본의 한계 |
| 나와의 연결 | 사용자가 선택한 경험이나 연구 근거, 관련성이 있다고 판단한 이유 |
| 보완할 내용 | 확인된 경험 부족과 단순한 자료 미등록을 구분한 설명 |
| 작성 제안 | 기존 문장과 수정안의 차이, 주장에 연결된 경험·문헌 |
| 실행 제안 | 목적, 예상 시간, 결과물, 완료 기준과 사용자가 선택할 일정 |
| 다음 검토 | 지난 제안의 실행 결과와 새로 바뀐 근거만 비교한 요약 |

적성 점수, 합격 확률, 취업 보장, 연구 주제의 독창성 보장은 제공 약속에 넣지 않습니다. 사용자의 실제 경력·성과·실험 결과를 만들어내지 않으며, 기록하지 않은 활동을 하지 않았다고 단정하지 않습니다.

## 기존 앱에 연결하는 화면 구조

새 서비스 전체를 별도 메뉴로 복제하기보다 기존 `/insight`를 목표별 성장 가이드의 진입점으로 발전시킵니다. 아래 주소는 제안이며 실제 라우트 추가를 의미하지 않습니다.

| 기존 위치 | 제안할 경험 | 기존 기능과 연결 |
| --- | --- | --- |
| 홈 | 활성 목표, 이번 주 선택한 행동 한 개와 다음 검토일 | 계획과 실제 기록으로 이동 |
| `/insight` | 목표 목록과 최신 변화 요약 | 취업·연구·직무 성장·독립 활동 중 필요한 흐름 선택 |
| `/insight/goals/:goalId` | 변화, 내 근거, 작성 제안, 실행, 검토의 순서 | 같은 목표의 자료와 결과를 연속해서 확인 |
| 경력·이력서·포트폴리오 | 문장 옆의 근거와 수정 전후 비교 | 사용자가 승인한 문장만 새 버전으로 저장 |
| 업무 위키·WBS | 경험, 연구 메모, 프로젝트 결과를 근거로 선택 | 모든 내용을 자동으로 AI에 보내지 않음 |
| 할 일·플래너 | 승인한 행동과 사용자가 정한 시간 | 원래의 계획·실제 기록 흐름 유지 |
| 설정 | 사용 자료, AI 동의, 보관·삭제, 이용권과 사용량 | 서버가 확인한 실제 이용 가능 상태 표시 |

화면 상단에는 목표와 이번에 분석하는 범위를 먼저 보여줍니다. 넓은 화면에서는 본문 옆에 근거 패널을 두고, 모바일에서는 근거를 접어 펼칠 수 있게 합니다. 내용이 많은 보고서는 제목과 한 문장 요약부터 읽게 하고, 표본과 방법은 바로 확인할 수 있게 둡니다.

기존 `DESIGN.md`의 무채색 기반, 단일 녹색 강조, 검정 주요 버튼을 따릅니다. 시장 변화의 상승·하락을 색만으로 구분하지 않으며, 320px 화면·키보드 조작·명확한 포커스·스크린리더 제목 순서를 확인합니다. 사용자를 압박하는 붉은 위험 점수나 끊임없이 뜨는 결제 배너는 도입하지 않습니다.

### 분석 결과 화면의 읽는 순서

```text
목표. 데이터 분야로 직무 전환 준비
분석 범위. 선택한 공고 / 지역 / 경력 / 비교 기간

1. 이번에 확인할 변화 최대 3개
   변화의 의미 → 출처와 표본 → 이전 분석과의 차이
2. 내 자료와 연결되는 경험
   확인된 근거 → 아직 확인이 필요한 내용
3. 문서에서 바꿔볼 부분
   수정 전후 → 문장별 근거 → 수정 / 적용 / 보류
4. 이번 주 할 일
   예상 시간과 결과물 → 일정 선택 → 계획에 추가
```

## 처음 사용하는 경험과 주간 흐름

### 처음 사용하는 3단계

1. **목표를 고릅니다.** 목표 직무나 연구 질문, 원하는 결과물과 검토 시점을 입력합니다. 주당 가능 시간·지역·경력 조건은 선택 사항으로 두고 나중에 바꿀 수 있게 합니다.
2. **분석에 쓸 자료를 고릅니다.** 경력 기록, 직접 작성한 글, 관심 공고나 DOI 중 필요한 것만 선택합니다. 업로드 없이 공개 예시를 먼저 볼 수 있습니다. 이름·회사명 등 가림 결과와 외부 모델에 전달할 범위를 확인합니다.
3. **첫 결과를 확인합니다.** 사용 자료와 예상 이용량을 확인한 뒤 분석을 시작합니다. 결과에서 문장 하나 또는 행동 하나를 선택하면 첫 사용이 끝납니다. 긴 프로필 작성은 선행 조건으로 만들지 않습니다.

경험이 없는 취업 준비생에게는 빈 이력서를 계속 업로드하게 하지 않습니다. 관심 공고에서 확인할 과제와 작은 결과물을 만들도록 돕습니다. 연구자에게는 경력 입력 대신 연구 질문과 선택한 문헌을 먼저 받습니다.

### 일주일의 흐름

| 시점 | 사용자 행동 | 앱의 지원 |
| --- | --- | --- |
| 첫 검토 | 바뀐 근거와 기존 결과의 차이를 확인 | 새 자료와 수정·철회된 자료만 우선 표시 |
| 계획 | 제안 중 할 수 있는 것만 선택 | 가능 시간을 넘으면 범위 축소를 제안 |
| 실행 | 기존 플래너와 업무 화면에서 작업 | 중복 할 일 생성 없이 원래 작업으로 이동 |
| 결과 기록 | 링크·파일·메모로 결과를 남김 | 경력 근거나 연구 기록으로 재사용할지 질문 |
| 다음 검토 | 문서에 반영할 내용을 승인 | 이전 버전을 보존하고 변경 이력 표시 |

주간 알림과 자동 재분석은 기본 비활성인 선택 기능입니다. 활성화할 때 실행 주기·회당 최대 사용 단위·월 상한을 확인받고 매 실행 전에 남은 범위를 서버에서 검사합니다. 잔량이 부족하면 건너뛰며 별도 동의 없이 추가 결제하지 않습니다. 새 자료가 없으면 “새로 확인된 변화가 없습니다.”라고 표시합니다. 같은 내용을 새 보고서처럼 반복 생성하거나, 사용자가 접속하지 않은 기간을 의지 부족으로 표현하지 않습니다.

### 오류와 불확실성을 보여주는 방법

| 상태 | 사용자에게 보여줄 내용과 다음 행동 |
| --- | --- |
| 대기·처리 중 | 실제 단계와 취소 버튼. 측정 근거가 없는 진행률은 표시하지 않음 |
| 자료 부족 | 부족한 범위와 추가할 수 있는 자료. 근거 없는 시장 결론은 만들지 않음 |
| 일부 출처 접근 불가 | 확인된 부분과 제외된 부분. 원문을 읽지 못했으면 메타데이터만 확인했다고 표시 |
| 자료가 오래됨 | 마지막 확인일과 갱신 방법. 과거 분석도 분석 당시의 날짜를 유지 |
| 분석 실패 | 저장된 입력 유지, 사용량 복원 여부와 재시도 방법 |
| 한도 도달 | 남은 사용량과 다음 갱신일. 기존 기록과 결과 열람·내보내기는 계속 제공 |
| 취소·동의 철회 | 진행 상태와 삭제 처리 결과. 취소 이후 결과를 자동 적용하지 않음 |

## 취업과 연구 분석을 구분하는 방법

두 흐름은 목표·근거·승인·계획이라는 기반을 공유하지만, “트렌드”를 판단하는 방법은 다르게 구현합니다.

### 취업·직무 성장 분석

관심 직무, 지역, 경력 수준, 고용 형태와 기간을 같은 조건으로 맞춘 공고를 비교합니다. 중복 게시, 채용 대행 재게시와 같은 공고 갱신을 가능한 범위에서 제거합니다. 공고에 적힌 기술을 역량 전체로 간주하지 않고 실제 업무·책임·검증 방식도 추출합니다.

자료가 허용한다면 최근 28일과 이전 28일의 공고 비중을 비교하되, 각 기간의 표본 수와 수집 범위가 같은지 먼저 확인합니다. 표본 조건이 다르면 증감률 대신 관찰된 사례만 보여줍니다. 공고에 없는 연봉을 AI가 채우지 않으며, 공고 수를 실제 신규 채용 인원으로 바꾸지 않습니다.

고용24 API는 기업회원, 신청 심사와 인증키가 필요한 서비스입니다. 데이터별 상업적 이용·보관·재배포·AI 처리 허용 범위를 확인한 뒤 사용합니다. 승인 전에는 사용자가 제공한 공고와 허용된 공개 자료로 제한된 비교 기능을 검증할 수 있습니다. 공고 세 개를 입력받아 “한국 취업시장 전체”의 통계로 설명해서는 안 됩니다. [S10](sources.md#s10).

### 연구 분석

연구 질문별로 문헌의 문제, 방법, 데이터, 결과, 한계와 재현 가능성을 비교합니다. DOI와 버전을 정규화하고 사전 공개 논문과 동료 심사를 거친 논문을 구분합니다. 발표량이나 인용 수는 관심도의 한 지표이며, 연구의 타당성이나 새로운 주제의 성공 가능성과 같은 뜻으로 쓰지 않습니다.

제안 결과는 문헌 비교표, 아직 검증하지 못한 질문, 재현 과제, 실험 계획과 원고 구조입니다. “선행 연구가 없다.”라는 단정 대신 검색한 데이터베이스·검색식·기간 안에서 확인하지 못한 범위를 표시합니다. 전문을 읽지 못한 논문은 초록·메타데이터 분석으로 명시하고 방법이나 결과를 추측해서 채우지 않습니다.

Crossref의 서지 메타데이터 접근은 논문 전문이나 모든 초록의 재배포 권한을 뜻하지 않습니다. OpenAlex도 현재 인증·이용량·비용 조건을 확인해야 합니다. 문헌 전문은 이용권이 확인된 자료나 사용자가 처리 권한을 가진 자료만 다룹니다. [S12](sources.md#s12), [S13](sources.md#s13).

| 단계 | 기능 | 완료 기준 |
| --- | --- | --- |
| 선행 기반 | 계정별 경력·문서·계획 저장 | 재로그인·다른 기기에서도 같은 자료가 보이고 다른 계정에는 노출되지 않음 |
| 선행 기반 | 목표별 자료 선택과 동의 | 기본 비공개, 선택한 범위만 분석, 철회·삭제가 실제 작업에도 반영됨 |

| 첫 제품 | 근거가 있는 변화 요약 | 핵심 주장에 유효한 출처와 분석 범위가 연결됨 |
| 첫 제품 | 경험·문헌 근거 보관함 | 경험·결과물·주장·원문 근거를 연결하고 사용자가 수정·확인 가능 |
| 첫 제품 | 문서 수정안과 버전 비교 | 확인된 사실만 사용하고 승인 후 새 버전 저장, 되돌리기 가능 |
| 첫 제품 | 실행 제안과 계획 반영 | 한 번 승인하면 한 번만 생성, 계획을 바꾸기 전에 사용자가 검토 |
| 첫 제품 | 실행 후 검토 | 완료한 결과물과 다음 문서 변경을 연결 |
| 유료 베타 전 | 실제 이용권과 결제 연동 | 검증한 결제 이벤트로 권한 부여, 만료·해지·환불 처리 일치 |
| 이후 확장 | 연구 문헌 수집과 재현 기록 | 별도 분야 검토자의 평가와 이용권 검증 통과 |
| 이후 확장 | 코치 검토와 기관 이용 | 공유한 목표·결과물에만 접근, 공유 철회 가능 |
| 이후 확장 | 음성 메모·캘린더 연동 | 실제 제공자 연결과 별도 동의, 중복 생성·삭제 대응 |

경험 근거에는 작성자, 활동 기간, 맡은 역할, 사용 기술, 실제 결과와 연결 자료를 보관합니다. AI가 추출한 항목은 사용자 확인 전까지 추정 상태로 둡니다. 같은 결과물이 이력서, 포트폴리오, 분기 성과 정리에 활용되어도 원래 근거와 수정 이력을 추적할 수 있게 합니다.

처음부터 자동 지원, 자동 논문 제출, 무제한 웹 수집, 자체 대형 모델, 기관용 인사 평가를 함께 만들지 않습니다. 사용자가 승인하지 않은 외부 발송과 사실을 부풀린 문장 생성은 제품 범위에 넣지 않습니다.

## 구체적인 사용 예시

아래는 기능 설명용 가상 사례이며 실제 사용자 결과나 검증된 노동시장 통계가 아닙니다.

### 직무 전환 준비자

사용자가 “4주 안에 데이터 직무 지원용 프로젝트 설명을 정리하고 싶고 주 6시간을 쓸 수 있다.”라고 입력합니다. 관심 공고 세 개와 기존 API 프로젝트 기록을 선택합니다.

앱은 이를 **선택한 공고 비교**로 설명하고, 공고에 공통으로 적힌 데이터 품질 검증 업무와 기존 프로젝트의 오류 처리 기록을 연결합니다. 원래 기록에 처리량이나 개선율이 없다면 “처리 속도 40% 개선”을 만들어내지 않습니다. 어떤 결과를 측정했는지 먼저 확인하도록 제안합니다.

사용자는 데이터 검증 과제 3시간, 결과 정리 2시간, 지원 문서 검토 1시간 중 가능한 항목을 선택합니다. 일정은 사용자가 정하고, 결과 링크를 남기면 확인한 사실만 프로젝트 설명의 새 버전에 반영합니다.

### 대학원 연구자

사용자가 연구 질문과 문헌 DOI 열 개를 입력합니다. 앱은 확인 가능한 메타데이터·초록·허용된 전문을 구분해 문헌 비교표를 만듭니다. 공통 방법의 한계에서 후속 질문 두 개를 제안하되 새로움은 검증되지 않았다고 표시합니다.

사용자가 질문 하나를 고르면 데이터 접근 확인, 재현 환경 구성, 작은 실험과 지도교수 검토를 계획으로 나눕니다. 실제 결과와 실패 조건을 연구 메모에 남긴 뒤 원고 구조와 다음 실험을 수정합니다. 선택한 문헌만 공유해 검토받을 수 있습니다.

### 프리랜서·재직자·현장 종사자

프리랜서는 고객 분야의 변화와 납품 결과를 연결해 제안서와 포트폴리오를 갱신합니다. 재직자는 비공개 업무 기록 중 허용된 부분만 가려서 분기 성과와 다음 학습 과제를 정리합니다. 현장 종사자는 짧은 메모, 교육 일정과 자격 유지 기록을 경력 근거로 묶습니다. 고객 기밀이나 다른 사람의 개인정보를 입력해야만 서비스를 쓸 수 있는 구조로 만들지 않습니다.

## 무료와 유료의 경계

| 구분 | 제공 가치 | 설계 원칙 |
| --- | --- | --- |
| 무료 | 기본 계획·실제 기록, 경력과 결과물 저장, 직접 작성, 기본 문서 이력 조회·복원, 기존 결과 열람·내보내기 | 핵심 기록을 결제로 잠그지 않음 |
| 무료 체험 | 범위를 제한한 개인 분석과 실행 연결 체험 | 횟수·범위와 종료 조건을 시작 전에 표시 |
| 개인 유료 | 개인 근거 비교, 문서별 작성 제안, 정기 변화 검토와 실행 후 갱신 | 분석량과 자료량 한도, 사용량 확인·취소 기능 제공 |
| 기간 이용권 실험 | 취업·프로젝트의 4주 집중 준비 | 자동 갱신 여부와 종료일을 분명하게 표시 |
| 향후 기관 계약 | 코치 검토, 동의한 참여자의 목표·결과물 공유, 관리 업무 절약 | 개인 비공개 기록과 조직의 권한을 분리 |

출처 보기, AI 오류 신고·정정, 동의 철회와 개인정보 삭제는 유료 전용으로 만들지 않습니다. 구독이 끝나도 사용자가 만든 기록과 확정 문서를 읽고 기존 버전을 복원·내보낼 수 있어야 합니다. 수동 버전 비교·복원과 AI가 새로 근거를 분석해 수정안을 만드는 기능을 구분하고, 서버 분석 비용이 드는 새 분석과 자동 갱신의 제공 범위를 이용권으로 관리합니다.

기관 고객에게는 기록 시간·감정·직무 적합성으로 사람을 줄 세우는 기능을 팔지 않습니다. 채용 후보자 평가나 선발 기능으로 확장한다면 현재의 개인 지원 서비스와는 별도로 법적 분류와 운영 책임을 검토해야 합니다. [S16](sources.md#s16).

## 가격과 원가를 검증하는 방법

### 첫 가격 실험

우선 무료와 개인 유료 한 종류로 시작하고, 동일한 범위를 월 **9,900원 또는 14,900원**에 제공하는 실험을 순차적으로 진행할 수 있습니다. 이는 지불 의사 검증용 가설입니다. 실제 표시 가격은 부가세 포함 여부와 결제 정책을 확정한 뒤 정합니다. 현재 앱의 시연용 연간 59,900원은 가격 결정의 근거로 사용하지 않습니다.

취업 준비자는 구독을 오래 유지하는 것보다 짧은 기간에 목표를 달성할 수 있습니다. 4주 이용권과 월 구독의 차이는 실제 결제·갱신·문의·환불 데이터를 보고 판단합니다. 처음부터 여러 요금제와 연간 선결제를 함께 출시해 가격 실험을 복잡하게 만들지 않습니다.

사용자에게는 토큰 수보다 “개인 심층 분석 몇 회, 문서 수정 몇 회, 자료 몇 개까지”처럼 이해할 수 있는 단위를 제시합니다. 다만 단위별 최대 자료량·출력량·자동 갱신 빈도를 함께 정하고 서버 비용 상한을 둡니다. 실패·중복 요청은 차감하지 않으며, 자료 부족으로 정상 분석을 제공하지 못한 경우의 복원 기준도 미리 고지합니다.

### 원가 계산 예시

아래 숫자는 **계산 방법을 설명하는 가정**입니다. 실제 모델·데이터·결제 업체의 견적이나 현재 원가가 아닙니다.

```text
표시 가격 P에서 월 순수입을 계산하는 구조
  R = P - 실제 적용 세금 T - 결제 수수료 F - 환불·취소 반영액 Q
  각 항목은 같은 기간·사용자 분모로 계산

사용자 한 명의 월 순수입 가정 R = 8,000원
  실제 결제액에서 부가세, 결제 수수료와 환불을 반영한 금액

월 변동비 가정 C = 2,400원
  모델 호출 1,200원 + 자료 접근 500원
  + 사용량에 따른 인프라 300원 + 고객 지원 400원

사용자 한 명의 공헌이익 = R - C = 5,600원
공헌이익률 = (R - C) / R = 70%
```

이는 개발 인건비 등 고정비를 빼기 전이므로 회사의 영업이익률이 아닙니다. 실제로는 평균 사용자와 사용량 상위 사용자를 나눠 확인합니다. 긴 문헌, 반복 재시도, 검색·파싱, 임베딩, 저장, 모니터링과 운영 지원 비용도 집계합니다. 데이터 공급자의 비용·권리 조건이 맞지 않으면 해당 범위를 제외하거나 상품을 다시 설계합니다.

9,900원·14,900원 각각에 대해 실제 세금·수수료·환불을 반영한 `R`을 따로 계산해야 하며, 위 8,000원이 두 가격에 공통으로 적용되는 것은 아닙니다. 월 변동비는 `작업 종류별 횟수 × 해당 작업의 실측 단가`를 합하고, 실패·취소 후 남는 제공자 비용과 지원 비용을 더합니다. 평균 사용, 상위 사용, 한도를 모두 소진한 경우를 비교해 상품 한도를 정합니다. 충분한 사용 표본이 쌓이면 p95 비용도 확인하되 작은 파일럿에서 안정적인 백분위 추정이 나온다고 가정하지 않습니다.

유료화 판단에는 실제 지불·환불·재사용과 작업당 비용을 사용합니다. 설문에서 “구독할 것 같다.”는 답변만으로 매출을 예상하지 않습니다. 수입보다 높은 비용이 드는 무제한 상품은 제공하지 않습니다.

### 결제 경험

분석 전에 예상 사용 단위와 남은 한도를 보여줍니다. 작업 시작 때 사용량을 예약하고 유효한 결과를 제공했을 때 한 번만 확정합니다. 실패·취소·자료 부족 정책에 따라 예약을 해제합니다. 결제 완료 화면으로 돌아왔다는 이유만으로 이용권을 활성화하지 않고 검증된 서버 결제 이벤트를 기준으로 합니다.

청구일, 갱신, 취소, 남은 기간과 분석 사용량을 같은 화면에서 확인하게 합니다. 결제 이력과 권한이 불일치하면 재결제를 유도하기 전에 서버 상태를 다시 확인하고 문의 경로를 제공합니다.

## 실험과 출시 판단

### 첫 4주 검증

가설 검증용으로 경력 전환·취업 준비자 10명과 연구자 10명을 모집할 수 있습니다. 두 집단은 서로 다른 흐름으로 평가합니다. 이 규모는 사용성 문제와 반복되는 가치를 찾기 위한 예시이며 시장 전체의 전환율을 추정하기에 충분하지 않습니다.

1. 최근 실제 공고·문서·연구 질문과 지금 사용하는 도구를 확인합니다.
2. 동의를 받은 제한 자료로 검토자가 확인한 첫 결과를 제공합니다. 수동 작성한 부분은 수동이라고 알립니다.
3. 사용자가 제안을 고르고 실행·수정하는지 4주 동안 관찰합니다.
4. 실제 구매가 가능한 베타에서 가격과 이용권을 검증합니다. 아직 제공할 수 없는 상품의 결제 의향을 실제 매출로 기록하지 않습니다.
5. 반복 사용하지 않은 이유를 목표 달성, 자료 부족, 품질 문제, 사용 부담과 가격으로 구분합니다.

### 지표와 가설 기준

| 지표 | 정의 | 초기 판단 기준의 예시 |
| --- | --- | --- |
| 활성화 | 동의·자료 선택 후 유효한 결과에서 문장이나 행동을 한 번 적용 | 어디서 막히는지 먼저 관찰, 목표 비율은 첫 실험 후 조정 |
| 실행 연결 | 제안 수가 아니라 사용자가 승인한 행동 중 결과를 기록한 비율 | 거절·보류 이유와 예상 시간 초과를 함께 분석 |
| 핵심 가치 | 한 주에 승인한 행동을 수행하고 확인 가능한 결과물을 연결한 활성 사용자 수 | 목표 유형별로 집계, 필수 파일 업로드로 강제하지 않음 |
| 반복 사용 | 분야별 첫 유효 분석 사용자 중 다음 주에도 검토나 실행 갱신을 사용한 사람 | 각 분야 10명이 첫 유효 분석을 받았다면 4명 이상이 3주 이상 사용하는지 탐색 |
| 지불 | 실제 구매 가능한 상품을 같은 조건으로 제안받은 분야별 사용자 중 결제한 사람과 환불 | 해당 분야 10명에게 실제 제안했다면 3명 수준의 구매가 나오는지 탐색. 상품 미제공 분야는 측정하지 않음 |
| 품질 | 사람이 확인한 핵심 주장과 근거의 일치 | 검증 표본 95% 이상을 목표로 하되 허위 경력·허위 인용은 0건 요구 |
| 경제성 | 환불과 사용량을 반영한 공헌이익, 상위 사용자의 비용 | 예시 목표 70%, 실제 가격·원가 측정 후 조정 |

위 숫자는 **팀이 검증할 중단·수정 기준의 초안**이며 업계 평균이나 성공 보장 기준이 아닙니다. 경력 사용자만 반복 사용하고 연구자는 그렇지 않다면 두 집단의 평균으로 성공이라 판단하지 않습니다. 표본과 분모, 관찰 기간을 항상 함께 보고합니다.

첫 베타에서는 보고서만 읽게 한 경험과 실행까지 연결한 경험을 인터뷰·행동 기록으로 비교합니다. 충분한 표본 없이 작은 차이를 통계적으로 유의한 A/B 결과로 부르지 않습니다. 취업률·논문 채택률은 다른 요인의 영향을 크게 받으므로 제품의 인과적 성과라고 주장하지 않습니다.

출시를 막는 조건은 계정 간 자료 노출, 이중 결제·사용량 차감, 허위 경력·인용, 철회 후 처리 지속입니다. 단순한 만족도나 매출이 이 문제를 상쇄하지 않습니다. 구현과 검증의 상세 순서는 [기술 설계와 구현 계획](03-기술-설계와-구현-계획.md)에 정리했습니다.
