# Timebar Diary 로컬 실행 가이드

처음에는 웹만 실행해 화면을 익히고, 로그인과 서버 저장을 확인할 때 API를 추가하세요. 채팅까지 확인하려면 저장소에 포함된 격리용 MySQL과 Redis 구성을 사용하는 편이 간단합니다. 아래 명령은 실행 위치를 구분해서 안내합니다.

## 실행 경로와 준비물

| 실행 목적 | 필요한 도구 | 실행 대상 |
| --- | --- | --- |
| 화면 살펴보기 | Node.js 22.12 이상, npm 10 이상 | Vite 웹 서버 |
| 로그인과 API 개발 | 위 도구, JDK 17, MySQL | 웹과 Spring Boot |
| 로그인과 채팅 확인 | 위 도구, Docker Engine과 Compose | 웹, API, MySQL 8.4, Redis 7.4 |
| 네이티브 앱 확인 | Android Studio 또는 macOS의 Xcode | Capacitor 프로젝트 |
| 데스크톱 앱 확인 | Electron 실행 환경 | Vite와 Electron |

JDK는 Gradle이 Java 코드를 빌드하는 데 사용합니다. Gradle Wrapper가 포함되어 있어 Gradle을 따로 설치할 필요는 없습니다. 첫 npm 설치, Gradle 실행, Docker 이미지 다운로드에는 네트워크 연결이 필요합니다.

저장소를 받은 뒤 PowerShell에서 다음을 확인합니다. 아래의 프로젝트 경로는 자신의 체크아웃 경로로 바꾸세요.

```powershell
cd E:\vscode-proj\vue-timeflow-proj
git status --short
node --version
npm --version
java -version
docker compose version
```

Docker 명령은 격리 DB를 사용할 때만 필요합니다. 이미 실행 중인 개발 서버가 있다면 해당 터미널과 실행 옵션을 먼저 확인하세요.

Node가 20.x처럼 요구 버전보다 낮으면 먼저 Node.js 22.12 이상 또는 지원되는 상위 LTS를 설치하고 터미널을 다시 여세요. node --version과 npm --version을 다시 확인한 뒤 설치를 진행합니다. npm ci가 경고만 내고 끝나더라도 지원하지 않는 Node로 실행해도 된다는 뜻은 아닙니다. JDK를 설치했는데 Gradle이 찾지 못한다면 JAVA_HOME이 JDK 17 경로인지 확인하세요.

## 웹만 실행하기

프로젝트 루트에서 frontend로 이동합니다. 잠금파일을 기준으로 설치하는 npm ci를 사용합니다.

```powershell
cd frontend
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:5173/을 엽니다. 터미널은 서버가 실행되는 동안 유지하며 종료는 Ctrl+C입니다. 서버는 127.0.0.1에 바인딩되고 포트 5173을 고정합니다. 포트가 사용 중이면 자동으로 다른 포트를 선택하지 않습니다.

API가 없어도 로컬 시연 데이터를 쓰는 화면을 살펴볼 수 있습니다. 로그인이나 실제 서버 채팅은 API가 필요합니다. 인증되지 않은 채팅의 시연 대화가 보이는 것을 서버 연결 성공으로 판단하지 마세요.

| frontend에서 실행할 명령 | 열리는 주소 또는 역할 |
| --- | --- |
| npm run dev:devices | /__preview에서 PC와 모바일 프레임 비교 |
| npm run dev:mobile | /__preview?view=mobile에서 모바일 프레임 확인 |
| npm run demo:mock | /mock-demo/ 독립 목업 |
| npm run dev:lan | 동일 사설망의 실제 휴대폰에서 접근 |

웹 서버는 위 명령 중 하나로만 실행하세요. 이미 실행 중이라면 주소만 이동하면 됩니다. localhost와 127.0.0.1은 브라우저 저장소와 허용 출처가 다를 수 있으므로 같은 주소를 일관되게 사용하세요.

## 격리된 DB와 채팅 실행하기

기존 개인 DB를 건드리지 않고 시작하려면 프로젝트 전용 chat-local 프로필을 사용합니다. 이 프로필은 새 개발 DB 전용입니다. 기존 데이터가 있는 DB 주소로 바꿔서 적용하지 마세요.

첫 번째 PowerShell 터미널에서 프로젝트 루트 기준으로 DB와 Redis를 시작합니다.

```powershell
docker compose -f infra/chat/compose.yml up -d --wait
docker compose -f infra/chat/compose.yml ps
```

MySQL은 127.0.0.1:13316, Redis는 127.0.0.1:16389를 사용합니다. MySQL 데이터베이스는 timeflow_chat_dev이며 계정은 timeflow_chat입니다. 개발용 기본 비밀번호는 Compose와 프로필에 들어 있으며 운영에 재사용하면 안 됩니다. 변경할 경우 CHAT_DEV_DB_PASSWORD를 Compose 실행과 API 실행 양쪽에 동일하게 설정하세요.

두 번째 터미널에서 API를 실행합니다. 이 예시는 새 PowerShell 터미널에서 시작하여 기존 서버용 환경변수가 섞이지 않은 경우를 전제로 합니다.

```powershell
cd E:\vscode-proj\vue-timeflow-proj\backend
.\gradlew.bat bootRun --args="--spring.profiles.active=chat-local"
```

세 번째 터미널에서 앞 절의 npm ci와 npm run dev를 실행합니다. chat-local에는 개발용 JWT 키와 127.0.0.1:5173 허용 출처가 설정되어 있습니다. 평소에는 이 환경을 로컬에서만 사용하세요.

```powershell
# 세 번째 PowerShell 터미널에서 실행합니다.
cd E:\vscode-proj\vue-timeflow-proj\frontend
npm ci
npm run dev
```

Windows에서 Docker 명령의 named pipe 연결 오류가 나면 Docker Desktop을 시작하고 Linux containers 엔진이 준비됐는지 확인하세요. docker info가 정상 응답한 뒤 Compose 명령을 다시 실행합니다. 포트 13316과 16389를 다른 서비스가 사용 중이면 해당 서비스의 소유자와 용도를 먼저 확인합니다.

API 로그에 Started가 나타나고 DB와 Redis가 healthy가 된 뒤 상태를 확인합니다.

```powershell
Invoke-RestMethod http://127.0.0.1:8080/actuator/health
```

웹의 /auth/signup에서 테스트 계정을 만들고 /auth/login에서 로그인합니다. 서로 다른 두 브라우저 프로필로 계정 두 개를 만들어 대화방, 메시지, 읽음과 입력 중 표시를 확인하세요. /__preview의 두 프레임은 계정 격리 테스트 용도가 아닙니다.

개발을 끝내면 웹과 API 터미널에서 Ctrl+C를 누른 뒤 아래 명령을 실행합니다. 볼륨을 지우는 -v는 붙이지 않습니다.

```powershell
# 프로젝트 루트에서 실행합니다.
docker compose -f infra/chat/compose.yml stop
```

## 기존 MySQL을 연결하는 방법

기본 프로필의 DB 기본 주소는 localhost:3307/timeflow입니다. 격리 환경의 13316 포트와 다릅니다. 기본 JDBC 드라이버는 MySQL이며 실제 서버 주소와 계정에 맞게 backend/.env를 설정합니다. 예전 MariaDB 안내를 그대로 복사하지 마세요.

```powershell
# 프로젝트 루트에서 파일이 없을 때만 복사합니다.
if (-not (Test-Path backend/.env)) {
  Copy-Item backend/.env.example backend/.env
}
```

backend/.env를 편집해 DB_URL, DB_DRIVER, DB_SCHEMA, DB_USERNAME, DB_PASSWORD, JWT_SECRET를 채웁니다. 파일은 KEY=value 형식이며 PowerShell의 $env: 구문을 파일 안에 쓰지 않습니다. JWT_SECRET는 UTF-8 32바이트 이상의 무작위 값이어야 합니다. 기존 DB는 먼저 백업하고 사용자와 스키마 권한을 준비하세요.

새 MySQL에 직접 DB와 계정을 준비할 때는 관리자 계정으로 접속합니다. 아래 3307은 기본 설정 예시이므로 실제 MySQL 포트로 바꾸세요. 이미 사용 중인 DB나 계정은 새로 만들지 말고 기존 관리자와 설정을 확인합니다.

```powershell
mysql -h 127.0.0.1 -P 3307 -u root -p
```

접속한 MySQL 프롬프트에서 다음 SQL을 실행합니다. 비밀번호 자리표시는 실제 새 비밀번호로 바꾸고 backend/.env에도 동일하게 입력하세요.

```sql
CREATE DATABASE timeflow CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'timeflow'@'localhost' IDENTIFIED BY '새로_정한_비밀번호';
GRANT ALL PRIVILEGES ON timeflow.* TO 'timeflow'@'localhost';
```

이 예시는 로컬 TCP 접속용 계정입니다. 원격 DB의 접속 호스트와 접근 허용은 DB 관리자가 별도로 제한해 설정합니다. 격리 chat-local 경로를 사용한다면 Compose가 준비하므로 위 수동 생성 절차는 필요하지 않습니다.

| 설정 | 확인할 내용 |
| --- | --- |
| DB_URL | 실제 MySQL 포트와 DB명. 기본 3307은 환경에 따라 바꿉니다. |
| DB_SCHEMA | 연결 대상 DB명과 일치시킵니다. |
| DB_DRIVER | MySQL은 com.mysql.cj.jdbc.Driver입니다. |
| CHAT_ENABLED | 기본 false. 채팅을 쓸 때 true로 설정합니다. |
| REDIS_HOST 및 REDIS_PORT | 채팅을 켰다면 실제 Redis 주소를 지정합니다. |
| APP_CORS_ALLOWED_ORIGINS | 브라우저가 직접 API를 호출하는 출처를 지정합니다. |

환경변수는 .env 값보다 우선할 수 있습니다. chat-local과 기존 DB 설정을 한 터미널에서 섞지 마세요. 기본 실행은 backend에서 .\gradlew.bat bootRun입니다. macOS와 Linux는 ./gradlew bootRun을 사용합니다.

Flyway는 서버 기동 시 마이그레이션을 관리하며 JPA는 스키마를 validate합니다. 과거 V1 SQL을 수동 재실행하거나 이력을 삭제하지 마세요. 스키마 검사에 실패하면 오류와 실제 DB 구조를 비교하고 docs/development/database-recovery-2026-10-03.md를 확인합니다.

## API 연결과 플랫폼 확인

개발 웹은 /api 요청을 Vite가 http://127.0.0.1:8080으로 전달합니다. backend 포트를 바꿨다면 frontend/.env.local에 DEV_API_TARGET=http://127.0.0.1:8081처럼 지정한 뒤 Vite를 재시작합니다.

VITE_API_BASE_URL이 비어 있으면 상대 경로를 사용합니다. 값이 있으면 브라우저가 지정한 API에 직접 연결합니다. VITE_ 접두사 값은 빌드된 웹에 공개되므로 DB 비밀번호와 JWT 키를 넣지 않습니다.

실제 휴대폰은 npm run dev:lan 후 표시되는 PC의 사설망 주소로 접속합니다. 휴대폰의 localhost는 개발 PC를 뜻하지 않습니다. 신뢰하는 사설망에서만 사용하고 개발 종료 시 서버를 닫으세요.

Android는 frontend에서 npm run mobile:sync 후 npm run android:open으로 엽니다. iOS는 macOS에서 npm run ios:open을 사용합니다. 데스크톱 개발은 다른 Vite를 종료한 뒤 npm run desktop:dev로 시작합니다. 설치형 앱에는 Vite 프록시가 없으므로 HTTPS API 주소를 별도로 준비해야 합니다.

## 확인 명령과 문제 해결

```powershell
# frontend에서 실행합니다.
npm run build:web
$testFiles = (Get-ChildItem tests/*.test.mjs).FullName
node --test --test-concurrency=1 $testFiles
node scripts/frontend-api-contract.mjs --check
```

```powershell
# backend에서 실행합니다.
.\gradlew.bat test bootJar --console=plain
```

오프라인 옵션은 필요한 의존성이 이미 캐시에 있을 때만 추가합니다. 이 명령은 개발자가 재검증하는 절차이며 실행 여부와 결과는 해당 작업의 기록에 남기세요.

테스트의 일부는 production HTML을 읽으므로 웹 빌드 후 테스트를 실행합니다. 백엔드 테스트 보고서는 backend/build/reports/tests/test/index.html에서 확인합니다. npm test 스크립트는 없으므로 위 Node 테스트 명령을 사용합니다.

웹과 API의 health 응답만으로 기능 검증이 끝나지는 않습니다. 가입과 로그인 후 두 계정의 채팅 전송, 새로고침 후 기록 유지, 비로그인 요청 거부를 확인합니다. 2026년 10월 31일 실제 재검증 범위와 결과는 docs/development/documentation-2026-10-31/verification.md에 기록합니다.

| 현상 | 원인 확인과 조치 |
| --- | --- |
| npm ci 실패 | Node와 npm 버전, 잠금파일 일치, 네트워크를 확인합니다. |
| 5173 포트 충돌 | 기존 Vite 터미널을 찾아 종료하거나 기존 서버를 사용합니다. |
| API 502 | API가 8080에서 실행되는지와 DEV_API_TARGET을 확인합니다. |
| API 401 또는 403 | 로그인 세션과 계정 권한, 호출 주소를 확인합니다. |
| JWT_SECRET 오류 | 기본 프로필의 실제 설정이 UTF-8 32바이트 이상인지 확인합니다. |
| DB 연결 또는 validate 실패 | 포트, DB명, 계정, 마이그레이션 로그를 확인합니다. 이력을 지워 우회하지 않습니다. |
| 채팅 API 404 | CHAT_ENABLED와 실행 프로필을 확인합니다. |
| 채팅 연결 실패 | Redis healthy, 포트, 로그인 계정과 API 로그를 확인합니다. |
