## 현재 프로젝트를 이해하는 기준

Timebar Diary는 계획과 실제 기록을 같은 시간축에서 비교하는 Vue 3 및 Spring Boot 서비스입니다. 저장소 이름은 vue-timeflow-proj이고 웹 패키지 이름은 timebar-diary-web입니다. Timeflow라는 이름도 설정과 앱 이름에 사용합니다.

화면 구현, API 구현, 화면의 API 연결, 운영 환경 검증은 각각 확인해야 합니다. 예를 들어 일정 화면에서 기록이 저장되어도 브라우저 localStorage에만 남을 수 있습니다. 백엔드에 대응 API가 있다는 사실만으로 여러 기기에서 같은 기록이 보장되지는 않습니다.

## Word에서 날짜와 목차 갱신

여섯 문서 모두 생성일에 CREATEDATE, 수정일에 SAVEDATE 필드를 사용합니다. 제목에는 Word의 제목 스타일을 적용했으며 본문 장과 절에는 제목 1과 제목 2 스타일을 사용합니다. 목차는 TOC 필드이므로 장을 추가하거나 순서를 바꾼 뒤 다시 계산할 수 있습니다.

1. 데스크톱 Microsoft Word에서 파일을 열고 편집을 허용합니다.
2. 장 제목을 추가할 때 홈 메뉴의 제목 1 또는 제목 2 스타일을 적용합니다. 글자 크기와 굵기만 바꾸면 자동 목차에 포함되지 않습니다.
3. Ctrl+S로 저장한 뒤 Ctrl+A와 F9를 눌러 본문의 필드를 갱신합니다. 노트북은 Fn+F9가 필요할 수 있습니다.
4. 목차 갱신 창에서는 목차 전체 업데이트를 선택합니다. 목차만 갱신하려면 목차를 우클릭하고 필드 업데이트를 선택해도 됩니다.
5. 갱신된 날짜와 목차를 확인하고 다시 저장합니다. 바닥글 쪽수는 바닥글을 열어 필요한 경우 별도로 갱신합니다.

SAVEDATE는 마지막 저장 시각을 표시합니다. 저장 전 F9만 누르면 이전 저장 시각이 나타날 수 있습니다. CREATEDATE는 필드를 다시 계산해도 최초 생성 시각을 유지하는 것이 정상입니다. 오늘 날짜를 표시하는 DATE 필드로 바꾸지 마세요. 웹 미리보기와 일부 편집기는 필드를 계산하지 않고 저장된 표시값만 보여줄 수 있습니다.

Alt+F9로 필드 코드와 표시값을 전환할 수 있습니다. 생성일, 수정일, 목차가 일반 텍스트로 바뀌지 않도록 Ctrl+Shift+F9는 사용하지 마세요. 이 문서에는 매크로를 넣지 않았습니다.

## 내용을 유지보수하는 방법

Word에서 직접 고칠 수 있습니다. 코드 변경을 문서에 반영할 때는 각 문서 끝의 근거 파일을 먼저 확인하고 기준 커밋과 기능 상태도 함께 갱신하세요. 문서 필드 갱신은 본문을 소스 코드와 자동 동기화하지 않습니다.

같은 폴더의 source에는 한국어 Markdown 원문이 있습니다. scripts/docs/build_handbook.py는 이 원문을 Word로 변환합니다. 재생성하면 Word에서 직접 편집한 내용은 덮어써지므로 먼저 원문에 반영하고 Word 파일의 변경 사항을 보관하세요. 변환기는 내용 갱신용이며 Word의 조판 및 목차 계산은 편집기의 필드 갱신으로 마무리합니다.

기존 docs/design과 docs/api-info에는 2026년 9월의 목표 설계가 포함되어 있습니다. 현재 API 계약은 docs/api/frontend-backend-2026-10-10을 먼저 읽으세요. 104개, 117개, 169개 같은 과거 API 수치를 현재 서버의 규모로 해석하지 마세요.
