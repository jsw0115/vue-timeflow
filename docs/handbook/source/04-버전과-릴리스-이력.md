# Timebar Diary 버전과 릴리스 이력

현재 웹과 API에 선언된 버전은 모두 0.1.0입니다. Git 태그로 확정된 릴리스 목록은 없으므로 아래 이력은 소스 변경의 주요 시점으로 읽어야 합니다. 커밋 날짜와 실제 운영 배포일은 별도로 관리합니다.

## 현재 버전의 기준

| 항목 | 값 | 근거 |
| --- | --- | --- |
| 웹 패키지 버전 | 0.1.0 | frontend/package.json |
| API 버전 | 0.1.0 | backend/build.gradle |
| 조사 기준 커밋 | 98ae7c7 | 2026년 10월 18일 커밋 |
| 조사 시점 브랜치 | master | 로컬 Git 상태 |
| Git 릴리스 태그 | 없음 | git tag --list |
| 컨테이너 이미지 식별자 | 전체 커밋 SHA | .gitlab/ci/linux.yml |

웹의 dependencies에 적힌 ^3.5.13 같은 값은 허용 범위이고 실제 설치 버전은 package-lock.json으로 고정됩니다. 이 값을 서비스 릴리스 번호로 사용하지 않습니다. Java의 Spring Boot 플러그인 선언은 3.5.16이며 Java toolchain은 17입니다.

동일한 0.1.0이라도 서로 다른 커밋에서 빌드했다면 코드가 다를 수 있습니다. 운영 중인 파일과 이미지는 패키지 버전, 전체 SHA와 빌드 식별자를 함께 기록해 구분하세요.

## 이력과 검증 기록 확인

프로젝트 루트에서 다음 명령을 사용합니다.

```powershell
git rev-parse HEAD
git log --first-parent --date=short --format="%h %ad %s" -20
git tag --list
git show --stat 5a8b78e
git diff 628deb5..5a8b78e -- backend frontend
```

특정 파일의 변경을 보려면 git log -- 경로를 사용합니다. uncommitted 변경은 아직 어떤 릴리스에도 확정되지 않은 작업이므로 릴리스 설명에 포함할 때 상태를 명시하세요.

10월 10일 검증 기록에는 백엔드 테스트 178개, 프런트엔드 테스트 47개 통과와 빌드 결과가 있습니다. 이는 당시 결과이며 현재 커밋에서의 재실행 결과가 아닙니다. 또한 H2 및 mock 테스트, 실제 MySQL 검증과 운영 검증은 범위가 다릅니다. 문서 숫자를 복사해 새 릴리스의 성공 근거로 사용하지 마세요.

## 앞으로의 릴리스 기록 방법

다음 항목은 현재 자동화된 버전 정책이 아니라 앞으로 릴리스를 정리할 때 사용하는 권장 절차입니다. 팀이 버전 규칙을 확정한 뒤 적용하세요.

1. 사용자에게 달라지는 기능과 호환성 영향을 정리하고 이번 배포에 포함할 커밋을 확정합니다.
2. 필요한 경우 웹 package.json과 잠금파일, API build.gradle의 버전을 일치시킵니다.
3. 아래의 버전 결합 위치를 검색하고 산출물 이름과 CI 경로를 함께 갱신합니다.
4. 테스트와 빌드 및 API 계약 대조를 실행하고 실제 결과를 기록합니다.
5. 이미지의 전체 SHA, 백업 위치, migration과 롤백 후보를 남긴 뒤 배포합니다.
6. 배포 후 확인한 환경과 시각을 기록합니다. 팀 정책이 있으면 태그와 릴리스 노트를 작성합니다.

현재 API JAR 이름에는 0.1.0이 직접 포함된 참조가 있습니다. build.gradle만 변경하면 이미지와 기동 스크립트가 기존 JAR를 찾을 수 있습니다. 버전을 올릴 때 다음 위치도 확인하세요.

```powershell
rg -n '0\.1\.0|timeflow-api-.*\.jar' `
  backend/build.gradle frontend/package.json `
  infra/deploy scripts/start-backend.ps1 .gitlab
```

| 기록 항목 | 적을 내용 |
| --- | --- |
| 버전 및 SHA | 패키지 버전과 전체 40자리 커밋 SHA |
| 변경 사항 | 사용자 영향, 수정 사항과 알려진 제한 |
| DB 변경 | Flyway 버전과 이전 앱 호환성 |
| 확인 결과 | 실행한 명령, 통과 여부와 검증 환경 |
| 배포 정보 | 환경, 실제 배포 시각과 적용 이미지 |
| 복구 정보 | 백업 위치와 호환 가능한 이전 SHA |
