## 1. PR-03 저장 모델 선택과 중복 정책

**사용자 문제.** "캘린더에 일정을 넣었는데 통계의 계획 시간이 두 배로 나와요." 일정과 루틴을 저장하는 서버 방식이 두 가지(구형 `/api/events`·`/api/routines`, 신형 `/api/schedules`·`/api/routine-records`)이고, 통계는 둘 다 더한다.

**이미 된 것.** 두 모델의 서버 CRUD, 신형의 version·반복 회차 계산. 상세 계획은 [IM-03](06-구현-방안.md#im-03-구형신형-저장-모델-선택)에 있다.

## 2. PR-05 BYOK 키 평문 저장 제거

**사용자 문제.** "설정에 AI 키를 넣었더니 'AI 연동됨'이라고 떠서 쓰고 있는 줄 알았어요." 입력한 키는 브라우저에 평문으로 남고, 실제로는 어디에도 쓰이지 않는다. AI도 연결되어 있지 않다.

**이미 된 것.** 서버 `/api/settings`의 비밀 필드 거부, AI 리포트 화면의 서버 제공 상태 표시(P0-1), `useCapabilityStatus` 조회 모듈. 상세 계획은 [IM-05](06-구현-방안.md#im-05-byok-키-평문-저장-제거)에 있다.

### 남은 기능

| ID | 기능 | 세부 요구 |
| --- | --- | --- |
| UF-75 | 저장된 키 삭제 | 앱 시작 시 `localStorage`의 `timeflow.ai.v1`에서 `apiKey`를 지우고, `provider: 'byok'`는 `none`으로 바꾼다. 나머지 설정은 유지한다 |
| UF-76 | 키를 다시 저장하지 않음 | 저장은 허용 필드(`provider scope enabled allowSensitive redactNames keepHistory`)만 고른다. 상태 객체에 `apiKey` 필드가 없다 |
| UF-77 | BYOK 선택지는 "준비 중" | 버튼은 `disabled`·`aria-disabled`이고 키 입력란이 없다 |
| UF-78 | AI 상태를 서버 기준으로 표시 | 설정 배지는 확인 중·확인 실패(다시 시도)·AI 준비 중·사용 가능 네 가지다. WBS·경력 화면도 서버 상태가 `true`일 때만 "켜져 있어요"라고 표시한다 |
| UF-79 | 키를 지운 사실 안내 | 지운 경우에만 설정 화면에 "보안을 위해 이 브라우저에 저장된 API 키를 지웠어요."를 한 번 보여 준다 |

## 7. PR-10 공유·업무·관리 서버 연결

**사용자 문제.** "가족에게는 일정 제목까지, 회사에는 바쁜 시간만 보이게 하고 싶은데, 상대에게 실제로 무엇이 보이는지 모르겠어요(CF-035)." "통계 숫자가 어떤 기록에서 나왔는지 눌러서 보고 싶어요(CF-014)." 공유·커뮤니티·업무·관리 화면은 아직 시연 데이터다.

**이미 된 것.** 친구·차단·공유 그룹·커뮤니티·업무 기록·WBS·위키·관리자 API와 권한 검사(FD-50~FD-52, FD-60~FD-63, FD-74~FD-76), 첨부 업로드 한도. 2026-11-20 1단계로 그룹별 공유 범위(V11), 그룹 캘린더·미리보기·철회, 이메일로 사람 찾기 서버를 만들었다(06 IM-10, Q-23·Q-24). 2단계로 친구·차단·공유 그룹·그룹 상세·공유 가시성 화면을 서버에 연결했다(UT-190 PASS). 3단계로 커뮤니티 목록·만들기·홈·가입 신청·가입 요청함·멤버·게시판을 서버에 연결했다(UT-196 화면 PASS). 3b-1로 챌린지 인증을 실제 기록으로 확인하고 기록 공개 챌린지를 두는 서버를 만들었고(V12, Q-26), 3b-2로 챌린지·랭킹 화면을 서버에 연결했고, 3b-3으로 커뮤니티 채팅방을 회원과 자동 동기화했다(채팅 V5, Q-25). 4단계로 업무 기록·WBS·위키 화면을 서버에 연결했다(UT-197). 5단계로 공유 첨부 화면을 서버에 연결하고 파일당 10 MiB 한도를 올리기 전에 알리며(UT-198), 관리자 화면이 서버 권한을 확인해 일반 계정에는 권한 없음 안내만 보이게 했다(UT-199). 관리 화면 중 사용자 관리·관리자 통계를 서버에 연결했다. 6단계로 통계 보드 "한눈에 보기"의 수치마다 집계 기간·시간대·기록 수를 보이고 누르면 그 수치를 만든 원본 목록으로 가게 했다(UT-200·UT-201). 2026-11-21 7-1로 1:1 문의(사용자 고객지원 작성·관리자 CS 답변)를, 7-2로 공지(관리자 등록·사용자 화면 표시)를, 7-3으로 콘텐츠 저장(사용자 화면 표시는 Q-29)을, 7-4로 감사 로그를, 7-6으로 모니터링(서버 측정값만)을 서버에 연결했다. 7-7로 게시글 신고(회원)와 신고 처리(관리자, 글 내용 확인)를 연결했다. 관리 화면 중 남은 것은 Q-30 결정 대기인 관리자 설정과 PR-17 보류인 구독/결제다(구독/결제는 PR-17 보류), 통계 보드의 다른 포틀릿과 일간·카테고리·비교 통계, 업무 리포트·히스토리(서버 API 없음)는 아직 시연 데이터다.
