- 근거는 [06 구현 방안](06-구현-방안.md), [구매자 의견 상세 제안](../product/customer-feedback-2026-11-14/implementation.md), [요구사항](../planning/requirements.md), 08 문서와 2026-11-18 소스 확인이다. 구매자 의견은 가상의 익명 의견이다.

## 1. PR-03 저장 모델 선택과 중복 정책

**사용자 문제.** "캘린더에 일정을 넣었는데 통계의 계획 시간이 두 배로 나와요." 일정과 루틴을 저장하는 서버 방식이 두 가지(구형 `/api/events`·`/api/routines`, 신형 `/api/schedules`·`/api/routine-records`)이고, 통계는 둘 다 더한다.

**이미 된 것.** 두 모델의 서버 CRUD, 신형의 version·반복 회차 계산. 상세 계획은 [IM-03](06-구현-방안.md#im-03-구형신형-저장-모델-선택)에 있다.

## 2. PR-05 BYOK 키 평문 저장 제거

**사용자 문제.** "설정에 AI 키를 넣었더니 'AI 연동됨'이라고 떠서 쓰고 있는 줄 알았어요." 입력한 키는 브라우저에 평문으로 남고, 실제로는 어디에도 쓰이지 않는다. AI도 연결되어 있지 않다.

**이미 된 것.** 서버 `/api/settings`의 비밀 필드 거부, AI 리포트 화면의 서버 제공 상태 표시(P0-1), `useCapabilityStatus` 조회 모듈. 상세 계획은 [IM-05](06-구현-방안.md#im-05-byok-키-평문-저장-제거)에 있다.

### 남은 기능

| ID | 기능 | 세부 요구 |
| --- | --- | --- |
| UF-75 | 저장된 키 삭제 | 앱 시작 시 `localStorage`의 `timeflow.ai.v1`에서 `apiKey`를 지우고, `provider: 'byok'`는 `none`으로 바꾼다. 나머지 설정은 유지한다 |
| UF-76 | 키를 다시 저장하지 않음 | 저장은 허용 필드(`provider scope enabled allowSensitive redactNames keepHistory`)만 고른다. 상태 객체에 `apiKey` 필드가 없다 |
| UF-77 | BYOK 선택지는 "준비 중" | 버튼은 `disabled`·`aria-disabled`이고 키 입력란이 없다 |
| UF-78 | AI 상태를 서버 기준으로 표시 | 설정 배지는 확인 중·확인 실패(다시 시도)·AI 준비 중·사용 가능 네 가지다. WBS·경력 화면도 서버 상태가 `true`일 때만 "켜져 있어요"라고 표시한다 |
| UF-79 | 키를 지운 사실 안내 | 지운 경우에만 설정 화면에 "보안을 위해 이 브라우저에 저장된 API 키를 지웠어요."를 한 번 보여 준다 |
