## 저장 방식 표기

| 값 | 의미 |
| --- | --- |
| 서버 | 화면이 서버 API를 호출해 계정별로 저장·조회한다 |
| 로컬 | 브라우저 store·시연 데이터 중심이다. 계정별 서버 저장이 끝난 화면으로 소개하지 않는다 |
| 일부 | 화면의 일부 기능만 서버를 호출한다 |
| 서버·로컬 | 로그인하면 계정별 서버 저장, 로그아웃이면 이 브라우저에 저장한다. 로그아웃 상태 화면에 "이 브라우저에만 저장돼요"를 보인다(PR-07, UF-87) |
| 시연 | 고정된 시연 값이나 메모리에만 있는 값이다. 새로고침하면 처음으로 돌아가고 서버에 저장하지 않는다 |
| 상태 표시 | 외부 제공자 미연결 상태를 서버에서 조회해 표시만 한다 |

2026-11-17 정적 확인 기준이다. 메뉴의 저장 방식이 바뀌면 이 표와 [03 기능개발 목록서](03-기능개발-목록서.md)를 함께 고친다.

## 일정·루틴 서버 계약

2026-11-18 PR-03(A안)에서 정한 기준 계약이다. 일정·루틴은 신형 `/api/schedules`·`/api/routine-records`만 쓴다. 구형 `/api/events`·`/api/routines`는 폐지 예정이며 화면에서 호출하지 않는다(`frontend/tests/legacy-schedule-api.test.mjs`가 검사). 일정 템플릿 `/api/events/templates`는 신형 저장소(`feature_record`)라 폐지 대상이 아니다. 아래 화면은 아직 저장 방식이 `로컬`이며, 실제 화면 연결은 PR-07에서 한다.

| 메뉴 | 화면 | 읽기 | 쓰기 |
| --- | --- | --- | --- |
| MN-01 | 홈 | `/api/home/summary`의 `schedules`·`routineRecords`·`planner.tasks` | 해당 없음 |
| MN-03 | 캘린더 | `/api/schedules/occurrences` | `/api/schedules` |
| MN-10 | 플래너 | `/api/schedules/occurrences`, `/api/planner/items`, 실제 기록 상세의 연결 `/api/record-links` | `/api/planner/items`, `/api/planner/recordings` |
| MN-20 | 일정 | `/api/schedules`, 상세의 연결 `/api/record-links` | `/api/schedules`, 기록 시작 `/api/planner/recordings/start`(`sourceKind`·`sourceId`) |
| MN-22 | 일정 템플릿 | `/api/events/templates` | `/api/events/templates`, 적용은 `/api/events/templates/{id}/apply` |
| MN-24 | 루틴 | `/api/routine-records` | `/api/routine-records`, `PUT /api/routine-records/{id}/history/{date}` |
| MN-25 | 루틴 히스토리 | `/api/routine-records/{id}/history` | 같은 경로의 `PUT` |
| MN-40~MN-42 | 통계 | `/api/stat/*` | 해당 없음 |

## 메뉴 변경 절차

1. `navGroups` 또는 `settingsSections.js`를 고친 커밋에서 이 문서의 해당 행을 함께 고친다. 메뉴 ID(MN)는 재사용하지 않고, 삭제한 메뉴는 행을 남기고 "삭제"로 표시한다.
2. 경로가 바뀌면 [화면 경로 목록](../product/screen-catalog.md)을 생성기로 다시 만든다.
3. 저장 방식이 `로컬`에서 `서버`로 바뀌면 [03 기능개발 목록서](03-기능개발-목록서.md)의 화면 열과 [07 결과서](07-테스트-시나리오-및-결과서.md)의 계정 전환 시나리오 결과를 함께 갱신한다.
