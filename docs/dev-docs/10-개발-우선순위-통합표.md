### 5-1. PR-03 저장 모델 선택과 중복 정책(완료)

- **결정**: A안. 일정·루틴을 신형 `/api/schedules`·`/api/routine-records`로 단일화했다(Q-01).
- **구현**: `InsightService.stats()`에서 구형 일정 합산을 빼고, `summary()`의 구형 루틴을 뺐다. 일정 템플릿 적용이 신형 `SCHEDULE`을 만들도록 바꿨다. 구형 API에 RFC 9745 형식 `Deprecation`·`Link` 헤더를 붙였다.
- **통계 규칙**: 계획 시간은 신형 일정 회차 + planner PLAN이다. 같은 기록은 `id`(일정은 `occurrenceKey`)로 한 번만 센다. 시간이 겹쳐도 자동으로 합치지 않는다.
- **검증**: UT-100~UT-103, UT-106 PASS(07 RUN-23~RUN-29).
- **후속**: 구형 자료 이전(UF-74)과 구형 제거는 PR-21이다.
