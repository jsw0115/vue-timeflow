## 읽는 법

- **서버**: 백엔드 API·저장·권한 구현 여부. **화면**: 프런트 화면이 서버 계약을 실제로 호출하는지 여부. **검증**: 이번 묶음 작성 이후 기록된 실행 증빙.
- 값은 `구현`, `일부`, `로컬`(브라우저 저장), `미연결`(외부 제공자 503 경계), `설계`(설계 단계), `없음`이다.
- 상태는 2026-11-17 소스 정적 확인과 기존 기록을 근거로 한다. 화면 열의 `로컬`은 계정별 서버 저장이 끝나지 않았다는 뜻이다.
- 수용 기준 원문은 고치지 않고 [원문](../planning/requirements.md#기능-요구사항)에서 읽는다.

## 요구 변경 절차

1. 새 요구나 수용 기준 변경은 먼저 [원문](../planning/requirements.md)에 ID와 함께 추가한다. ID는 원문에서만 만든다.
2. 이 문서의 표에 같은 ID 행을 추가하거나 고치고, [01 개발 우선순위](01-개발-우선순위.md)에 연결한다.
3. 관련 테스트 ID를 [테스트 계획](../quality/test-plan.md)에 정의하고 [07 결과서](07-테스트-시나리오-및-결과서.md)에 시나리오를 연결한다.
4. 문서 버전을 올리고 변경 이력에 이유를 적는다. 폐기한 요구도 행을 지우지 않고 "폐기"와 대체 ID를 남긴다.
