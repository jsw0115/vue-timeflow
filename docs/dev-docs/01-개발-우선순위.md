## 우선순위 기준

- **P0**: 기록 유실·덮어쓰기, 사실과 다른 성공 표시, 권한·비밀값 노출처럼 기본 신뢰를 해치는 문제. 새로 발견되면 일정과 관계없이 맨 앞에 넣는다.
- **P1**: 매일 쓰는 기록·계획 흐름의 서버 연결, 개발 환경, 첫 배포 전 필수 검증.
- **P2**: 사용성 개선, 서비스 연동, 성능 측정.
- **P3**: IoT·전용 기기 확장. 핵심 흐름이 검증된 뒤 판단한다.

같은 등급 안에서는 선행 조건이 없는 항목, 다른 작업을 막고 있는 항목, 변경 범위가 작은 항목 순서로 둔다. 근거는 [작업 원장](../releases/backlog.md), [WBS](../planning/wbs.md), [검토보고서 대응 계획](../agent/records/2026-11-16-검토보고서-우선구현/plan.md), [구매자 의견 목록](../product/customer-feedback-2026-11-14/README.md)이다.

## P0. 기록 신뢰성·잘못된 표시 차단

### PR-01. 플래너 version 충돌 방지 마무리

- **문제**: 기존 `/api/planner/items`는 마지막에 저장한 요청이 이전 변경을 덮어쓴다.
- **현재 상태**: 완료(2026-11-17). 백엔드 전체 196개·프런트 64개·계약 검사·빌드 통과([07 RUN-13~RUN-18](07-테스트-시나리오-및-결과서.md#실행-결과-기록)). 프런트 화면에는 `/api/planner/items` 호출이 없어 클라이언트 수정은 필요 없었다.
- **후속**: 운영 적용 시 V7과 서버·클라이언트를 함께 배포한다(PR-13). 이 작업은 로컬 구현·검증까지이며 운영 DB 적용은 하지 않았다.
- **수용 기준**: 오래된 version의 수정·상태 변경·삭제는 409, 다른 계정은 404, version 누락·음수는 400, 동시 쓰기는 한 건만 성공.
- **연결**: REQ-F07, REQ-N05, TC-08, TC-39, WBS-04.

### PR-02. 업로드 크기 한도 정렬

- **문제**: `infra/deploy/nginx.conf`는 `client_max_body_size 10m`인데 Spring은 파일 10MB·요청 11MB를 허용한다. 10MB 파일에 multipart 부가 정보가 붙으면 프록시에서 먼저 거절될 수 있다.
- **현재 상태**: 검증. 2026-11-17 Nginx를 `11m`로 맞추고, 설정 정렬 테스트(`frontend/tests/upload-limits.test.mjs`)와 앱 경계 테스트(`FeatureHttpTest`)를 추가해 통과했다([07 RUN-19~RUN-22](07-테스트-시나리오-및-결과서.md#실행-결과-기록)). 실제 프록시 경유 업로드(TS-05의 프록시 부분)는 서버 환경이 필요해 PR-13에서 확인한 뒤 완료로 바꾼다.
- **수용 기준**: 프록시·앱·화면 안내의 한도가 같은 값을 가리키고, 경계값·초과·타인 파일 테스트가 통과한다.
- **연결**: REQ-F14, TC-22, TC-23, IMP-004, WBS-02.

### PR-03. 구형·신형 저장 모델 선택과 중복 정책

- **문제**: 구형 `/events`·`/routines`·`/planner/items`와 신형 `/schedules`·`/routine-records`는 자동 동기화하지 않는다. 둘을 함께 쓰면 통계가 중복 집계될 수 있다.
- **현재 상태**: 완료(2026-11-18). A안(신형 `/schedules`·`/routine-records`로 단일화)을 채택했다. 통계·홈 요약에서 구형 일정·루틴을 뺐고, 일정 템플릿 적용이 신형 일정을 만들도록 바꿨고, 구형 API에 폐지 예정 헤더를 붙였다. 백엔드 전체·프런트 전체·계약 검사 통과([07 RUN-23~RUN-29](07-테스트-시나리오-및-결과서.md#실행-결과-기록)). 화면별 계약 표는 [04](04-메뉴기능-목록서.md#일정루틴-서버-계약)에 있다.
- **후속**: 구형 서버 자료 이전(UF-74)과 구형 API·테이블 제거는 PR-21이다. 로컬 자료 이전 규칙은 [09 권장 결정](09-잔여-개발-항목-기획서.md#권장-결정)의 Q-11·Q-13을 따라 PR-07에서 구현한다.
- **수용 기준**: 화면별로 사용할 계약을 정한 표, 로컬 자료 이전 규칙(원본 ID·사용자 승인·멱등성), 시간이 겹친다는 이유만으로 자동 병합하지 않는다는 규칙.
- **연결**: REQ-F03, REQ-F05, REQ-F07, TC-11, IMP-001.

### PR-04. 잔여 작업 일정·담당 재산정

- **문제**: WBS의 제안 일정(34~54 MD)에 실제 담당 인력이 배정되어 있지 않다.
- **현재 상태**: 대기. 인력·예산·납기는 저장소만으로 확정할 수 없다.
- **수용 기준**: 역할별 배정, 선행 조건, 외부 승인 대기, 운영 검수 완충을 포함한 일정. 확정하지 못한 값은 "미정"으로 남긴다.
- **연결**: WBS-03~WBS-13, 검토보고서 P0-3.
