## 점검 범위와 방법

- 도구: 컨테이너에 설치된 Chromium(Playwright). 이 세션에는 Claude in Chrome 확장이 없다. 화면 점검은 `vite preview`(프로덕션 빌드), 실제 백엔드 점검은 `vite` 개발 서버(`/api`를 백엔드로 넘김)로 했다.
- 화면: 지난 점검과 같은 라우터 106개 경로.
- 화면 조건 18가지(모두 106개 경로, 합계 1,908회): 아래 표 외에는 로그아웃 상태이고 가짜 API가 모든 요청에 401을 돌려준다. 로그인 조건은 지난 점검의 en-1440-in과 같은 가짜 응답을 쓴다.

| 묶음 | 조건 |
|---|---|
| 태블릿 너비 | 768px 한국어, 768px 영어(로그인), 1024px 영어, 1024px 한국어(로그인) |
| 200% 확대 | 1440px 창을 200%로 키운 것과 같은 CSS 너비 720px, 한국어·영어 |
| 표면 | 다크·세피아·고대비(포레스트, 한국어), 다크(포레스트, 영어, 로그인) |
| 색상 테마 | 잉크·플럼·클레이·모스 × 라이트·다크(한국어) |

- 화면마다 확인한 것: 지난 점검과 같다(페이지 오류·콘솔 오류, 가로 넘침, `<html lang>`, 대비, 이름 없는 버튼, 라벨 없는 입력칸).
- 키보드: 주요 화면 16곳에서 Tab을 40번 눌러 초점 표시와 초점을 잃는지 봤다. 대화 상자 6곳(일정 템플릿·프로젝트 캔버스 컬럼 관리·공수 항목·할 일·메모·D-Day)은 키보드로 열고, Tab으로 초점이 창 밖으로 나가는지, Esc로 닫히는지, 닫은 뒤 초점이 연 버튼으로 돌아오는지 봤다. 본문(`main`) 첫 요소까지 Tab 횟수도 셌다.
- 실제 백엔드: `infra/chat/compose.yml`로 격리 MySQL 8.4·Redis 7.4를 띄우고 `chat-local` 프로필로 백엔드를 실행했다(Flyway 적용 후 시작). 점검용 계정을 새로 만들어 가입·로그인, 106개 경로 열기, 만들기·새로고침·완료·삭제, 표시 언어 계정 저장, 메모를 할 일로 바꾸기를 확인했다. 운영 DB는 쓰지 않았다.

## 찾은 버그

<a id="bug-012"></a>
### BUG-012. 일부 링크가 브라우저 기본 색으로 보이고 다크 표면에서 읽기 어려움 (P2, 접근성)

- 화면:
  - 다이어리 작성(`/diary/entry`)의 "이 날의 일정과 실제 기록" 일정 이름
  - 전체 화면 목록(`/sitemap`)의 화면 카드 이름
  - 화면 상세(`/screens/PLAN-001`)의 관련 화면 카드 이름
  - 관리자 서비스 설정(`/admin/settings`)의 "사용자 관리"·"감사 로그" 링크
- 실제: 글자가 브라우저 기본 링크 색 rgb(0,0,238)로 보인다. 다크 표면에서는 대비가 1.46:1~1.6:1이다(기준 4.5:1). 라이트 표면에서는 대비는 넘지만 DESIGN.md의 링크 색(accent)과 다르다.
- 원인: 링크 색은 `styles.css`의 `a:not([class])`에만 있다. `RouterLink`는 활성 상태가 아닐 때 `class=""`를 남겨서 이 규칙에 걸리지 않는다. `.screen-card`처럼 클래스가 있는 링크도 글자색 규칙이 없으면 기본 색이 된다.
- 근거: 18조건 대비 계산(다크 6조건 모두에서 나옴). 로그아웃 다크 조건에서 106개 경로의 모든 `<a>` 글자색을 따로 확인했더니 기본 색은 다이어리 작성뿐이었다. 나머지 세 화면은 관리자로 로그인해야 열려서 로그인 조건(가짜 관리자 응답)에서 나왔다. 같은 방식의 링크(할 일·일정의 "플래너에서 먼저 끝내기", 집중의 "플래너에서 보기", `LinkedRecords.vue`의 연결 기록)는 이번 조건에서 화면에 나오지 않아 직접 보지 못했다.
- 권장: 링크 기본 색 규칙이 `class=""`인 링크도 포함하게 하고, `.screen-card`처럼 카드 전체가 링크인 곳은 글자색을 토큰으로 정한다.

### BUG-013. 본문 바로가기가 없어 키보드로 본문까지 Tab 60번 (P2, 접근성)

- 화면: 사이드바가 있는 모든 화면.
- 실제: 페이지를 새로 열고 Tab을 누르면 로고, 하루 모드, 사이드바의 묶음·메뉴, 환경설정, 로그인 항목까지 59곳을 지나 60번째에 본문 영역(맨 위 통합 검색 버튼)에 닿는다(`/`·`/tasks`, 1440px·390px 같음). 본문으로 바로 가는 링크가 없다.
- 근거: Tab 횟수 측정, `App.vue`·`index.html`·`styles.css`에서 본문 바로가기 검색. 웹 접근성 점검 항목 6.4.1(반복 영역 건너뛰기)에 해당한다([점검 항목](../../security/WEB_ACCESSIBILITY_KWCAG22_33.md)).
- 권장: 화면 맨 앞에 초점을 받을 때만 보이는 "본문 바로가기" 링크를 두고 `main`으로 초점을 옮긴다.

<a id="bug-014"></a>
### BUG-014. 영어 화면에서 서버 오류 문구가 한국어로 보임 (P2, 다국어)

- 화면: 로그인(`/auth/login`), 가입(`/auth/signup`).
- 실제: 영어 화면에서 비밀번호를 틀리면 "이메일 또는 비밀번호가 올바르지 않습니다.", 이미 가입한 이메일로 가입하면 "이미 가입된 이메일입니다."가 그대로 보인다. 문구도 앱의 해요체와 달리 "~습니다"체다.
- 원인: 화면은 서버가 보낸 `message`를 `tr()`로 넘기는데, 인증·공통 응답 문구(성공 안내 포함) 26개 중 25개가 영어 사전에 없다(`backend/.../auth`, `common/ErrorCode.java`).
- 근거: 실제 백엔드로 두 경우를 영어 화면에서 재현했다. 사전 대조는 스크립트로 했다. 나머지 23개 문구가 화면에 실제로 나오는지는 하나씩 재현하지 않았다.
- 권장: 화면에 나올 수 있는 서버 오류 문구를 사전에 더하거나, 서버 오류 코드로 화면 문구를 고른다.

## 오탐으로 판단한 것

- 대화 상자 점검에서 처음에는 `[role=dialog]`가 0개로 나왔다. `Modal.vue`는 `<dialog>`를 `showModal()`로 여는 기본 대화 상자라 역할 속성을 따로 적지 않는다. Playwright의 역할 검색(`getByRole('dialog')`)으로는 1개로 잡혔다.
- 대화 상자에서 Tab을 누르면 몇 번에 한 번 초점이 페이지 밖(`body`)으로 나갔다. 마지막 요소 다음에 브라우저 주소창 쪽으로 넘어간 것이고, 다시 Tab을 누르면 창 안 첫 요소로 돌아왔다. 뒤쪽 화면의 요소에 초점이 간 적은 없다.
- 다이어리·머니로그의 월 입력칸에 초점 표시가 없다고 나왔다. 월 입력칸 안의 연·월 칸 사이를 Tab으로 옮길 때 잡힌 값이다. 입력칸 자체는 `:focus-visible`에서 2px accent 테두리가 보였다.
- 설정 테마(`/settings/theme`)의 "저장 실패 · 다시 시도"는 미리보기 견본 문구다.
- 플래너 월간·연간의 "실패로 세지 않아요"는 실행률 설명 문구다.
- `vite preview`에서 `/settings/theme`처럼 두 단계 주소를 새로 고치면 빈 화면이 된다. `build:web`은 `base: './'`라 자원 경로가 주소 기준으로 풀리기 때문이다. 리눅스 컨테이너 배포는 `--base=/`로 빌드하고(`.gitlab/ci/linux.yml`), GitLab Pages는 해시 주소를 써서 배포에는 해당하지 않는다.
- 관리자가 아닌 계정으로 `/admin`을 열 때의 403은 정상 흐름이다. 화면은 "이 계정에는 관리자 권한이 없어요. 관리자 화면이 필요하면 운영 책임자에게 권한을 요청해 주세요."를 보인다.

## 확인하지 못한 것

- 화면 읽기 프로그램(NVDA·VoiceOver 등)으로 읽어 보기. 이 환경에 없다.
- 실기기(휴대폰·태블릿)와 Capacitor·Electron 포장 앱.
- 웹 글꼴: `styles.css`가 불러오는 Pretendard(`cdn.jsdelivr.net`)를 이 환경의 네트워크가 막아 대체 글꼴로 그렸다. 지난 점검도 같다. 글자 폭이 달라 가로 넘침 결과가 실제와 조금 다를 수 있다.
- 실제 백엔드로 확인하지 않은 흐름: 채팅·공유·커뮤니티 쓰기, 파일 올리기, 비밀번호 재설정 메일, 로그인 시도 제한(계정이 잠길 수 있어 하지 않음), 관리자 계정 화면.
- 사용자 지정 색상 테마, 시스템 설정 따르기, 다크 표면의 로그인 상태 전체(영어 1조건만 봤다).
- 정식 KWCAG·OWASP 점검. 이 문서는 정식 인증 결과가 아니다.
