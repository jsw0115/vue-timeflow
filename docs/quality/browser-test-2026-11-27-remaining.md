## 점검 범위와 방법

- 도구: 컨테이너에 설치된 Chromium(Playwright). 이 세션에도 Claude in Chrome 확장이 없다. 화면 점검은 `vite preview`(프로덕션 빌드)로, 실제 백엔드 점검은 격리 MySQL 8.4·Redis 7.4(`infra/chat/compose.yml`)와 `chat-local` 백엔드, `vite` 개발 서버로 했다. 운영 DB는 쓰지 않았다.
- 실제 글꼴: 이 환경은 `cdn.jsdelivr.net`이 막혀 있다. 그래서 npm의 `pretendard@1.3.9` 패키지에 든 같은 CSS·글꼴 파일을 세션 임시 폴더에 받고, 브라우저가 그 주소를 요청하면 이 파일로 대신 줬다. 저장소 의존성은 바꾸지 않았다.
- 실제 백엔드: 점검용 계정 A·B·C·D와 관리자 계정 2개를 새로 만들었다. 관리자 역할은 격리 DB에서만 바꿨다.
- 화면 읽기 프로그램 대신: 106개 경로의 접근성 구조(페이지 제목, h1, `main`·`nav` 랜드마크, 현재 메뉴 표시, 중복 id, alt 없는 이미지)를 읽었다. 실제 화면 읽기 프로그램 결과는 아니다.
- 실기기 대신: Playwright의 기기 설정(Pixel 7, iPhone 13, Galaxy S9+, iPad Mini)으로 Chromium을 띄웠다. 실제 기기·실제 Safari 결과는 아니다.

## 찾은 버그

<a id="bug-015"></a>
### BUG-015. 서버에서 세션이 끝나면 안내 없이 로그아웃 상태가 되고 시연 기록이 보임 (P2)

- 화면: 로그인 상태의 모든 화면.
- 재현: 계정 D로 로그인해 할 일 화면을 연다. 관리자가 D를 정지한다(모든 기기 로그아웃). D의 탭을 새로 고친다.
- 실제: 요청이 401을 받고 토큰 갱신(`/api/auth/refresh`)도 401이면 `clearSession()`이 조용히 세션을 지운다. 사이드바는 "로그인 · 기록을 계정에 저장하려면 로그인하세요"로 바뀌고, 메모 화면에는 이 브라우저의 시연 메모 4건이 보인다. 왜 로그아웃됐는지, 다시 로그인하라는 안내가 없다.
- 영향: 정지뿐 아니라 강제 로그아웃·refresh 토큰 만료에도 같은 경로를 탄다(`features/auth/session.js`의 `refresh()` 실패 처리). 사용자는 시연 기록을 내 기록으로 착각하거나, 이어서 쓴 기록이 계정이 아니라 이 브라우저에 저장될 수 있다.
- 근거: 실제 백엔드에서 관리자 화면으로 정지해 재현했다. 같은 탭에서 새로고침 없이 화면만 옮겼을 때는 이미 받은 목록을 그대로 보였다.
- 권장: 갱신 실패로 세션을 지울 때 "로그인이 끝났어요. 다시 로그인해 주세요." 같은 안내를 보이고 로그인 화면으로 안내한다. 정지 사유는 로그인할 때 서버 문구("비활성화된 계정입니다.")로 보인다.
- 처리(2026-11-27): 토큰 갱신이 실패해 세션을 지울 때만 `sessionNotice.ended`를 켠다(사용자가 직접 로그아웃하면 켜지 않는다). 앱 셸 본문 맨 위에 "로그인이 끝났어요. 지금 보이는 기록은 이 브라우저에 있는 것이에요. 계정 기록을 보려면 다시 로그인해 주세요."와 로그인 링크·닫기 버튼을 `role="alert"`로 보이고, 로그인 화면에도 같은 안내를 보인다. 다시 로그인하면 사라진다. 실제 백엔드에서 관리자 정지 뒤 새로고침으로 한국어·영어 모두 확인했다.

<a id="bug-016"></a>
### BUG-016. 모든 화면의 페이지 제목이 같음 (P2, 접근성)

- 화면: 106개 경로 전부.
- 실제: 브라우저 탭 제목(`document.title`)이 어느 화면이든 "Timebar Diary · 계획과 실제 기록"이다. `index.html`의 `<title>`만 있고, 화면을 옮길 때 제목을 바꾸는 코드가 없다.
- 영향: 화면 읽기 프로그램은 화면을 옮길 때 페이지 제목을 먼저 읽으므로, 어느 화면에 왔는지 알 수 없다. 탭이 여러 개일 때도 구분하기 어렵다. 웹 접근성 점검 항목 6.4.2(제목 제공)에 해당한다([점검 항목](../../security/WEB_ACCESSIBILITY_KWCAG22_33.md)).
- 권장: 라우터 이동 뒤 화면 이름(사이드바 이름, 본문 언어)으로 `화면 이름 · Timebar Diary`를 붙인다.
- 처리(2026-11-27): 사용자 화면은 머리글의 화면 이름(`pageName`), 관리자 화면은 라우트 이름으로 탭 제목을 바꾼다(권한 확인 전에는 "관리자 화면"). 106개 경로에서 기본 제목이 0개가 됐고 서로 다른 제목은 87개다(환경설정 구역처럼 화면 이름이 같은 곳은 제목도 같다). 영어 화면에서 한글이 남던 앱 셸 밖 화면 4곳의 이름은 사전에 더했다.

<a id="bug-017"></a>
### BUG-017. 미리보기 시험(device-preview)이 가끔 끝나지 않음 (P2, 시험)

- 실제: `tests/device-preview.test.mjs`가 끝나지 않아 전체 시험이 멈췄다. 그동안 이 컨테이너에서 NOT_RUN으로 두었다(07 RUN-176).
- 원인: 시험이 `/src/main.js`를 요청하면 Vite가 의존성 최적화를 시작한다. 최적화가 도는 동안 `vite.close()`를 부르면 끝나지 않는다. 의존성 캐시(`node_modules/.vite`)가 최신이면 최적화가 없어 통과했기 때문에 가끔만 멈췄다. 같은 단계를 시간을 재며 따라 해서 확인했다(요청 3개는 2.3초 안에 200, close만 끝나지 않음. 15초 기다린 뒤 close하면 끝남).
- 처리(2026-11-27): 이 시험은 미리보기 경로만 보므로 Vite 서버를 만들 때 `optimizeDeps: { noDiscovery: true, include: [] }`로 의존성 탐색을 끈다. 시험만 바꿨고 앱 설정은 그대로다. 캐시가 있을 때 2번, 캐시를 치운 상태에서 1번 통과했고, 전체 시험 403개가 제한 시간 안에 끝났다.

- IMP-023 셋 다 고친다: 앱 셸 밖 화면을 `<main class="bare-main">`으로 감쌌다. 전역 `main`의 여백·높이·안쪽 스크롤과 본문 최대 너비는 `bare-main`에 쓰지 않아 화면 모양은 그대로다. 공개 포트폴리오는 안쪽 `main`을 `div`로 바꿔 `main`이 하나만 남게 했다. 점검·권한 안내·재설정 화면의 큰 제목은 h1로 바꾸되 예전 제목 크기(22px·17px·18px)를 유지했다. 떠 있는 채팅 창 제목은 다른 화면 위에서는 h2, 채팅 화면(`/chat`)에서는 이 창이 본문이라 h1이다. 접근성 구조 다시 읽기: 106개 경로에서 `main` 없음 0, h1 없음 0, h1 2개 0. 수정 중 채팅 창 제목 선택자를 바꾸면서 멘션함·태그함 제목(같은 `.chat-page-head h1`을 쓴다)의 모양이 바뀐 것을 화면 비교로 찾아 함께 맞췄다.
- IMP-024 작은 버튼부터 누르는 영역만 44px: 보이는 크기는 두고 투명한 `::after`로 누르는 영역만 넓혔다. 아이콘 버튼(`.person-info`: 알림 삭제, D-Day 고정, 담당자 프로필 등)은 44×44, 한 줄에 이어진 글자 버튼·링크(멘션·태그함의 대화 열기·읽음 표시·태그, WBS 펼침, 카드 머리의 "플래너 열기 →" 같은 버튼, 위키 경로, 시작 구성 적용 체크)는 높이만 44px로 넓혀 옆 대상과 겹치지 않게 했다. 넓힌 영역 안의 점이 대상에 닿는 비율은 10~43%에서 100%가 됐다. 휴대폰(iPhone 13 에뮬레이션)에서 실제로 누를 수 있는 너비·높이가 24px보다 작은 대상은 92개(14개 경로)에서 46개(7개 경로)로 줄었다. 남은 것은 IMP-026에 적었다.
- IMP-025 비어 있으면 닫고, 쓰던 게 있으면 둔다: 새 글 작성·커뮤니티 만들기는 열 때의 입력과 같으면 화면이 바뀔 때 닫고, 쓴 내용이 있으면 열어 둔다. 프로필 창은 보기 전용이라 화면이 바뀌면 닫는다. 주소로 여는 `/community/new`·`/address/profile`은 주소를 옮긴 뒤 창을 열어 곧바로 닫히지 않게 했다. 뒤로 가기 시험: 빈 창은 닫히고, 제목을 쓴 새 글 작성과 이름을 쓴 커뮤니티 만들기는 쓴 내용과 함께 남는다.
- 수정 전후 화면 비교(106개 경로 × 390·1440px): 앱 셸 밖 화면과 나머지 화면이 픽셀 단위로 같다. 다른 곳은 시각(초) 표시와, 같은 빌드끼리도 달라지는 일간 통계 영역뿐이다.

## 대신한 점검과 확인하지 못한 것

- 화면 읽기 프로그램(NVDA·VoiceOver)으로 실제로 읽어 보기: 이 환경에 없어 접근성 구조 읽기로 대신했다.
- 실기기·실제 Safari·Capacitor·Electron 앱: 이 환경에 없어 Chromium 기기 에뮬레이션으로 대신했다.
- 비밀번호 재설정 메일: 화면이 서버를 부르지 않고 메일 서비스가 연결되지 않아 시험할 흐름이 없다.
- 커뮤니티 챌린지·랭킹, 그룹 채팅, 파일 기간 변경·삭제, 강제 로그아웃 버튼은 실제 백엔드로 누르지 않았다.
- 정식 KWCAG·OWASP 점검이 아니다.
