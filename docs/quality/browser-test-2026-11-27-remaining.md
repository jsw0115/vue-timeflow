## 점검 범위와 방법

- 도구: 컨테이너에 설치된 Chromium(Playwright). 이 세션에도 Claude in Chrome 확장이 없다. 화면 점검은 `vite preview`(프로덕션 빌드)로, 실제 백엔드 점검은 격리 MySQL 8.4·Redis 7.4(`infra/chat/compose.yml`)와 `chat-local` 백엔드, `vite` 개발 서버로 했다. 운영 DB는 쓰지 않았다.
- 실제 글꼴: 이 환경은 `cdn.jsdelivr.net`이 막혀 있다. 그래서 npm의 `pretendard@1.3.9` 패키지에 든 같은 CSS·글꼴 파일을 세션 임시 폴더에 받고, 브라우저가 그 주소를 요청하면 이 파일로 대신 줬다. 저장소 의존성은 바꾸지 않았다.
- 실제 백엔드: 점검용 계정 A·B·C·D와 관리자 계정 2개를 새로 만들었다. 관리자 역할은 격리 DB에서만 바꿨다.
- 화면 읽기 프로그램 대신: 106개 경로의 접근성 구조(페이지 제목, h1, `main`·`nav` 랜드마크, 현재 메뉴 표시, 중복 id, alt 없는 이미지)를 읽었다. 실제 화면 읽기 프로그램 결과는 아니다.
- 실기기 대신: Playwright의 기기 설정(Pixel 7, iPhone 13, Galaxy S9+, iPad Mini)으로 Chromium을 띄웠다. 실제 기기·실제 Safari 결과는 아니다.

## 찾은 버그

<a id="bug-015"></a>
### BUG-015. 서버에서 세션이 끝나면 안내 없이 로그아웃 상태가 되고 시연 기록이 보임 (P2)

- 화면: 로그인 상태의 모든 화면.
- 재현: 계정 D로 로그인해 할 일 화면을 연다. 관리자가 D를 정지한다(모든 기기 로그아웃). D의 탭을 새로 고친다.
- 실제: 요청이 401을 받고 토큰 갱신(`/api/auth/refresh`)도 401이면 `clearSession()`이 조용히 세션을 지운다. 사이드바는 "로그인 · 기록을 계정에 저장하려면 로그인하세요"로 바뀌고, 메모 화면에는 이 브라우저의 시연 메모 4건이 보인다. 왜 로그아웃됐는지, 다시 로그인하라는 안내가 없다.
- 영향: 정지뿐 아니라 강제 로그아웃·refresh 토큰 만료에도 같은 경로를 탄다(`features/auth/session.js`의 `refresh()` 실패 처리). 사용자는 시연 기록을 내 기록으로 착각하거나, 이어서 쓴 기록이 계정이 아니라 이 브라우저에 저장될 수 있다.
- 근거: 실제 백엔드에서 관리자 화면으로 정지해 재현했다. 같은 탭에서 새로고침 없이 화면만 옮겼을 때는 이미 받은 목록을 그대로 보였다.
- 권장: 갱신 실패로 세션을 지울 때 "로그인이 끝났어요. 다시 로그인해 주세요." 같은 안내를 보이고 로그인 화면으로 안내한다. 정지 사유는 로그인할 때 서버 문구("비활성화된 계정입니다.")로 보인다.

<a id="bug-016"></a>
### BUG-016. 모든 화면의 페이지 제목이 같음 (P2, 접근성)

- 화면: 106개 경로 전부.
- 실제: 브라우저 탭 제목(`document.title`)이 어느 화면이든 "Timebar Diary · 계획과 실제 기록"이다. `index.html`의 `<title>`만 있고, 화면을 옮길 때 제목을 바꾸는 코드가 없다.
- 영향: 화면 읽기 프로그램은 화면을 옮길 때 페이지 제목을 먼저 읽으므로, 어느 화면에 왔는지 알 수 없다. 탭이 여러 개일 때도 구분하기 어렵다. 웹 접근성 점검 항목 6.4.2(제목 제공)에 해당한다([점검 항목](../../security/WEB_ACCESSIBILITY_KWCAG22_33.md)).
- 권장: 라우터 이동 뒤 화면 이름(사이드바 이름, 본문 언어)으로 `화면 이름 · Timebar Diary`를 붙인다.

## 대신한 점검과 확인하지 못한 것

- 화면 읽기 프로그램(NVDA·VoiceOver)으로 실제로 읽어 보기: 이 환경에 없어 접근성 구조 읽기로 대신했다.
- 실기기·실제 Safari·Capacitor·Electron 앱: 이 환경에 없어 Chromium 기기 에뮬레이션으로 대신했다.
- 비밀번호 재설정 메일: 화면이 서버를 부르지 않고 메일 서비스가 연결되지 않아 시험할 흐름이 없다.
- 커뮤니티 챌린지·랭킹, 그룹 채팅, 파일 기간 변경·삭제, 강제 로그아웃 버튼은 실제 백엔드로 누르지 않았다.
- 정식 KWCAG·OWASP 점검이 아니다.
