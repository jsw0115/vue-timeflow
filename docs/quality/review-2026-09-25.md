# 3단계 보안·검증 기록

대상: API 설계 문서, API 목록 생성기, Vue 개발용 PC·모바일 미리보기, Vite 설정, 앱 진입 HTML.
세 번의 독립 검토 관점으로 진행했다. 외부 침투테스트나 전체 서비스 보안 인증을 뜻하지 않는다.

## 1차 — 기능·소스 정합성

- 현재 Controller 매핑 자동 추출: 89개(서비스 연결32, 계약 stub52, 공용 메모리 시연5).
- npm run build:web 성공: 172 modules. 기존 단일 JS chunk 약618KB 경고는 남음.
- npm run check:preview 3/3 통과: 입력 경계/개발 HTTP+프록시/운영 HTML 분리.
- 프록시 시험은 임시 loopback mock HTTP 서버를 사용했고 Authorization 헤더와 경로·쿼리 전달을 검증했다.
- 목표 /api/v1과 기존 /api를 문서에서 구분. 새 API를 구현 완료로 표기하지 않았다.

## 2차 — 보안·경계

- npm --prefix frontend audit --json: 알려진 취약점 total0 (검사일 기준, dev 포함).
- iframe 대상은 고정 allowlist. 외부 URL, javascript:, //host, /api, 관리자, /__preview 자기 참조는 기본 홈으로 복원.
- 미리보기 HTTP write 요청405, no-store/nosniff, frame-src self. 새 창 rel=noopener noreferrer.
- 기본 Vite host127.0.0.1, LAN은 별도 dev:lan으로 명시적으로 활성화. allowedHosts=true / cors=true / TLS검증 해제 없음.
- 개발 페이지는 public 폴더 밖, plugin apply:serve, 운영 HTML에 참조 없음.
- 발견 및 수정: 앱 index.html에 viewport가 없었음 → viewport/lang/charset/title 추가.
- 보안 검토 중 기존 백엔드 관리자 역할 검사 누락, 공용 메모리 플래너 사용자 구분 없음 확인. API 설계서에 출시 차단 항목으로 기록. 이번 변경은 해당 백엔드 API를 활성화하거나 구현하지 않음.

- 기존 application.yml에 비밀번호 literal 설정이 있음을 확인(값은 기록하지 않음). 운영 전 환경변수/비밀 저장소로 이동하고 노출 여부에 따라 교체 필요. 이번 프런트엔드·문서 작업은 해당 비밀을 복사하지 않음.

## 3차 — 최종 회귀

- 최종 Vue 운영 빌드 성공: 172 modules, viewport/lang 포함, 미리보기 도구 참조 없음.
- 최종 자동 테스트 3/3 통과, 실패0.
- node scripts/api-inventory.mjs --check: 현재 89개 경로와 목록 일치.
- node scripts/check-design-docs.mjs: 문서10개·로컬 링크25개·목표 API114개·미리보기 경로14개 검증 성공. 목표 API ID/메서드+경로 중복 없음.
- 중간 회귀에서 포트5173 사용 중 충돌 발견. 테스트 서버를15173부터 빈 포트 선택으로 변경하고, configFile/root를 절대경로로 고정해 작업경로 의존성도 제거. 수정 후 재검증 통과.
- 개발 서버·사용자 DB를 중지하거나 초기화하지 않았다.

## 검증 범위와 제한

현재 호스트 Node20.18/npm10.8에서 빌드와 자동 테스트를 실행했다. 프로젝트 선언은 Node>=22.12이므로 정상 개발 환경은 해당 선언을 따른다. 네이티브/Electron 테스트까지 통과했다고 주장하지 않는다.
브라우저 도구에 연결된 브라우저가 없어 시각 렌더링과 클릭 검증은 미실시. Android/iOS 실기기·Electron 실행도 미실시.
MariaDB·Flyway 기동, 사용자 데이터 변경, 운영 배포는 수행하지 않았다.
현재 앱은 샘플/브라우저 저장을 포함하며 로그인 화면은 서버 인증과 아직 연결되어 있지 않다.
