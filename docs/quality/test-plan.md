## 테스트 층과 환경

단위·서비스·MockMvc는 입력·권한·업무·응답 계약을, H2는 지정 영속 로직을, 실제 MySQL·Redis·브라우저는 설치·방언·동기화·프록시를 확인합니다. 한 층의 성공이 다른 층의 검증을 대체하지 않습니다.

격리 DB와 테스트 계정 A·B·ADMIN을 사용합니다. 운영 데이터·비밀값을 테스트에 복사하지 않습니다. 브라우저 프로필을 분리하고 같은 출처의 두 미리보기 프레임을 서로 다른 계정으로 간주하지 않습니다. 시간대·자정·기간·반복·모바일·키보드와 실패 복구를 포함합니다.

## 실행 명령

프로젝트가 요구하는 Node와 JDK를 먼저 확인합니다. npm test 스크립트는 없으므로 실제 Node 테스트 명령을 사용합니다.

```powershell
# backend에서 실행합니다.
.\gradlew.bat test bootJar --console=plain

# frontend에서 실행합니다.
npm ci
npm run build:web
$testFiles = (Get-ChildItem tests/*.test.mjs).FullName
node --test --test-concurrency=1 $testFiles
npm run build:pages

# 프로젝트 루트에서 실행합니다.
node frontend/scripts/api-inventory.mjs --check
node frontend/scripts/frontend-api-contract.mjs --check
python scripts/docs/build_current_database.py --check
python scripts/docs/build_screen_catalog.py --check
python scripts/docs/verify_documentation.py
```

backend의 좁은 테스트는 `--tests`로 해당 클래스를 선택할 수 있습니다. 기존 테스트는 H2·mock·서비스 단위 범위도 포함합니다. 실제 DB·UI 스크립트는 `scripts/chat/`, `scripts/database/`와 해당 날짜의 기록을 읽고 격리 환경을 준비한 뒤 실행합니다. 임의 운영 DB에 검증 데이터를 쓰지 않습니다.
