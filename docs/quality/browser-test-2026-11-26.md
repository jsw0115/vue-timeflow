# 전체 화면 브라우저 점검 결과 (2026-11-26)

작성일 2026-11-26. 수정일 2026-11-26. 다국어(PR-32) 16단계와 사용자 결정 5건을 반영한 뒤, 라우터의 모든 화면을 브라우저로 열어 본 결과다. 가짜 API로 확인했으며 실제 백엔드·운영 환경·실기기 확인이 아니다. 버그 번호는 [날짜별 원장](../releases/backlog.md)과 같고, 실행 기록은 [dev-docs 07 RUN-288](../dev-docs/07-테스트-시나리오-및-결과서.md#실행-결과-기록)이다. 버그 수정 확인은 RUN-289, 개선(IMP-015~IMP-018) 확인은 RUN-290이다.

## 점검 범위와 방법

- 도구: 컨테이너에 설치된 Chromium(Playwright)과 `vite preview`(프로덕션 빌드). 이 세션에는 Claude in Chrome 확장이 없고, 앱이 클라우드 컨테이너 안에서 돌아 사용자 PC의 Chrome으로는 열 수 없었다.
- 화면: 라우터의 106개 경로. 정적 경로, `/settings/` 15개 구역, ID가 붙는 경로의 예시(`/dday/1`, `/tasks/1`, `/share/groups/1`, `/screens/PLAN-001`, `/p/abc`), `/legal?doc=이용약관`을 포함한다.
- 조건 5가지:

| 이름 | 너비 | 표시 언어 | 로그인 | 가짜 API |
|---|---:|---|---|---|
| ko-1440-out | 1440px | 한국어 | 아니오 | 모든 요청 401 |
| en-1440-out | 1440px | 영어 | 아니오 | 모든 요청 401 |
| en-320-out | 320px | 영어 | 아니오 | 모든 요청 401 |
| en-1440-in | 1440px | 영어 | 예 | 표시 언어·집중 기록·알림·관리자 통계만 실제 모양, 나머지 404 |
| ko-390-in | 390px | 한국어 | 예 | en-1440-in과 같음 |

- 화면마다 확인한 것: 페이지 오류(잡히지 않은 예외)와 콘솔 오류, 가로 넘침, `<html lang>`, 영어 화면에 남은 한글, 글자와 배경의 대비(일반 글자 4.5:1, 큰 글자 3:1 미만), 이름 없는 버튼·링크, 라벨 없는 입력칸, 본문이 비어 있는 화면.
- 따로 눌러 본 동작: 같이 집중 주 버튼 색, 약관 뷰어 탭 전환과 `?doc=` 주소, 통합 검색(영어·한국어), 환경 설정에서 언어 바꾸기, 새 글 작성 창 열기와 Esc로 닫기. 로그인 상태에서 목록 API가 404·500으로 실패할 때 화면 10개가 오류를 알리는지도 봤다.

## 찾은 버그와 처리

아래 다섯 건은 점검에서 찾은 뒤 같은 날 고쳤다. 다시 연 결과는 [07 RUN-289](../dev-docs/07-테스트-시나리오-및-결과서.md#실행-결과-기록)에 있다.

<a id="bug-007"></a>
### BUG-007. 기록 목록을 불러오지 못해도 빈 목록으로 보임 (P2) — 완료

- 화면: D-Day(`/dday`), D-Day 관리(`/events/dday`), 메모(`/memos`), 다이어리(`/diary`), 머니로그(`/money`).
- 재현: 로그인한 상태에서 목록 API가 404 또는 500으로 실패하게 한 뒤 화면을 연다.
- 기대: 할 일·일정·루틴·업무 위키·WBS처럼 "불러오지 못했어요"와 다시 시도 버튼을 보인다.
- 실제: "표시할 항목이 없어요", "조건에 맞는 메모가 없어요" 같은 빈 상태 문구만 보인다. 사용자는 자료가 없어진 것으로 오해할 수 있다.
- 근거: 같은 기반(`createFeatureStore` → `useRecordCollection`)의 `state.error`를 할 일·일정 화면은 보이고, 위 다섯 화면은 쓰지 않는다.
- 권장: 다섯 화면에 할 일 화면과 같은 불러오기 실패 상태(문구·다시 시도)를 더한다.
- 처리(2026-11-26): 공통 부품 `components/ListLoadState.vue`와 `features/records/listLoadState.mjs`를 만들어 다섯 화면에 "…를 불러오는 중이에요"·"…를 불러오지 못했어요"와 다시 시도를 넣었다. 그동안 빈 목록 문구는 숨긴다. 404·500 모두 10개 화면이 실패를 알리고, 다시 시도를 누르면 요청을 다시 보낸다.

### BUG-008. 업무 히스토리의 고정 예시 값에 시연 표시가 없음 (P2) — 완료

- 화면: 업무 히스토리(`/work/history`).
- 실제: 업무 유형 4개(누적 255시간)와 인수인계 문서 2건이 `WorkHistoryView.vue`에 고정돼 있다. 로그인 상태에서도 그대로 보이고 시연이라는 표시가 없다.
- 기대: 실제 기록에서 집계하거나, 집계 전까지 시연 예시라고 밝힌다(DESIGN.md "신뢰" 원칙).
- 권장: 다른 시연 화면처럼 시연 표시를 붙이고, 실제 집계는 별도 작업으로 정한다.
- 처리(2026-11-26): "업무 유형별 누적 시간과 인수인계 문서 목록은 시연용 예시예요…" 시연 표시를 붙였다. 실제 집계는 아직 없다.

placeholder만 있거나 아무 이름이 없어 화면 읽기 프로그램이 무엇을 입력하는지 알 수 없다(DESIGN.md "placeholder를 label 대용으로 사용하지 않는다").

<a id="bug-010"></a>
### BUG-010. 글양식 설정 스위치의 켜짐·꺼짐이 보조기기에 전달되지 않음 (P2, 접근성) — 완료

- 화면: 글양식 설정(`/settings/forms`).
- 실제: 항목마다 있는 스위치가 `<button class="switch">`이고 켜짐은 `on` 클래스(모양)로만 표시한다. `role="switch"`·`aria-checked` 또는 `aria-pressed`가 없다. 이름은 감싼 `<label>`에서 얻는다.
- 기대: DESIGN.md 호환 클래스 표의 Switch(`role="switch"` + 이름)처럼 상태를 함께 전달한다.
- 위치: `views/settings/SettingsFormStyleView.vue` 160~167행.
- 처리(2026-11-26): `role="switch"`와 `aria-checked`를 붙였다. 접근성 트리에서 `switch "카테고리 …" [checked]`로 읽히고, 누르면 checked가 바뀐다.

<a id="bug-011"></a>
### BUG-011. 약관 뷰어의 뒤로 가기 화살표가 키보드로 닿지 않음 (P2, 접근성) — 완료

- 화면: 약관 뷰어(`/legal`).
- 실제: 머리글의 "←"가 `<span @click>`이라 Tab으로 갈 수 없고 이름도 없다. 아래의 "확인했어요" 버튼으로는 돌아갈 수 있다.
- 근거: 마크업 확인(`views/legal/LegalViewerView.vue`). 화면 읽기 프로그램으로 실제 확인하지는 않았다.
- 권장: `aria-label`이 있는 버튼으로 바꾼다.
- 처리(2026-11-26): "뒤로 가기" 이름이 있는 버튼으로 바꿨다. 이전 기록이 없으면 "확인했어요"처럼 홈으로 간다. Tab으로 가서 Enter로 누를 수 있는 것을 확인했다.

- 남은 차이: 새 루틴 만들기 창의 단위 입력칸은 처음 값이 '회'로 들어 있어 영어 화면에서도 '회'가 보인다. 입력칸 값은 그대로 저장되므로 화면용 번역을 넣지 않았다. 목록·충돌 비교에서는 "1 time"처럼 보인다.

## 오탐으로 판단한 것

- `/settings/forms` 스위치 3개를 처음에는 "이름 없는 버튼"으로 셌다. 버튼을 감싼 `<label>`에서 이름을 얻으므로 이름 문제는 아니다. 상태 전달 문제만 BUG-010으로 남겼다.
- `/chat`은 1440px에서 본문에 "채팅은 이동 가능한 대화 버튼에서 열 수 있어요." 한 줄만 보인다. 채팅을 떠 있는 창으로 여는 설계다.
- `/planner`, `/community/new`, `/chat/room`, `/address/profile`은 다른 주소로 바로 넘어간다. `/planner`는 라우터가 마지막으로 본 플래너 보기로 보낸다. 나머지 셋은 화면이 열리면서 주소를 바꾼다: `/community/new`는 만들기 창을 띄우고 커뮤니티 목록으로, `/chat/room`은 채팅으로, `/address/profile`은 프로필 창을 띄우고 주소록으로 간다.
- 처음 집중 화면이 비어 보인 것은 가짜 응답에 기록 API의 `serverTime` 대신 다른 이름을 넣었기 때문이다. 바로잡은 뒤 정상으로 보였다(07 RUN-287).
