## 문제와 제공 가치

시간 기록·공고·경력 문서·연구 자료가 흩어져 있어 사용자가 무엇을 바꾸고 실제로 무엇을 해야 할지 연결하는 비용이 큽니다. Timebar Diary는 계획·실제 기록·업무·경력을 기반으로, 근거가 있는 제안을 사용자가 승인한 행동과 결과물로 이어주는 경험을 검증합니다.

무료 핵심 가치는 개인 계획과 기록의 보관·검토입니다. 유료 후보 가치는 개인 자료와 외부 변화를 비교한 분석, 문서 수정 제안, 실행 후 갱신입니다. 사업적 차별화는 AI 모델 자체의 독점성보다 사용자가 확인한 근거·문서·행동의 연결에서 검증합니다.

고용·미래 업무의 공식 자료와 경쟁 제품 분석은 [시장·사용자 분석](../product/ai-growth-2026-10-31/01-시장과-사용자.md), [근거 자료](../product/ai-growth-2026-10-31/sources.md)에서 관리합니다. 같은 수치와 경쟁 기능 표를 이 문서에 다시 복제하지 않습니다.

## 고객과 시장 접근

| 순서 | 고객 | 얻으려는 결과 | 접근·검증 방법 |
| --- | --- | --- | --- |
| 첫 개인 실험 | 기존 경험이 있는 직무 전환자·재직자 | 경험을 근거로 지원·성과 문서를 개선 | 접근 가능한 소프트웨어·데이터 커뮤니티에서 실제 문서·4주 작업 관찰 |
| 병행 소규모 실험 | 공학·컴퓨터과학 연구자 | 문헌 비교를 실험·집필 계획과 연결 | 분야 검토자가 있는 소규모 모집, 취업 흐름과 분리 평가 |
| 후속 개인 확장 | 취준생·프리랜서·경력 복귀자·현장 종사자 | 작은 결과물·제안서·경력·자격 준비 | 사용자 제약과 입력 방식별 사용성 검증 |
| 기관 확장 | 코치·교수·취업지원기관·소규모 팀 | 동의한 목표와 결과물 검토 시간 절약 | 개인 가치 검증 후 유상 파일럿·권한·계약 검토 |

현재 유료 가입자·활성 사용자·매출·TAM은 측정하지 않았습니다. 전체 취업자 수에 임의 전환율을 곱한 시장 규모를 제시하지 않습니다. 도달 가능한 채널의 단계별 조건부 전환율과 실제 결제·환불을 측정합니다.

첫 모집에서는 광고 규모 확대보다 최근 작성한 문서·사용 중인 도구·결과를 만드는 과정의 불편을 확인합니다. 샘플 분석과 내보내기로 전환 비용을 낮추고, 기록을 가두거나 취업 불안을 자극해 결제시키지 않습니다.

## 수익·비용과 운영

무료·개인 유료 한 종류와 짧은 기간 이용권을 먼저 검증합니다. 가격 가설 9,900원·14,900원, 사용 단위·자동 갱신 동의·공헌이익 산식은 [제품·유료화 설계](../product/ai-growth-2026-10-31/02-제품과-유료화-설계.md#가격과-원가를-검증하는-방법)에서 단일 관리합니다.

| 구분 | 관리할 비용·수입 | 확인 시점 |
| --- | --- | --- |
| 수입 | 실제 결제, 세금·수수료·환불 반영 순수입 | 상품 실험과 월별 대사 |
| 변동비 | 모델·검색·데이터·파싱·저장·작업 재시도·고객 지원 | 작업별 및 사용자별 평균·상위 사용량 |
| 고정비 | 개발·디자인·분야 검토·운영 인력, 기본 서버와 도구 | 월 예산·개발 계획 수립 |
| 확보 비용 | 모집·콘텐츠·광고·기관 영업과 지원 시간 | 채널·집단별 실제 유료 전환 |
| 유지 비용 | 데이터 이용권·보안·장애 복구·결제·개인정보 문의 | 유료 베타 전과 정기 검토 |

손익분기 유료 사용자 수는 `월 고정비 ÷ 사용자당 월 공헌이익`으로 시나리오를 비교합니다. 공헌이익이 0 이하인 상품은 판매량만 늘려 해결되지 않습니다. 실제 견적과 사용량이 없으므로 숫자 매출 전망을 확정하지 않습니다. 매출·현금 유입·이익을 구분하며 연간 선결제를 월 수익과 혼동하지 않습니다.

초기에는 외부 모델 API와 비공개 작업자로 시작하고 GPU 도입은 총비용·품질·데이터 반출 조건을 확인한 뒤 결정합니다. 별도 AI 서버는 독립 배포·작업 복구를 위한 구성일 수 있으며 자체 모델 학습을 뜻하지 않습니다.

## 사업 검증과 중단 기준

1. 개인 문제 검증을 통과한 뒤 분석·행동 연결을 시험합니다.
2. 분야별로 첫 유효 결과, 승인·실행·결과물 연결과 반복 사용을 측정합니다.
3. 실제 제공 가능한 유료 베타에서 결제·환불·문의·사용량을 측정합니다.
4. 자료 이용권·품질·권한·결제 일관성과 공헌이익을 확인한 뒤 규모를 늘립니다.

실험 규모·지표의 예시와 분야별 분모는 [제품 검증 기준](../product/ai-growth-2026-10-31/02-제품과-유료화-설계.md#실험과-출시-판단)을 따릅니다. 목표를 달성해 떠난 사용자와 불만족 이탈을 구분합니다. 취업률·논문 게재를 다른 조건을 통제하지 않은 제품 성과로 홍보하지 않습니다.

자료 권리가 불분명하거나, 허위 경력·가짜 인용·타인 자료 노출·이중 차감이 발생하면 해당 기능 확대를 중단합니다. 비용 상한을 지킬 수 없으면 범위·한도·가격을 수정하고 무제한 약속을 하지 않습니다.

## 확장과 주요 위험

기관 유료화는 개인 사용자의 동의를 받은 검토·피드백부터 시작합니다. 기관이 결제했다고 개인 기록 전체에 접근하게 하지 않습니다. 채용 평가·조직 감시로 확장하는 것은 별도 제품·법적 검토가 필요한 범위입니다.

| 위험 | 대응 | 책임 역할 |
| --- | --- | --- |
| 범용 AI·공공 서비스와 경쟁 | 기존 도구 대비 실제 실행·문서 갱신 가치 검증 | 기획 |
| 취업 준비의 짧은 이용 기간 | 기간 이용권·목표 달성 후 자연스러운 종료 허용 | 제품·사업 |
| 연구 분야별 품질 차이 | 별도 파일럿·분야 검토·허용 자료 제한 | 도메인 검토 |
| 데이터 공급·모델 정책 변경 | 공급자 어댑터·권리 장부·비용 상한·중지 스위치 | 개발·운영 |
| 운영과 고객 지원 부담 | 지원 범위·복구·환불·삭제 절차를 베타 전에 마련 | 운영 |

일정과 버전은 [WBS](wbs.md), 실제 계획 변경과 의사결정 날짜는 [작업 원장](../releases/backlog.md)에 남깁니다. 사업 가설을 기능 구현 완료나 계약 확정으로 바꾸지 않습니다.
