## 산정과 작업 규칙

WBS는 Work Breakdown Structure, 즉 산출물 중심 작업 분해 구조입니다. 아래 작업 ID는 요구·작업 원장·릴리스에 연결하고 완료 증거가 있어야 체크합니다. 한 작업을 코드 작성만으로 끝내지 않고 문서·회귀 검증·필요한 migration을 포함합니다.

인력 예시는 개발 2명과 일부 시간의 디자인·분야 검토 지원입니다. 표의 MD는 person-day의 초기 추정이며 1MD는 한 사람이 하루 작업하는 단위입니다. 병렬 가능성·리뷰·승인 대기는 별도이므로 MD 합계를 달력 일수로 바로 바꾸지 않습니다. 실제 담당자와 최종 추정은 착수 때 정합니다.

## 검수와 일정 변경

각 작업의 상태는 대기·진행·검토·완료·보류로 관리합니다. 완료일과 증거를 [날짜별 작업 원장](../releases/backlog.md)에 기록합니다. 산출물이 미완성이거나 필수 테스트가 실패하면 완료로 바꾸지 않습니다.

릴리스 문서는 [버전·릴리스 관리](../releases/README.md)를 따릅니다. 목표 날짜가 지나면 자동 완료하지 않고 실제 상태·원인·새 목표·영향 버전을 남깁니다. 같은 요구가 두 WBS에 걸치면 공통 산출물과 단계별 완료 기준을 명시해 이중 진척 계산을 피합니다.

추가 요청은 영향 분석 후 WBS 작업을 추가하고 기존 기간·MD·의존성을 다시 봅니다. 확정된 범위 변경은 요구사항 변경일과 릴리스 노트에 함께 연결합니다.
