## 기록 규칙

`REQ-F`는 기능, `REQ-N`은 품질·운영 요구입니다. 상태는 구현 완료라는 단일 값 대신 서버·화면·외부 연동·검증의 차이를 적습니다. 우선순위 P0는 데이터·권한·결제 피해 차단, P1은 핵심 흐름, P2는 확장·편의입니다. 목표 버전은 계획이며 실제 릴리스일은 [릴리스 원장](../releases/README.md)에만 확정합니다.

아래 테스트 ID는 [테스트 케이스](../quality/test-plan.md)에 정의합니다. 테스트 케이스가 있다는 것과 이번 문서 작업에서 실제 실행했다는 것은 다릅니다.

## 추적과 변경

요구 ID는 삭제 후 재사용하지 않습니다. 변경일·변경 이유·영향 API/화면/DB·승인 역할·목표 버전을 [작업 원장](../releases/backlog.md)에 추가하고 [WBS](wbs.md)에 연결합니다. 폐기한 요구도 폐기 이유와 대체 ID를 남깁니다.

검수 실패는 증상·재현 조건·기대 결과·실제 결과·증거·수정 버전·회귀 테스트로 등록합니다. 문서 수정만으로 기능 요구를 완료 처리하지 않습니다. 실행 증거는 [검증 기록 목록](../quality/test-plan.md#검증-증거와-한계)을 따릅니다.
