# 테스트 설정 충돌로 인한 기동 실패 수정 계획.

## 목표.

첨부 로그의 `FeatureTestConfig`와 `PlannerPersistenceTest.Config` 사이 `dataSource` 중복 등록을 재현하고, 테스트 클래스가 실행 classpath에 포함되어도 일반 애플리케이션 설정을 오염시키지 않도록 수정한다.

## 진행 순서와 검증.

1. 실제 실행 설정과 테스트 설정을 조사하고 일반 기동 경로의 회귀 테스트를 작성한다. 수정 전 첨부 로그와 같은 빈 충돌이 발생하는지 확인한다.
2. 원인에 필요한 최소한의 설정만 변경한다. 기존 SQL/JPA 테스트가 명시적으로 설정을 로딩하는 동작을 유지한다.
3. 회귀 테스트와 관련 영속성 테스트, 전체 백엔드 검사를 실행한다. 가능한 경우 격리된 DB로 실제 서버 기동과 health 응답도 확인한다.
4. 검증 명령과 한계를 기록하고 이번 변경만 커밋한다.

## 범위.

- 빈 덮어쓰기 허용으로 충돌을 감추지 않는다.
- 기존 사용자 변경과 UI는 수정하지 않는다.
- 실사용 DB의 데이터와 스키마를 임의로 변경하지 않는다.
