# 문서 정리 작업 맥락

## 2026년 10월 31일

- 요청은 docs 폴더의 주제별 한국어 Word 문서 작성이다. 앱 기능이나 실행 설정은 변경하지 않는다.
- 신규 개발자가 현재 구현과 과거 목표 설계를 혼동하지 않도록 소스 근거를 우선한다.
- Word 필드는 CREATEDATE, SAVEDATE, TOC를 사용하고 Heading 스타일과 필드 갱신 안내를 포함한다. 날짜는 문서 자체의 생성 및 저장 시각이며 코드 릴리스 날짜와 다르다.
- 패키지 버전은 웹과 API 모두 0.1.0이며 Git 태그는 없다. 별도 정식 릴리스 번호를 만들어 내지 않는다.
- 기존 사용자 변경은 AGENTS.md, PlannerItemQueryRepositoryImpl.java, Modal.vue 및 미추적 파일들이다. 이번 작업 대상에서 제외한다.
- GitLab Pages와 Linux 컨테이너 배포를 구분한다. 화면의 로컬 저장과 백엔드 구현은 별개다.
- 후속 요청으로 실제 실행 및 오류 해결을 범위에 추가했다. 기본 설치 Node는 20.18.0으로 프로젝트 요구 22.12 이상에 미달한다. JDK는 17.0.12, Docker Compose는 2.29.2다. Docker 접근은 샌드박스 밖에서 재확인한다.
- Word 제작은 관리 런타임 Python과 Node를 사용했다. Windows 번들에 LibreOffice가 없어 공식 MSI를 임시 폴더에 설치 없이 추출했다. 기본 샌드박스의 MSI 추출은 1603으로 실패했고 승인된 샌드박스 밖 추출은 성공했다.
- 추가 CI 명령 검증에서 예전 목표 설계 생성기의 catalog 및 current-operations가 현재 소스와 달라 Pages 검사가 실패함을 확인했다. 과거 설계 문서를 현재 내용으로 덮어쓰지 않고 CI가 최신 frontend-api-contract와 api-inventory를 검사하도록 수정했다. 최신 계약 검사는 277 operation과 190 schema를 소스와 대조한다.
- 실제 검증에서 API 시작 오류는 발견되지 않았다. 기존 개발 환경과 새로 생성한 격리 빈 DB 양쪽에서 core V6 및 chat V4 기동을 확인했다. 테스트용 브라우저 셀렉터와 204 기대값은 현재 소스를 읽어 정정한 뒤 재실행했다.
- 최종 마무리에서 Word 6개 구조 검사를 재통과했고 5173, 8080, 18080 서버 리스너가 없음을 확인했다. timeflow-chat 및 timeflow-manual-20261031 컨테이너는 중지하고 볼륨은 유지했다. 문서와 제작 도구의 변경만 별도 커밋한다.
