# 신규 개발자용 한국어 Word 문서 정리 계획

로컬 실행, 배포, 프로젝트 구조, 릴리스 이력, 기능 명세를 독립된 Word 문서로 작성하고 읽는 순서와 갱신 방법을 안내한다. 실제 소스와 실행 설정을 우선하며 목표 설계, 현재 구현, 미연결 기능을 구분한다.

1. 소스와 기존 문서, Git 이력의 근거를 확인한다. 검증은 명령어, 경로, 버전 및 구현 상태 대조로 수행한다.
2. docs/handbook에 주제별 한국어 DOCX 여섯 개와 안내 README를 작성한다. 생성일, 수정일, 목차는 Word 필드로 제공한다.
3. OOXML 필드와 문서 구조를 검사하고 전체 페이지를 렌더링하여 가독성과 잘림을 확인한다.
4. 기존 사용자 변경을 보존하고 이번 문서 변경만 의미 단위로 커밋한다. 커밋이 환경상 불가능하면 제한과 결과를 기록한다.

## 실행 검증 요청 추가

사용자가 로컬 실행 가이드를 직접 따라 실행하고 오류를 해결하도록 요청했다. 웹 단독 실행, 격리 MySQL과 Redis, API 기동, 가입 및 로그인과 채팅 HTTP 흐름을 실제로 확인한다. 발견한 문제는 최소 범위로 수정하고 관련 테스트를 실행한 뒤 여섯 매뉴얼과 Word 산출물에 반영한다. 기존 개인 DB와 기존 사용자 소스 변경은 보존한다.
