## 문서 기준선 결정

- 전체 목차는 docs/README.md, 주제별 기준·수정 계기는 project/document-register.md입니다. 현재 기능·로컬 실행은 기존 한국어 안내서 원문을 재사용하고 같은 본문을 복제하지 않았습니다.
- setup·local-platforms·cross-platform·table-design·schema-alignment·feature-design·product-spec-v2·api-specification·production의 중복 본문 9개를 기준 연결로 통합했습니다. 과거 고유 설계·검증은 날짜 있는 이력으로 남겼습니다.
- 실제 격리 설치의 28개 테이블·205개 컬럼·15개 물리 FK를 확인했습니다. 사용자 행은 포함하지 않고 Core·Chat 이력을 분리했습니다. 중지되어 있던 격리 DB만 시작하고 조사 후 다시 중지했습니다. 기존 개인 DB는 조작하지 않았습니다.
- DB 소스 해시는 운영체제 개행 차이로 실패하지 않도록 UTF-8·LF 정규화 SHA-256으로 기록했습니다. 현재 DB와 40개 목표 DDL, feature_record JSON과 독립 물리 테이블을 구분했습니다.
- 라우터 경로·플래너 매핑 86개를 생성 목록으로 관리합니다. 화면 명세는 12개 화면군과 상태·와이어프레임·흐름을 다룹니다. 경로 수와 실제 서버 연동·검증 수는 다릅니다.
- 요구는 기능 23개·품질 10개, 테스트 케이스는 44개, WBS는 14개 작업으로 추적합니다. 케이스 작성은 실제 통과 수를 늘리는 작업이 아닙니다.
- 0.1.1~0.5.0 후보와 미래 날짜는 제안입니다. 선언 버전 0.1.0·태그 없음·미배포를 유지하고 개발 중 추가·수정·완료·실배포 날짜를 분리합니다.
- Java 헤더 검사·디자인 충돌, 기본 Node, AI 준비 표시·BYOK·업로드 경계·화면 연결·운영 검수는 원장에 남겼습니다. 문서 작업을 기능 수정 완료로 표시하지 않았습니다.
- 이번 요청에는 병렬 에이전트 작업을 사용하지 않았습니다. 설치 공식 문서 확인 외에는 저장소·격리 DB 근거를 중심으로 작성했습니다.
