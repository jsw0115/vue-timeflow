## 2. 위반·고위험 항목과 조치

위험도는 "누가(로그인 여부) · 어떤 조건에서 · 무엇을 할 수 있는가"로 매겼다.

> **2, 6, 8, 9번(SEC-2.6·2.9·6.2·2.13)은 사용자 결정(2026-11-16)으로 조치하지 않았다.** 한 번 조치했다가 되돌려 소스는 점검 전과 같다. 아래 "조치" 칸은 조치할 때의 방법으로 남겨 둔다.

| 순번 | 항목 | 위험도 | 발견 내용 | 조치 |
| ---: | --- | --- | --- | --- |
| 1 | **SEC-1.11 크로스사이트 요청 위조(CSRF)** | 높음 | 로그인은 세션 쿠키로 하는데, 상태를 바꾸는 요청(회의 개설·종료·계정 변경 등)을 막는 장치가 SameSite=Lax 쿠키뿐이었다. SameSite는 같은 상위 도메인(같은 사이트)의 다른 시스템에서 보내는 요청을 막지 못한다. 은행처럼 같은 도메인 아래 시스템이 많은 환경에서는 그 중 한 곳의 화면만 오염돼도 회의관리 요청을 위조할 수 있다. | 요청 출처 검사 필터를 넣었다. POST·PUT·PATCH·DELETE는 브라우저가 붙이는 `Origin`(없으면 `Referer`)이 이 서비스 자신이거나 허용 목록일 때만 받는다. `Origin: null`은 거부, 두 헤더가 모두 없는 서버 간 호출은 통과. 외부망 WAS는 브라우저 Origin을 내부망으로 넘기지 않으므로 외부망 WAS에도 같은 필터를 넣었다. 설정: `meeting.security.csrf-origin-check`·`trusted-origins`(외부망 WAS는 `meeting.gateway.*`). |
| 2 | **SEC-2.6 하드코딩된 중요정보** — 미조치(기존 유지) | 높음 | `application-oracle.yml`(저장소에 커밋됨)에 개발 Oracle DB의 **주소·계정·비밀번호가 평문**으로 있었다. | (조치 시) 환경변수(`EZCONF_DB_URL`·`EZCONF_DB_USER`·`EZCONF_DB_PASSWORD`)로 바꾼다. **사용자 결정으로 조치하지 않았다 — 파일은 점검 전 그대로다.** |
| 3 | **SEC-1.3 경로 조작** | 높음(조건부) | 녹음 업로드에서 저장 파일 확장자를 클라이언트가 보낸 파일명의 마지막 점 뒤 문자열 그대로 썼다. `x../../../../tmp/evil` 같은 파일명을 보내면 저장 경로가 녹음 폴더 밖으로 나간다. 녹음 서버 저장(`meeting.recording.save-mode: server`)을 켠 사이트의 진행자·주최자만 도달할 수 있다(기본값은 PC 저장이라 막혀 있음). | 녹음 확장자는 허용 목록(webm·ogg·oga·m4a·mp4·wav·mp3)만 쓰고 나머지는 `.webm`으로 바꾼다. 저장 경로가 녹음 폴더 안인지 한 번 더 확인한다. 회의 자료 저장 확장자도 영문·숫자만 쓰게 했다(업로드 검사는 원래 있었지만 같은 방식으로 막아 둠). |
| 4 | **SEC-1.7 신뢰되지 않는 주소로 자동 이동** | 중간 | 로그인 화면이 `?next=` 값이 `/`로 시작하기만 하면 그대로 이동했다. `//다른사이트`, `/\다른사이트`는 브라우저가 외부 주소로 해석하므로 로그인 직후 피싱 사이트로 보낼 수 있었다. | 같은 사이트 안의 경로만 받는다 — `//`·역슬래시·제어 문자를 거부하고, 최종 주소의 출처가 자기 자신인지 확인한다. 외부망 WAS의 같은 검사(`safeNext`)에도 제어 문자·역슬래시 거부를 더했다. |
| 5 | **SEC-2.2 부적절한 인가** | 중간 | `GET /api/meetings/{id}/sync-state`(진행 중 페이지 위치)·`/presence`(참석자 명단·접속 현황)는 로그인만 하면 **참석자가 아니어도** 볼 수 있었다(QC-09와 같은 내용). | 회의 상세와 같은 규칙(참석자 또는 관리자)으로 막았다. 취소된 회의는 숨긴다. |
| 6 | **SEC-2.9 약한 비밀번호 허용** — 미조치(기존 유지) | 중간 | 자체 로그인 비밀번호는 길이(8자)만 검사했다. `12345678`도 통과했다. | (조치 시) 공공기관 개발보안 가이드 기준 조합 규칙 — 영문 대문자·소문자·숫자·특수문자 중 3종류 이상이면 8자, 2종류면 10자 이상. **사용자 결정으로 조치하지 않았다 — 길이(8자)만 검사하는 기존 동작 그대로다.** |
| 7 | **SEC-4.1 오류 메시지 정보 노출** | 중간 | ① 페이지 이미지가 없을 때 오류 응답에 **서버의 절대 저장 경로**를 실었다. ② 로그인 없이 열리는 상태 확인 주소(`/actuator/health`)가 `show-details: always`로 DB 제품명·디스크 경로·여유 용량·Valkey 버전을 보여 줬다(공통 설정·수은 운영 템플릿). | ① 응답에는 "페이지 이미지 파일이 없습니다"만 싣고 경로는 서버 로그에만 남긴다. ② `show-details: never` + `show-components: always` — 구성요소별 UP/DOWN만 보인다. 운영 스크립트 `ezconf.sh`의 판정("db=UP redis=UP")은 그대로 동작한다. |
| 8 | **SEC-6.2 디버그 코드 잔존** — 미조치(기존 유지) | 낮음~중간 | 로그인 화면 소스에 개발용 계정 목록과 공용 비밀번호(`12345678`)가 들어 있어 **운영 서버에서도 그대로 내려갔다**(화면에는 localhost에서만 보였을 뿐). | (조치 시) 계정 목록·비밀번호를 화면 소스에서 빼고 개발 계정 시드가 켜진 서버만 내려준다. **사용자 결정으로 조치하지 않았다 — 로그인 화면은 기존 그대로다.** |
| 9 | **SEC-2.13 주석에 시스템 주요 정보** — 미조치(기존 유지) | 낮음 | `application-oracle.yml` 주석에 개발 DB 서버 내부 IP·계정·비밀번호가 있었다. | (조치 시) 2번과 함께 지운다. **같은 파일이라 2번과 함께 기존 그대로 두었다.** |
| 10 | **SEC-1.13 HTTP 응답 분할** | 낮음 | 외부망 WAS가 로그인 뒤 이동 주소(`next`)를 그대로 `Location` 헤더에 썼다(제어 문자 검사 없음). 톰캣이 대부분 막지만 소스 단계 검사가 없었다. | 4번과 함께 제어 문자를 거부한다. |
| 11 | **SEC-1.1 SQL 삽입** | 낮음(보강) | 인사연동 프로시저 이름(설정값)을 SQL 문자열에 그대로 이어 붙였다. 설정을 바꿀 수 있는 사람만 도달하지만 형식 검사가 없었다. | 프로시저 이름은 `스키마.패키지.이름` 식별자 형식만 받는다(SSO 세션 뷰 이름은 원래 검사하고 있었다). |

## 3. 49개 항목 판정표

판정: **적합** / **부적합→조치** / **위험 수용 필요** / **해당 없음**. "근거"는 확인한 위치·통제 장치다.

### 3-1. 입력 데이터 검증 및 표현 (1.1 ~ 1.17)

| 번호 | 항목 | 판정 | 근거 / 조치 |
| --- | --- | --- | --- |
| 1.1 | SQL 삽입 | 부적합→조치 | 데이터 접근은 JPA(JPQL 바인딩)·Criteria API. 직접 SQL은 SSO 세션 뷰 조회(값 바인딩, 뷰 이름 식별자 검사)·인사연동 호출 2곳. 인사연동 프로시저 이름 형식 검사를 추가(2장 11번). |
| 1.2 | 코드 삽입 | 적합 | 서버에 `ScriptEngine`·SpEL `parseExpression`·`GroovyShell` 없음. 화면 스크립트에 `eval`·`new Function` 없음. |
| 1.3 | 경로 조작 및 자원 삽입 | 부적합→조치 | 녹음 저장 확장자(2장 3번). 회의 자료·페이지 이미지·다운로드는 서버가 발급한 ID로 DB에서 경로를 읽는다(사용자 입력이 경로를 정하지 않음). |
| 1.4 | 크로스사이트 스크립트(XSS) | 적합 | 화면 7개의 `innerHTML` 출력 66곳을 추적 — 사용자·서버 데이터는 모두 `esc()`/`escapeHtml()`로 HTML 이스케이프, 알림(토스트)은 `textContent`. `data-i18n-html`은 서버의 다국어 문구(신뢰 데이터)만 넣는다. JSP 없음. |
| 1.5 | 운영체제 명령어 삽입 | 적합 | 앱 코드에 `Runtime.exec`·`ProcessBuilder` 없음. 문서 변환은 jodconverter가 고정 실행 파일(LibreOffice)을 고정 인자로 띄운다. |
| 1.6 | 위험한 형식 파일 업로드 | 적합 | 확장자 허용 목록 + 파일 앞부분 시그니처 검사(`FileTypeValidator`), 저장 이름은 서버 UUID, 웹 루트 밖 저장, 크기 상한(100MB/500MB), 다운로드는 참석자 확인 + 종료 회의만 + `attachment`. |
| 1.7 | 신뢰되지 않는 URL 주소로 자동접속 연결 | 부적합→조치 | 로그인 화면 `next`(2장 4번). 서버의 `sendRedirect`는 설정 주소 또는 검사한 경로만. |
| 1.8 | 부적절한 XML 외부개체 참조 | 해당 없음 | 앱이 XML을 직접 파싱하지 않는다(`DocumentBuilderFactory`·`SAXParser` 등 없음). |
| 1.9 | XML 삽입 | 해당 없음 | XML 생성·XPath 없음. |
| 1.10 | LDAP 삽입 | 해당 없음 | LDAP 연동 없음. |
| 1.11 | 크로스사이트 요청 위조 | 부적합→조치 | 2장 1번. 웹소켓 핸드셰이크는 `meeting.sync.allowed-origins`가 따로 검사(운영 템플릿에서 지정). |
| 1.12 | 서버사이드 요청 위조 | 적합 | 서버가 부르는 주소(내부망 WAS, ezTalk 대화방 생성, 회의노트·메신저 주소 템플릿)는 모두 설정값. 사용자 입력은 주소 템플릿의 자리표시자 값으로만 들어가고 URL 인코딩된다. |
| 1.13 | HTTP 응답분할 | 부적합→조치 | 외부망 WAS `next`(2장 10번). 다운로드 파일명은 Spring `ContentDisposition`(RFC 5987 인코딩). |
| 1.14 | 정수형 오버플로우 | 적합 | 목록 크기 상한(100), 페이지 번호는 DB 조회 키로만 사용, 업로드 크기는 프레임워크 상한. |
| 1.15 | 보안기능 결정에 사용되는 부적절한 입력값 | 적합 | 권한 판단은 세션 사용자 ID + DB의 회의·계정 상태(`MeetingAccessGuard`·`DriverAuthority`·`AdminGuard`). 클라이언트가 보낸 역할 값을 쓰지 않는다. 동기화 이벤트 종류도 서버가 허용 목록으로 거른다. |
| 1.16 | 메모리 버퍼 오버플로우 | 해당 없음 | 네이티브 코드(JNI) 없음. |
| 1.17 | 포맷 스트링 삽입 | 적합 | `String.format`의 형식 문자열은 모두 상수. |

### 3-2. 보안 기능 (2.1 ~ 2.16)

| 번호 | 항목 | 판정 | 근거 / 조치 |
| --- | --- | --- | --- |
| 2.1 | 적절한 인증 없는 중요 기능 허용 | 적합 | `/api/**` 전체에 인증 인터셉터(`WebConfig`). 예외인 `/api/auth/**`는 컨트롤러가 직접 세션 확인, `/api/i18n/**`은 공개 문구. 관리 API는 인터셉터 + 컨트롤러 이중 확인. actuator는 health·info만. |
| 2.2 | 부적절한 인가 | 부적합→조치 | 2장 5번. 그 밖의 회의 상세·자료·다운로드·동기화 송신·녹음은 참석자/주최자/진행자 확인이 있다. |
| 2.3 | 중요한 자원에 대한 잘못된 권한 설정 | 적합(운영 조건) | 임시 파일은 `createTempFile`(소유자만 읽기). 저장 폴더 권한은 설치 절차서대로 실행 계정(ezconf) 소유·0750으로 만든다 — 설치 때 확인. |
| 2.4 | 취약한 암호화 알고리즘 사용 | **위험 수용 필요** | 그룹웨어 SSO 쿠키(`LOGINCOOKIE`) 복호화가 AES/CBC에 **IV를 키 앞 16자로 고정**한다. 그룹웨어가 정한 규격이라 우리 쪽만 바꿀 수 없다(복호화 전용). 그 밖의 암호화: 비밀번호 BCrypt, 캐시 키 SHA-256. → 6장 |
| 2.5 | 암호화되지 않은 중요정보 | 적합(운영 조건) | 운영은 L4에서 HTTPS + 세션 쿠키 `secure: true`(수은 템플릿). 비밀번호·SSO 쿠키 값은 로그에 남기지 않는다. 외부망 WAS ↔ 내부망 구간은 망연계 안 HTTP + 비밀 값 헤더 — 망연계 구간 암호화 여부는 은행 확인 사항(외부망 구성 확인 질의서). |
| 2.6 | 하드코드된 중요정보 | 부적합(미조치 — 기존 유지) | 2장 2번 — `application-oracle.yml`의 DB 접속 정보는 사용자 결정으로 그대로 둔다. 그 밖: 초기 관리자 `super`의 납품 기본 비밀번호(V12 시드)는 첫 로그인 때 변경을 강제하고 바꾸기 전까지 기동마다 경고 로그를 남긴다(설계상 유지). SSO 키·외부망 비밀 값·Valkey 비밀번호는 환경변수. |
| 2.7 | 충분하지 않은 키 길이 사용 | 적합 | SSO 복호화 키는 32바이트(AES-256)가 아니면 기동을 멈춘다. BCrypt 기본 강도. |
| 2.8 | 적절하지 않은 난수값 사용 | 적합 | ID는 `UUID.randomUUID()`(SecureRandom), 세션 ID는 톰캣·Spring Session. `Math.random`·`new Random` 없음. |
| 2.9 | 취약한 비밀번호 허용 | 부적합(미조치 — 기존 유지) | 2장 6번 — 길이 8자만 검사하는 기존 동작을 유지(사용자 결정). |
| 2.10 | 부적절한 전자서명 확인 | 해당 없음 | 전자서명 검증 기능 없음. |
| 2.11 | 부적절한 인증서 유효성 검증 | 적합 | `TrustManager`·`HostnameVerifier`를 바꾸는 코드 없음(JDK 기본 검증). |
| 2.12 | 사용자 하드디스크에 저장되는 쿠키를 통한 정보 노출 | 적합 | 세션 쿠키는 브라우저 종료 시 사라지는 쿠키(`http-only`). 오래 남는 쿠키는 언어 선택(`ezconf_lang`)뿐이고 중요정보가 아니다. |
| 2.13 | 주석문 안에 포함된 시스템 주요정보 | 부적합(미조치 — 기존 유지) | 2장 9번 — 2.6과 같은 파일이라 함께 그대로 둔다. |
| 2.14 | 솔트 없이 일방향 해쉬 함수 사용 | 적합 | 비밀번호는 BCrypt(솔트 포함, `{bcrypt}` 접두). |
| 2.15 | 무결성 검사 없는 코드 다운로드 | 적합 | 화면 라이브러리(sockjs·stomp·글꼴)는 앱 안에 동봉 — 외부 CDN에서 실행 중에 내려받지 않는다. |
| 2.16 | 반복된 인증시도 제한 기능 부재 | 적합 | 계정 잠금(5회 실패 → 30분) + 같은 IP 실패 제한(10분 20회 → 10분 차단) + 외부망 WAS 로그인 반복 보호. |

## 6. 후속 조치·확인 사항

1. **미조치 항목(SEC-2.6·2.13·2.9·6.2) 관리** — 사용자 결정으로 기존 소스를 유지했다. 기관 점검 도구로 재검사하면 다시 검출될 수 있으므로 점검 대응 때 사유(개발 전용 설정·개발 화면 등)를 따로 정리한다. `application-oracle.yml`의 개발 DB 비밀번호는 저장소에 평문으로 남아 있다. 지금 작업본의 `application-local.yml`(미커밋 변경)에도 개발 DB 비밀번호가 들어 있으니 커밋하지 않는다.
2. **운영 설치 때 출처 검사 확인** — L4가 `Host` 헤더를 사용자 접속 주소 그대로 넘기면 설정 없이 동작한다. L4가 Host를 내부 주소로 바꾸면 회의 개설 등이 403(`CSRF_ORIGIN_REJECTED`)이 되므로 `meeting.security.trusted-origins`(외부망 WAS는 `meeting.gateway.trusted-origins`)에 사용자 접속 주소를 넣는다. 첫 설치 화면 확인 단계에서 회의 개설이 되는지 본다.
3. **SEC-2.4 위험 수용 결정** — 그룹웨어 SSO 쿠키의 고정 IV는 그룹웨어 업체 규격이다. 은행·그룹웨어 업체에 규격 개선(요청마다 다른 IV, 인증 암호 방식)을 요청하거나 위험 수용으로 기록한다.
4. **비밀번호 정책 확인** — 지금은 길이(`meeting.account.password-min-length`, 기본 8자)만 검사한다. 은행 내부 정책(조합·변경 주기·재사용 금지)이 정해지면 다시 판단한다.
5. **운영 문서 반영** — 운영자 매뉴얼에 `meeting.security.*`와 health 응답 변경(상세 없음)을 추가한다.
6. **화면 목업** — `docs/mockup`은 이번 화면 변경을 아직 반영하지 않았다(`build-mockup.py` 재생성 필요).
