# SAST_DAST_TOOLING.md — 안전한 보안 진단 실행 가이드

## 구분
| 방식 | 목적 | 도구 후보 (설치/허가 여부는 프로젝트 확인) | 제한 |
|---|---|---|---|
| SAST | 소스·데이터 흐름 정적 검사 | SpotBugs+FindSecBugs, PMD, Semgrep, SonarQube, CodeQL | 모든 경고가 참이 아니며 미탐 존재 |
| SCA/SBOM | 라이브러리·공급망 위험 | OWASP Dependency-Check, OSV-Scanner, 사내 SCA | 취약점 데이터 업데이트 및 라이선스 확인 필요 |
| Secret scan | 소스·이력 비밀값 | Gitleaks, 사내 규칙 | 실제 비밀값을 출력하거나 외부 보내지 않음 |
| DAST | 동작 중 웹·API 취약점 | OWASP ZAP, 사내 웹 취약점 진단 | **승인된 로컬·시험 환경 한정** |
| 접근성 자동 | HTML·ARIA·대비 등 | axe-core/axe DevTools, Lighthouse, WAVE | 수동 키보드·보조기술 검사를 대체 못함 |

## 안전한 절차
1. 프로젝트·조직에서 허가된 도구와 버전, 라이선스, 외부 통신/클라우드 업로드 여부 확인.
2. 검사 범위(모듈/파일/URL)와 책임자·기간·계정·제외 경로·부하 제한 결정.
3. 최소 범위 정적 분석부터 시작. 원본 보고서에 비밀·개인정보가 있다면 외부로 전송하지 않는다.
4. 진짜 취약점/오탐/미확인을 구분하고 Jira/결함장부 등 실제 기록 위치를 남긴다.
5. 수정 후 같은 규칙·같은 환경에서 재검사. 스캔 미탐을 전체 취약점 없음으로 표현하지 않는다.

## 언어별 예
- Java/JSP: JSP 렌더링 결과 확인이 필수. `taglib`, `c:if`, `c:out`을 단순 검색만으로 보안 취약점이라 단정 금지.
- JavaScript: DOM XSS·CSP·이벤트 바인딩·서드파티 코드 검사.
- Python/기타: 취약 API, 의존성, 템플릿 자동 이스케이프, 파일/셸 호출 검사.

> 자동 실행 명령은 프로젝트에 설치되어 있는 도구와 정책을 확인한 후에만 문서화한다. 외부 DAST/침투·실제 운영 리소스 변경을 자동 실행하지 않는다.
