## 2. 항목별 결과

### A11Y-01 적절한 대체 텍스트 — 부적합 → 조치 완료

- **발견**: 회의 화면의 본문 문서 이미지(`viewer.html` `#page-img`)가 `alt=""`(꾸밈 이미지 취급)였다. 이 이미지는 회의 자료 그 자체(정보 이미지)라 화면낭독기 사용자는 무엇이 표시됐는지 알 수 없었다.
- **조치**: 페이지가 바뀔 때마다 대체 텍스트를 "자료 이름 — 전체 N쪽 중 M쪽"으로 넣는다(한국어·영어·일본어 문구 `viewer.page.alt`).
- **적합으로 본 것**: 좌측 썸네일은 "N페이지" 대체 텍스트가 있다. 그 밖의 아이콘은 글자가 함께 있는 버튼 안의 SVG이거나 `aria-label`이 있다. `<area>`(이미지 맵)·`input type="image"`는 없다.
- **한계**: 문서 이미지 속 글자 내용 자체는 대체 텍스트로 옮기지 않는다(변환된 페이지 그림). 본문 글자가 필요하면 원본 자료(종료 후 다운로드)로 제공한다.

### A11Y-02 제목 제공 — 적합

- 화면 5개 모두 `<title>`이 있고, 고른 언어와 사이트 이름 설정에 따라 바뀐다(`data-i18n-doc-title`). 회의 화면은 "회의명 — 문서 뷰어"로 회의마다 다르다.
- 화면마다 `<h1>`이 있다(로비·회의 화면·조직 관리·이벤트 이력은 1개, 로그인 화면은 로그인 폼과 비밀번호 변경 폼에 하나씩 — 한 번에 하나만 보인다).
- 공통조직도 iframe은 `title`(`orgchart.frameTitle`)이 있다.

### A11Y-03 기본 언어 표시 — 적합

- 화면 5개 모두 `<html lang="ko">`이고, 영어·일본어를 고르면 `document.documentElement.lang`이 그 언어로 바뀐다(`js/i18n.js`).

### A11Y-04 새 창 사전 안내 — 부적합 → 조치 완료

- **발견**: 로비의 "회의 입장"·자료 "보기"·"열람"(회의 화면을 팝업 창으로 엶), "회의록 작성"(회의노트 새 창), "대화방"(메신저 새 창) 버튼과, 회의 시작·종료 직후 알림의 "회의 입장"·"회의록 작성" 버튼이 누르기 전에 새 창이 열린다는 것을 알리지 않았다.
- **조치**: 새 창을 여는 버튼에 화면낭독기용 글자 "(새 창)"(`.sr-only`)과 마우스 툴팁(`title`, 예: "회의 입장 (새 창)")을 붙인다. 목록·회의 정보는 다시 그려지므로 새로 붙는 버튼을 지켜보며 붙인다(`index.html` `markNewWindow`). 대화방은 메신저 창을 여는 사이트(`messengerOpenEnabled`)에서만 붙인다. 화면 배치는 바뀌지 않는다.
- 새 창은 모두 사용자가 버튼을 눌렀을 때만 열린다(초점 이동만으로 여는 곳 없음). `target="_blank"` 링크는 없다.

### A11Y-05 레이블 제공 — 부적합 → 조치 완료

- **발견**: 입력란 옆에 레이블 글자는 보이지만 `<label for>`로 연결되지 않아 화면낭독기가 입력란 이름을 읽지 못하는 곳이 39곳, 레이블 자체가 없는(자리표시자만 있는) 곳이 7곳이었다.

| 화면 | 연결한 입력란(`label for` + `id`) | 이름을 붙인 입력란(`aria-label`) |
| --- | --- | --- |
| 로비 `index.html` | 17곳 — 간편 개설(회의 이름·설명·유형·진행자·날짜·시작·종료), 일시 지정(날짜·시작·종료), 비밀번호 변경(현재·새·확인), 안건, 회의 수정(이름·설명·유형) | — |
| 개설 폼 모듈 `js/meeting-form.js` | 8곳 — 전체 항목 개설 폼(이름·설명·유형·날짜·시작·종료·진행자·안건) | 2곳 — 자료 파일 선택, 조직도 검색 |
| 조직 관리 `admin-org.html` | 14곳 — 사용자 등록·수정(아이디·이름·부서·직위·이메일·초기 비밀번호·표시 순서), 비밀번호 설정(새·확인), 부서 등록·수정(코드·이름·상위·구분·표시 순서) | 1곳 — 사용자 검색 |
| 회의 화면 `viewer.html` | — | 4곳 — 페이지 번호, 참석자 추가 검색, 조직도 검색, 자료 파일 선택 |

- `aria-label`은 다국어 문구로 언어에 따라 바뀐다(`data-i18n-aria-label`). 새로 붙인 `id`는 화면 안에서 겹치지 않는 것을 확인했다.
- **적합으로 본 것**: 로그인·이벤트 이력 화면은 원래 모두 연결돼 있었다. 주최자·참석자 검색란은 원래 `aria-label`이 있었다.

### A11Y-06 마크업 오류 방지 — 적합

- 화면 5개의 정적 마크업을 파서로 검사: **id 중복 0, 같은 속성 중복 0, 짝이 안 맞는 태그 0, 닫히지 않은 태그 0**(HTML이 생략을 허용하는 `p`·`li`·`td` 등 제외).
- 스크립트가 만드는 목록·회의 정보·참석자 패널은 같은 함수로 같은 구조를 만들어 반복 렌더링에서 id를 새로 만들지 않는다(목록 항목은 `data-id`를 쓴다). 실제 화면의 동적 DOM 검사(브라우저 개발자 도구 — 점검 기준서 4.1절 스크립트)는 하지 않았다.

## 4. 검증

- 정적 검사 재실행: 레이블 없는 사용자 입력란 0(숨은 입력·버튼 제외), id 중복 0.
- 화면 스크립트 문법 확인(`node --check`) 통과, 다국어 문구 일관성 테스트(`I18nCatalogConsistencyTest`) 포함 전체 자동 테스트 통과.
- **하지 않은 것**: 화면낭독기(NVDA·센스리더)로 읽어 보기, 키보드만으로 조작해 보기, 실제 브라우저에서 동적 화면 검사.

## 5. 후속 확인 사항

1. **화면낭독기 확인** — 고친 곳(문서 이미지, 새 창 버튼, 입력란 이름)을 센스리더 또는 NVDA로 한 번 읽어 본다. 특히 회의 화면에서 페이지를 넘길 때 대체 텍스트가 바뀌는지 본다.
2. **인증 도구 재점검** — 기관 점검 도구로 다시 검사할 때는 로그인 후 화면(로비·회의 화면·관리 화면)까지 포함한다. 레이블 대부분이 로그인 후 화면의 대화 상자 안에 있다.
3. **화면 목업** — `docs/mockup`은 이번 화면 변경을 아직 반영하지 않았다(`build-mockup.py` 재생성 필요).
