# SW_SECURE_CODING_49.md — SW 개발보안 49개 항목

> 기준: 행정안전부·KISA 2021년 소프트웨어 개발보안 가이드 개정 49개 분류. **개발 단계 자체 점검용 재구성표**이며 공식 원문을 대체하지 않는다. 항목명은 원문과 일부 띄어쓰기가 다를 수 있으므로 계약/인증 시 공식 문서를 대조한다.

각 항목 상태는 `PASS / FAIL / REVIEW / NOT_RUN / N/A` 중 하나로 기록한다. 항목이 없거나 스택에 해당하지 않을 때는 N/A 근거를 기재하며 **JSP라는 이유로 XSS·CSRF를 제외하지 않는다**.

## 검토 순서
1. 실제 변경된 파일과 입력·출력·권한·설정·DB·파일·외부 요청 흐름을 도식화한다.
2. 관련 ID를 선정하고 코드를 변경하기 전에 예방 조치를 반영한다.
3. 단위·통합·정적 검사 증빙을 수집한다. 정적 검사에 탐지되지 않았다고 PASS로 간주하지 않는다.
4. 해당하지 않는 언어·기능의 항목은 근거를 첨부하여 N/A로 둔다.
5. 취약 발견은 파일/라인·입력 경로·재현 가능성·수정/재시험 결과를 기록한다.

## 주의할 구현 예 (Java/JSP/API)
- SQL 바인딩과 정렬 컬럼 허용 목록은 둘 다 필요하다.
- JSP `<c:out>`은 HTML 텍스트 표현에 유용하지만 JavaScript 이벤트 속성/URL/스크립트 문자열 문맥의 XSS 대응을 자동으로 완성하지 않는다.
- HTML 템플릿/프론트엔드 코드가 정상 동작하는 것과 접근성은 별도로 검증한다.
- `@PreAuthorize`, 필터, 인터셉터의 존재만으로 모든 객체 접근 인가가 완료됐다고 간주하지 않는다.
- 테스트용 외부 URL/네트워크 요청은 허가 범위와 비밀정보 노출 가능성을 확인한다.
